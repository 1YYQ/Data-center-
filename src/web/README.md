# React 工作区

正式 React/TypeScript/Vite 源码。生产构建基础路径为 `/workspace/`，由 FastAPI 同源提供：

- `/workspace/query`：查询受理、缺型号补充、原任务轮询与刷新恢复、结果/警告/鉴权原文链接。
- `/workspace/manuals`：当前授权资料目录、精确版本原文及反馈；保留原查询页 `?manual=<version_id>` 链接。
- `/workspace/manage`：先看当前管理范围资料列表，按名称/型号、待核验确认或待发布筛选，再进入精确版本；新版本 PDF 上传、本地解析请求与真实批次状态；精确批次逐块核验、专业确认与核验集；真实确认登记、材料上传/关联/核查；参考开放、发布/撤回预检、回执和本地关键词索引。
- `/workspace/access-review`：系统外审批事实登记、材料上传/关联、匹配职责核查及外部撤销登记。
- `/workspace/services`：具备 `system.configure` 的系统管理员可配置生成、向量和解析服务的本地测试修订，运行固定合成自检并预检启停。当前企业准入未配置，严格合成输入仍按既有逐用途选用和证明门禁执行。
- `/workspace/operations`：系统管理员查看实际逐用途准入、自检当前性及脱敏近期任务，不获得员工正文或业务重试权限。
- `/workspace/accounts`：系统管理员登记账号、激活凭据和停用会话；账号角色不自动授予资料权限。

当前视觉与页面组织依据用户批准的[任务工作台设计](../../doc/design/任务工作台全新设计.md)重新实施。普通员工以明确的资料问题发起查询并查证结果，知识管理员以资料总览进入精确版本并排核对原页和内容块，系统管理员以准入状态/异常进入账号、审批和服务管理。角色共用导航壳，菜单和操作按当前身份显示，最终权限由服务端复核。未实现的计算、表格和报告入口不展示为可用功能。审批对话框使用 Ant Design Modal，原文使用受控原生 dialog；实际验收范围见[项目状态](../../doc/planning/STATUS.md)。

从仓库根目录运行（Node 22.20.0 或符合 engines 的更高版本）：

```powershell
npm --prefix src/web ci --cache outputs/npm-cache
npm --prefix src/web run typecheck
npm --prefix src/web test
npm --prefix src/web run build
```

开发服务器只绑定回环，代理到 `127.0.0.1:8000` 的现有 API；启动前必须按后端说明显式选择和初始化获准的隔离环境。前端构建不连接数据库、不初始化账号、不持有模型或服务密钥。生产不使用 Vite 开发服务器。`dist/`、`node_modules/` 和 `outputs/` 均忽略，不提交业务资料。

依赖精确锁定于 `package-lock.json`。React/DOM 19.2.0、TypeScript 5.9.3、Vite 7.3.8、Ant Design 6.7.1；Vite 的 Node 约束为 `^20.19.0 || >=22.12.0`，Ant Design 6 的 React/DOM peer 为 `>=18.0.0`。约束核对依据安装包元数据与 [Vite 官方说明](https://vite.dev/guide/)、[React TypeScript 文档](https://react.dev/learn/typescript)、[Ant Design 官方说明](https://ant.design/docs/react/introduce/)。

`api.ts` 统一同源 Cookie、CSRF、no-store、HTTP 错误与会话 epoch。所有受保护 JSON/二进制请求携带 `X-Workspace-CSRF` 绑定页面与当前 Cookie 身份，写入另保留既有 CSRF 门禁；旧请求不能在新身份下回填。变更命令按账号/方法/路径仅保留幂等键、输入摘要及 If-Match，不存问题、上传内容或请求正文。未知结果（包括成功响应正文中断）阻止同路径再次写入，只能通过 `GET /operation-receipts` 核对原回执；查不到不等于未执行，不换键重发。存储中的工作恢复信息只有自己的不透明对话/任务标识，不缓存回答正文。

工作列表由 `/workspace-data/works` 返回每项工作的最新执行，历史执行经独立只读接口按需读取；追问显式携带服务端当前 `conversation_id/context_revision`，历史浏览不覆盖当前工作。受保护结果、目录、历史、原文和原图每 10 秒复核，另有从读取开始计算的 15 秒单调时钟显示期限；网络缓慢不能延长旧授权投影。HTTP 读取超时 15 秒，离线/失权/隐藏原文时撤销 Blob URL；恢复焦点和可见时重新核验。已合法下载或用户自行保存的副本无法远程收回。

`/me`短暂超时或服务错误时暂停显示并卸载受保护视图，保留既有会话绑定及不透明工作标识，自动或手动只读复核后恢复原工作；不据一次读失败推断已登出。实际401/403/404及身份不匹配仍清理会话，不通过重连绕过撤权，也不重放变更。

原生 Node 测试验证客户端 HTTP/存储边界，包括未知结果禁止重发、只读回执核对、CSRF、ETag 与身份切换隔离。`src/server/test_task_workspace.py` 验证实际 HTTP 投影和权限，`test_task_workspace_browser.py` 与既有管理员/服务浏览器节点验证构建后的业务链路；需显式隔离 PG 环境，详见[本地验证说明](../../doc/development/本地查询执行与验证.md)。本地合成验证不替代真实岗位签认、复杂 PDF 或企业服务准入。

新版本上传 API 接收版本标识、型号和 PDF；业务依据页以独立来源 GET/PATCH 登记真实来源渠道、说明及可选接收时间/单位/定位，未知时间保持空。缺少来源渠道/说明时，发布预检会如实阻断。新知识库创建仅保存本人登记元数据，等待按既有审批配置管理范围，不自动授予权限。新文档 PDF 上传仅在真实知识库级管理范围内开放，来源随草稿登记，分类和业务确认仍需后续核对。生命周期入口通过独立元数据 API 查看在用资料/回收站、版本保护性暂停与真实消解依据、逻辑删除影响和治理历史。删除须理由与确认，采用文档 ETag 和稳定幂等；删除成功清除原选文档投影，回收站不调用原文、普通版本和确认接口。原件按策略保留不证明物理完整性，未配置保留期，永久清理和恢复未开放。真实外部解析及完整企业生命周期验收仍保留边界。管理页刷新保留所选精确版本；没有选定版本时优先当前发布版，上传后只根据服务端返回 ID 选中新草稿。
