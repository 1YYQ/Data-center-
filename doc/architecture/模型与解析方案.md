## 2. 方案比较与选择依据

| 路线 | 取舍 | 状态 |
| --- | --- | --- |
| BGE-M3 + MinerU VLM | 将文本检索和复杂文档解析分开；云端接入之后可以分别评估本地替换 | 用户选择 |
| Qwen3-Embedding + PaddleOCR-VL | 另一套可评测的模型与解析组合；改用它仍需重新验证向量与解析结果 | 保留为历史候选，不同时实施 |

本路线的工程收益是模型、解析和业务流程可分别演进；代价是需要自行维护证据结构、权限、任务状态及验证。该收益是设计判断，不代表 BGE-M3 或 MinerU 在用户手册上已优于其他候选。

## 3. BGE-M3 接入设计

BGE-M3 的稠密向量维度为 1024，模型说明中的最大序列长度为 8192 tokens，并支持稠密、稀疏和多向量检索能力。[官方模型卡](https://huggingface.co/BAAI/bge-m3)

- 首版设计使用 **1024 维稠密向量**；型号、公式编号等同时保留精确匹配或关键词检索路径。普通 embeddings API 是否提供稀疏或多向量输出必须核实，不因模型具备能力就假定服务已提供。
- 分别对文档片段与用户查询生成向量，二者必须使用同一向量配置。片段按章节、表格和公式关联切分，不将输入上限当作目标片段长度。
- 将实际服务限制、分词与截断策略纳入适配器；超限重新切分并保留关联，禁止静默截断公式条件。
- 接收向量时校验数量、顺序、维度及有限数值；失败结果不进入可用索引。
- 接入建议为硅基流动的 BGE-M3 embeddings 接口；官方文档列出该模型，但平台会调整模型服务，具体账户可用性与行为需实测。[平台接口文档](https://api-docs.siliconflow.cn/docs/api/embeddings-post)

## 4. MinerU VLM 接入设计

MinerU 官方完整解析 API 提供 VLM 选项、表格与公式识别，以及包含 Markdown 和 JSON 的结果；采用异步任务方式。[官方 API 文档](https://mineru.net/doc/docs/index_en/)

- 首版设计接入完整解析 API，显式选择 `vlm`；不以仅返回 Markdown 的轻量接口替代本项目所需的结构化解析。
- 本地文件优先经官方上传流程提交，不把本地目录变成公开下载地址。文件大小、页数、配额与支持格式以实际服务核验结果为准。
- 保存内部任务标识、远端任务标识和状态。提交、上传、轮询、下载分别记录；超时与限流使用有上限的重试。远端任务已存在时优先恢复查询，避免重复提交；提交结果未知时显式标记待核对。
- 下载后持久保存原始解析响应、Markdown、结构化内容和关联图片，不能把有时效的远端结果链接当作长期证据。
- 归一化保留页序号、阅读顺序、内容类型、表格结构、公式及上下文；坐标、置信度仅在服务实际提供时记录。缺乏可靠定位或存在关键识别歧义的内容标为待核验。
- `vlm` 是服务选项，不足以证明云端实际使用某个固定本地模型。记录服务返回的版本；未提供则标记未知，并保留请求参数、时间和结果哈希，不自行补造版本。
- 原生表格等资料可按格式直接读取结构；MinerU 作为所选解析服务，不意味着所有格式必须先转成图片。首期格式集合依据样本确定。

## 5. 数据与接口边界

建议流程：原件登记 → MinerU 解析 → 结构归一化与关键内容校验 → 关联切分 → BGE-M3 向量化 → 授权范围检索 → 证据核对 → 计算与文件生成。

| 记录 | 必须保留的关联 |
| --- | --- |
| 文档版本 | 文档标识、版本、原件哈希、适用范围、访问范围 |
| 解析运行 | 文档版本、服务与实际可知版本、请求参数、输出结构版本、原始结果位置、状态及问题 |
| 内容块与片段 | 解析运行、原文位置、关联块、切分规则版本、内容哈希、核验状态 |
| 向量配置 | 模型、可知修订版本、供应商或本地服务、维度、预处理、归一化与截断规则 |
| 索引版本 | 片段集合、向量配置、构建与验证状态、当前是否启用 |

数据库优先采用 PostgreSQL + pgvector。上述内容为逻辑数据要求；具体表结构和关系单独维护在 [数据库设计](../database/数据库设计.md)，尚未实施。首版 BGE-M3 稠密向量按 `vector(1024)` 设计，保留配置和索引版本关联，物理索引参数经样本验证后确定。

沿用此前讨论的职责划分：PostgreSQL 关系表管理用户、权限、文档版本、公式、任务及计算记录；JSONB 用于可变解析属性；pgvector 管理向量与相似度检索；原始文件、完整解析结果和生成文件独立存储，其存储实现尚未确定。首版不同时引入 MongoDB。

本地 Docker 与后续内网部署优先保持相同数据库和扩展版本组合。数据库版本、扩展安装、备份恢复、表结构升级及带权限过滤的检索需验证后锁定；当前未安装数据库，也未验证这些能力。

解析接口负责提交、状态查询与结果归一化；向量接口负责批量文本到向量。业务层不直接依赖供应商响应结构。适配层只覆盖实际接入需求，不预建完整多供应商框架。

## 6. 迁移与兼容性

| 变化 | 处理方式 | 相对成本 |
| --- | --- | --- |
| BGE-M3 API → 本地 BGE-M3 | 对齐权重修订、分词、预处理、池化、归一化及推理精度；以固定文本和检索案例验证。不能证明兼容时新建索引 | 中，取决于是否重建与数据量 |
| BGE-M3 → 其他向量模型 | 文档和查询切换至同一新配置，重新生成文档向量；即使维度相同也不混用 | 中—高 |
| MinerU 云端 → 内网解析服务 | 核对模型、流水线、输出字段与许可；新解析形成新版本，变化片段重新向量化；保留历史引用 | 中—高 |
| 本地 Docker → 内网 | 搬迁原件、结构化结果、索引及配置；准备镜像、依赖与模型文件，验证无意外外网依赖 | 取决于硬件与运行条件 |

新索引在后台构建、验证后切换；查询模型配置与索引必须一起切换。旧索引在回退窗口内保留，窗口与删除策略按企业要求确定。重建期间的资料更新、删除和权限变化需同步到新索引，禁止回退后重新暴露已撤权资料。

本地部署不保证只改服务地址即可完成。内网模型权重、代码和依赖的许可条件及硬件适配在选择具体版本时核验。

## 7. 数据流与验证

- MinerU 接收获准提交的文件或页面，向量平台接收片段及查询文本，生成服务只接收任务所需的授权内容；各数据流分别配置，不能因允许一种服务而默认允许全部资料外发。
- 凭据从环境或密钥服务读取；只保存密钥引用，日志不记录完整原文、密钥或带凭据的下载链接。
- 已存在的解析结果与索引不能因单次失败被覆盖；待核验、失败或权限不足内容不得伪装成已验证结果。

首轮验证采用获准样本，覆盖正文、复杂或跨页表格、公式上下标、变量单位、警告和脚注。先人工确定应找到的证据与关键识别结果，再检查：

1. 解析是否保留关键结构与原文定位；识别错误能否进入待核验状态。
2. 向量响应是否符合配置；型号、版本与权限过滤后是否能检索到正确证据。
3. 查询、下载与结果引用是否遵循同一权限边界。
4. 限流、超时、重复请求与过期结果链接能否被识别和恢复。
5. 切换模型配置或解析版本时，历史引用、新旧索引隔离与回退是否正确。

检索阈值、准确率、耗时、费用和人工校验成本需根据样本建立基线；目前均无实测结论。
