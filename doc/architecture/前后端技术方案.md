## 2. 首版配套组件基线

“必要”区分能力与产品：应用需要构建、数据访问、迁移和可靠任务执行等能力，但并非只有某个指定工具才能提供。下表明确首版选用的实现。

| 组件 | 作用 | 必要性与首版决定 | 兼容性要点 |
| --- | --- | --- | --- |
| TypeScript | 检查组件属性、接口字段和任务状态的类型使用 | 非 React 硬性依赖；为持续迭代采用 | React、React DOM 与类型定义版本配套；静态类型不能替代后端运行时校验 |
| Vite | 本地开发与生产静态资源构建 | 需要构建工具，首版采用 Vite | 选择满足其要求的受支持 Node 版本；构建与类型检查分别执行；生产不使用开发服务器 |
| Ant Design | 表格、表单、上传、对话框及反馈组件 | 非强制；为减少基础交互重复实现采用 | 按 React 版本核对 peer dependencies 和浏览器支持；按需引入，仅选择一套基础 UI 库 |
| SQLAlchemy | 表映射、查询、连接池与事务边界 | 可用原生 SQL 替代；本项目统一采用 SQLAlchemy 2.x 风格 | 数据库对象与 Pydantic 接口模型分开；复杂检索允许参数化 SQL，不强行套 ORM |
| Psycopg 3 + pgvector Python 集成 | PostgreSQL 通信与向量类型适配 | 数据库驱动必要，本项目选此组合 | Python 包与数据库中的 pgvector 扩展均需配置；校验 1024 维向量读写与距离查询 |
| Alembic | 记录和执行表结构版本变更 | 数据库演进能力必要，选用 Alembic | 自动生成只是候选迁移；扩展、向量类型、索引和数据转换需检查，不能以建表替代升级 |
| Celery + RabbitMQ | 独立进程执行与消息派发 | 正式长任务需要恢复能力，选用此组合 | Worker 在 Linux 容器运行；API 与 Worker 共享任务定义，消息传标识不传完整手册 |

路由、请求状态管理库、Web 入口具体实现及生产编排配置不在本轮锁定范围；Docker Compose 继续作为已讨论的部署建议。

### 2.1 主要替代方案与取舍

| 选择 | 主要替代 | 本轮理由与成本 |
| --- | --- | --- |
| TypeScript | JavaScript | 增加类型维护，但让字段及接口修改更容易在开发时发现不一致 |
| Vite | 手动配置构建工具、引入前端全栈框架 | 当前是独立 FastAPI 后端，优先保持静态前端与简单构建链 |
| Ant Design | shadcn/ui 或自建组件 | 本项目已有大量表格、表单和管理交互；Ant Design 提供现成组件。shadcn/ui 便于修改源码，但定制组件的后续合并与维护由项目承担 |
| SQLAlchemy + Alembic | 直接驱动调用与手写 SQL 迁移 | 统一事务、模型和迁移约定；保留复杂 SQL 能力，接受依赖与学习成本 |
| Celery + RabbitMQ | Celery + Redis | 两者均为支持的消息代理；本项目尚无缓存需求，选专用消息代理，不同时引入 Redis |
| 独立任务系统 | FastAPI 进程内后台任务、数据库任务表自建执行器 | 进程内方式不足以提供本项目要求的恢复机制；自建需维护租约、重试与重复执行处理。RabbitMQ 增加一个持久化服务的运维成本 |

Ant Design 的现成组件与 shadcn/ui 的源码分发方式见各自说明；本轮没有声称 RabbitMQ 比 Redis 更快，也没有将组件选择等同于可靠任务机制已完成。[Ant Design](https://ant.design/docs/react/introduce/)、[shadcn/ui](https://ui.shadcn.com/docs)、[Celery 代理说明](https://docs.celeryq.dev/en/stable/getting-started/backends-and-brokers/index.html)

### 2.2 必须落实的兼容规则

- Vite 的 TypeScript 转译不等于类型检查；构建验证另行执行 TypeScript 检查。UI 库类型支持不代表老旧企业浏览器可运行，需确定浏览器范围。[Vite](https://vite.dev/guide/features.html)、[React TypeScript](https://react.dev/learn/typescript)、[Ant Design](https://ant.design/docs/react/introduce/)
- API 与 Worker 分别管理连接和会话，不跨请求、并发任务或进程共享 Session。若 API 使用异步数据库调用，须配套异步会话和驱动路径；同步调用不能直接阻塞异步处理路径。[SQLAlchemy 会话说明](https://docs.sqlalchemy.org/en/20/orm/session_basics.html)
- Alembic 迁移统一执行一次，不让每个应用副本启动时竞争修改数据库。破坏性变更需备份及恢复方案，不能假定降级脚本能够恢复已删除数据。[Alembic](https://alembic.sqlalchemy.org/en/latest/autogenerate.html)
- Celery 调度与 RabbitMQ 派发不保证业务“恰好一次”。任务记录先持久化，并设计派发补偿；执行前检查状态，重复消息不得重复产生业务结果。配置重试、确认及超时后，验证 Worker 中断恢复。[Celery 任务说明](https://docs.celeryq.dev/en/stable/userguide/tasks.html)
- PostgreSQL 是业务任务状态和结果的持久依据；Celery 结果后端不是第二份业务事实来源。若后续任务编排需要结果后端，再按用途配置。首版不因使用 Celery 自动添加 Redis、Flower 或周期调度服务。
- MinerU 已接收的任务通过远端任务标识恢复轮询；本地任务重试不得无条件重新上传。BGE-M3 调用按片段与向量配置识别已有结果，重试保持索引版本一致。

FastAPI 提供 OpenAPI 描述与数据校验；Vite 支持构建静态部署产物。[FastAPI 文档](https://fastapi.tiangolo.com/features/)、[Vite 文档](https://vite.dev/guide/build.html)

## 3. 接口与职责设计

具体端点、数据结构、权限与异步状态见 [接口设计](../接口设计.md)，持久化关系见 [数据库设计](../数据库设计.md)；两者当前均未实现或联调。

- React 负责输入、任务进度、结果及证据展示；通过后端访问资料，不直接连接数据库，也不持有模型服务密钥。
- FastAPI 负责身份与数据权限校验、业务接口、任务提交、证据组织和结果访问。角色可见范围以 `doc/roles/` 为准，不能仅靠前端隐藏入口控制权限。
- 解析、批量向量化、计算和导出交给独立执行进程；任务状态与结果保存在 PostgreSQL，页面关闭或请求中断不应使任务记录消失。
- API 与执行进程可复用同一后端代码和镜像，初期不拆分业务微服务；本地模型与解析推理服务独立部署，避免 GPU 依赖绑定 Web 后端环境。
- 前后端约定接口版本、字段类型、错误结构、分页与任务状态；精确数值明确传输格式、单位及舍入方式，正式计算由后端执行。
- 用户管理、身份认证与审计需要明确实现；框架提供接口能力不代表已具备完整业务权限模型。

pgvector 提供 SQLAlchemy 等 Python 集成；较重的任务可使用独立任务系统，而非只依赖 Web 进程中的后台回调。[pgvector Python](https://github.com/pgvector/pgvector-python)、[FastAPI 后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)

## 4. 迭代与内网部署成本

| 变化 | 需要保持与处理的内容 |
| --- | --- |
| 新增角色页面或业务任务 | 保持接口与权限约定；新增页面不直接依赖供应商响应结构 |
| 修改数据库结构 | 使用版本化迁移，校验历史数据与旧任务引用，避免简单重建数据库 |
| 切换外部 API 或本地模型 | 后端适配层和能力验证负责变化；不要求前端感知服务地址与密钥 |
| 本地 Docker → 内网单机 | 复用经验证镜像，调整配置、证书与服务地址，迁移数据并演练恢复 |
| 内网无公网访问 | 前端字体、脚本及预览资源本地打包；镜像、依赖和所需模型文件提前准备；外部服务另行替换 |
| 单机 → 高可用 | 需额外设计数据库、消息服务、文件存储与调度，不能只复制应用容器 |

若采用 Vite 静态前端，Node 工具用于构建，前端产物不要求独立 Node 运行服务；Python API 和执行进程仍需运行。Compose 可通过环境覆盖配置支持部署，但不会自动解决数据恢复或高可用。[Docker 文档](https://docs.docker.com/compose/how-tos/production/)
