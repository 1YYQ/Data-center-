# 前后端技术方案：React + FastAPI

记录日期：2026-11-10。

状态：用户已选择 React + FastAPI；以下配套组件、接口和部署设计为待审阅草案，尚未搭建或完成兼容性验证。

## 1. 选型与范围

前端使用 React，后端使用 Python + FastAPI，与已确定的 PostgreSQL + pgvector、BGE-M3、MinerU VLM 配合。模型与解析细节见 [模型与解析方案](模型与解析方案.md)。

本次确认框架，不等于确认所有配套库、版本和运行服务。目标是支撑三类角色的资料管理、证据查询、任务执行和结果交付，并保留从本地 Docker 迁至企业内网的路径。

| 比较路线 | 取舍 | 状态 |
| --- | --- | --- |
| React + FastAPI | 自定义业务界面与 Python 数据处理相结合；权限、审计和管理功能需实现 | 用户选择 |
| Vue + FastAPI | 同样能接入既定后端和模型，适合已有 Vue 经验的维护团队 | 未选择 |
| React／Vue + Django REST Framework | 可复用管理、认证和 ORM 基础，专用业务流程仍需开发 | 未选择 |

上述取舍沿用选型讨论，是工程判断，不是已测得的性能或工期结论。

FastAPI 提供 OpenAPI 描述与数据校验；Vite 支持构建静态部署产物。[FastAPI 文档](https://fastapi.tiangolo.com/features/)、[Vite 文档](https://vite.dev/guide/build.html)

## 3. 接口与职责设计

- React 负责输入、任务进度、结果及证据展示；通过后端访问资料，不直接连接数据库，也不持有模型服务密钥。
- FastAPI 负责身份与数据权限校验、业务接口、任务提交、证据组织和结果访问。角色可见范围以 `doc/roles/` 为准，不能仅靠前端隐藏入口控制权限。
- 解析、批量向量化、计算和导出交给独立执行进程；任务状态与结果保存在 PostgreSQL，页面关闭或请求中断不应使任务记录消失。
- API 与执行进程可复用同一后端代码和镜像，初期不拆分业务微服务；本地模型与解析推理服务独立部署，避免 GPU 依赖绑定 Web 后端环境。
- 前后端约定接口版本、字段类型、错误结构、分页与任务状态；精确数值明确传输格式、单位及舍入方式，正式计算由后端执行。
- 用户管理、身份认证与审计需要明确实现；框架提供接口能力不代表已具备完整业务权限模型。

pgvector 提供 SQLAlchemy 等 Python 集成；较重的任务可使用独立任务系统，而非只依赖 Web 进程中的后台回调。[pgvector Python](https://github.com/pgvector/pgvector-python)、[FastAPI 后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)

## 4. 迭代与内网部署成本

| 变化 | 需要保持与处理的内容 |
| --- | --- |
| 新增角色页面或业务任务 | 保持接口与权限约定；新增页面不直接依赖供应商响应结构 |
| 修改数据库结构 | 使用版本化迁移，校验历史数据与旧任务引用，避免简单重建数据库 |
| 切换外部 API 或本地模型 | 后端适配层和能力验证负责变化；不要求前端感知服务地址与密钥 |
| 本地 Docker → 内网单机 | 复用经验证镜像，调整配置、证书与服务地址，迁移数据并演练恢复 |
| 内网无公网访问 | 前端字体、脚本及预览资源本地打包；镜像、依赖和所需模型文件提前准备；外部服务另行替换 |
| 单机 → 高可用 | 需额外设计数据库、消息服务、文件存储与调度，不能只复制应用容器 |

若采用 Vite 静态前端，Node 工具用于构建，前端产物不要求独立 Node 运行服务；Python API 和执行进程仍需运行。Compose 可通过环境覆盖配置支持部署，但不会自动解决数据恢复或高可用。[Docker 文档](https://docs.docker.com/compose/how-tos/production/)
