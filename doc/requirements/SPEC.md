# 数据中心 · 产品规格

状态：首个业务任务范围已于 2026-11-11 确定；具体公式样本、详细规则与企业环境仍待核对，功能尚未实现。

依据：用户提供的项目理解、AGENTS.md 建议稿及后续选型决定。本文将其整理为产品需求；不表示功能已实现，也不表示具体格式、全部技术栈或验收阈值已经确认。

## 1. 产品目标与范围

建立企业专业知识管理与 AI 数据生产平台。用户将资料一次入库，后续描述工作任务，由系统检索适用依据、组织规则、执行确定性计算，生成可复核的表格或数据文档。

成功标准是完成真实工作：使用正确版本的资料，保留证据和计算记录，产物符合业务模板，并减少重复输入与人工复核成本。仅能回答文档问题不构成完整验收。

首个验证范围已确定：参考计算公式手册，输入一组业务参数，自动核对单位和适用条件，执行计算并生成 Excel，保留输入值、公式、结果与手册出处。缺少参数时先提示补充，不自行填值。首批不要求额外引入设备操作手册。

设备参数整理、批量计算和其他报告类型保留为后续候选，不扩入当前首个任务。手册输入格式与具体公式仍须依据样本确定。

初期不包含直接控制设备、覆盖所有文档格式、无依据的专业推断，以及尚无业务需求支撑的复杂平台功能。

### 1.1 首个业务闭环（已确定）

| 环节 | 已确定要求 |
| --- | --- |
| 资料依据 | 使用计算公式手册，公式、变量、单位、适用条件及来源需可定位 |
| 输入 | 用户提供一组业务参数；原始值与单位分别保留，不用换算值覆盖原始输入 |
| 计算前校验 | 检查必要参数、单位一致性或可换算性，以及公式适用条件；有依据的换算须保留过程 |
| 缺项处理 | 显示缺少哪些参数及已知定义；相关信息补齐前停止依赖它的计算，不默认填零、经验值或模型猜测值 |
| 条件不满足 | 单位不兼容或适用条件不成立时明确说明，不产生冒充正式有效结果的数值 |
| 计算与交付 | 由确定性程序执行计算，生成 Excel，保留输入值、采用公式、计算结果和手册出处 |
| 来源追溯 | 关联实际手册版本及其公式所在章节、页序号或其他可靠位置；未知出处不得编造 |

首个任务的验收应同时检查：正确输入的结果可独立核对；缺少参数时会提示补充且不自动代填；单位或适用条件错误时能阻断相关计算；Excel 能打开且必要字段和来源齐全。具体预期数值、精度、容差及版式待样本与交付规则讨论后确定。

用户尚未指定业务领域、具体公式与参数名称、手册格式、Excel 模板、是否要求单元格内可重算公式，以及补参界面的具体交互。这些分别由待确定清单 D02、D05、D08 收敛，不将本节视为已完成计算引擎设计。

## 2. 职责划分

| 职责 | 输入与产出 |
| --- | --- |
| 资料管理与解析 | 原始文件 → 有版本和位置标识的内容及解析问题 |
| 结构化知识管理 | 原文证据 → 关联变量、单位、条件的规则与参数 |
| 检索 | 任务、权限和适用范围 → 候选证据及必要上下文 |
| 语言模型 | 任务与证据 → 信息组织、执行计划、结果说明 |
| 确定性计算 | 已核验规则与输入 → 可重复计算的结果与记录 |
| 验证 | 证据、输入、结果、产物 → 检查结果及未解决问题 |
| 文档生成 | 已整理数据与模板 → 表格或文档及来源索引 |

以上为逻辑职责，不预设服务数量或代码模块；前后端框架已确定为 React + FastAPI，配套设计见 [前后端技术方案](../architecture/前后端技术方案.md)。

前后端端点、请求响应、权限、错误和任务状态契约单独维护在 [接口设计](../api/接口设计.md)，目前为未实施的草案。

## 3. 资料如何成为可信知识

1. 登记原始文件、内容哈希、版本、来源、适用设备及访问范围；识别重复内容。相同内容也须保留不同来源与权限关系。
2. 保存原件，解析章节、正文、表格、公式、图注、警告和脚注，保留原文定位。解析结果与索引可由原件重建。
3. 标记无法识别、缺失或存在歧义的内容。关键公式或表格未经核验，不得作为正式计算依据；不得静默丢弃关键内容。
4. 结构化关联公式、变量、数据类型、单位、约束、适用条件、精度和示例。未知字段显式留待确认。
5. 根据文档权威性与有效状态决定适用范围。上传较晚不自动代表现行版本，历史数据也不自动成为正式规范。
6. 更新时保留版本关系与变更记录；删除或权限变化同步影响索引、缓存和派生内容。历史计算保留可审计标识，同时遵守已确定的数据留存政策。

每次检索得到的是候选依据，仍需检查适用范围、版本和原文支持关系。语义相似或检索分数不能替代该检查。

## 4. 一次任务的完整流程

1. **明确任务**：识别设备或业务对象、目标产物、版本限制、用户输入和单位；列出影响结果的缺项。
2. **检索资料**：在授权范围内过滤并检索，补齐公式定义、表头、限制和警告，控制上下文预算。
3. **组织证据**：建立任务、原文位置、规则与输出字段的对应关系；未解决的版本冲突和适用条件歧义阻止相关结论继续生成。
4. **准备计算**：检查公式、输入类型、单位、取值范围和精度；记录原始数据与换算过程。
5. **执行与验证**：使用受控程序计算，并与独立核对的预期结果或适当的独立计算方式比较；模型自评不作为通过依据。
6. **生成产物**：按确定的模板组织数据、结果、单位、来源与验证状态。
7. **交付检查**：验证内容和引用，检查文件可打开、字段完整、公式无错误；相关检查全部通过后才能标为已验证。

不涉及计算的任务跳过计算步骤，仍须完成证据及产物检查。局部缺项允许交付清晰标识的部分结果，不能把整个任务标为完成。

用户明确要求估算时，记录假设、采用值和估算标识；估算与正式计算分开呈现，不能覆盖原始数据。

## 5. 概念数据对象

数据库已选择优先采用 PostgreSQL + pgvector。以下为业务对象概览；字段、关系、约束与索引生命周期单独维护在 [数据库设计](../database/数据库设计.md)，当前为未实施的设计草案，文件存储实现及物理性能参数仍待验证。

| 对象 | 需要保留的信息 |
| --- | --- |
| 文档版本 | 文档标识、版本标识、名称、哈希、来源、适用对象、有效状态、权限、原件位置 |
| 证据片段 | 片段标识、文档版本、原文定位、内容类型、正文或表格结构、关联上下文、核验状态 |
| 公式规则 | 规则标识、版本、原表达式、变量定义及类型、单位、适用条件、范围、精度、来源、验证样例 |
| 任务 | 用户目标、访问范围、设备与版本限制、原始输入、目标模板、缺项、执行状态 |
| 计算记录 | 规则与执行版本、输入及来源、单位换算、结果、舍入方式、验证结果 |
| 产物 | 文件标识、任务关联、生成时间、字段与证据或计算记录的映射、检查状态 |

证据定位使用文件实际提供的信息：PDF 文件页序号与印刷页码分别记录；其他格式使用章节、段落、表格或单元格等定位方式。

## 6. 异常与权限要求

| 情况 | 预期行为 |
| --- | --- |
| 无检索结果或证据不充分 | 在授权范围内补充检索；仍不足则说明缺项，不生成无依据结论 |
| 型号不符或版本冲突 | 排除不适用证据；无法确定时请求确认，暂停相关结果 |
| 公式解析歧义或参数缺失 | 指明原文位置或缺失变量，阻止依赖它的计算 |
| 单位不兼容或输入越界 | 返回可定位的问题，不继续输出正式结果 |
| 无权访问资料 | 不向用户或模型暴露内容；检索和缓存遵循权限边界 |
| 文档包含执行指令 | 作为资料内容处理，不改变权限或执行任意代码 |
| 导出失败或无法重算 | 保留任务记录并报告失败或未验证状态，不宣称交付成功 |

企业资料、向量与日志均受数据使用范围约束。外部模型、解析服务、存储及遥测的数据流向须在接入真实企业资料前明确；凭据不得进入仓库。

## 7. 验收设计

先建立人工核对的样本与当前工作流程基线，再确定数值阈值。真实样本必须获准使用；脱敏或模拟样本用于早期验证时，须注明不能替代真实业务验收。

| 维度 | 验证证据 |
| --- | --- |
| 解析完整性 | 对照原件检查关键表格、公式、变量、条件和警告 |
| 检索与版本 | 预标注证据命中情况、型号和有效版本匹配结果 |
| 引用准确性 | 能定位原文，且原文确实支持对应结论 |
| 计算与单位 | 独立预期值、边界输入、换算和舍入对照记录 |
| 缺项与冲突处理 | 无依据、缺参数、型号不符、版本冲突时的阻断结果 |
| 文件质量 | 模板字段、文件打开、公式重算、数值与来源映射检查 |
| 权限与注入 | 越权访问、缓存隔离、文档内指令不被执行的验证记录 |
| 使用效率 | 同类任务重复输入量、上下文用量、耗时及人工复核成本对比 |

首个闭环需覆盖正常路径和相关失败路径；单次演示成功不能证明系统整体可靠。结果须记录通过、失败或未验证及其原因。
