## 1. 产品目标与范围

建立企业文档沉淀与大模型办公协作平台。持续将企业文档纳入数据中心，管理来源、版本和访问范围；用户通过大模型接口表达工作需求，系统按权限检索、理解、整合资料，并按任务需要调用确定性工具，帮助解决实际办公问题。

成功标准由角色的真实工作决定：获得原先难以获取的授权资料、找到可核验依据、理解和整合内容，或完成实际办公成果。计算任务还需保留计算记录；文件任务还需满足输出要求。文档数量、问答次数和技术组件数量不能单独作为产品成功依据。

企业文档沉淀是长期目标，当前仅对部分候选场景了解资料渠道，完整文档种类、来源清单与接入方式仍需调查；不能据此宣称已支持所有文件格式或自动连接企业全部系统。

需求从普通使用者、知识管理员和系统管理员的工作过程出发，了解现有系统中找不到、无法判断或难以完成的事项。普通使用者已说明计算填表、设备资料查询和多资料对比报告三类需求，并选择 1.3 的设备操作维护查询作为首期流程；相关管理角色的具体工作仍需调查。尚未调查的痛点只能标为假设，不能把对传统系统的推测写成事实。

初期不包含直接控制设备、覆盖所有文档格式、无依据的专业推断，以及尚无业务需求支撑的复杂平台功能。

界面与交互（2026-11-15 用户澄清）：以 Apple 备忘录的简洁和信息层次为参考，信息主次围绕各角色实际工作安排，按角色和权限展示菜单、功能及必要面板，不统一套用管理后台框架。普通员工主要看到知识查询、我的任务和结果，不显示无权使用的管理入口；保留自然语言提问、手册版本和出处核对。首期面向电脑网页，不做手机和平板适配。

### 普通使用者整体工作模型（2026-11-17 范围更正）

用户指出，普通使用者应主要看到答案或实际成果，其他附加证据采用链接式跳转；“消息与条件 → 单轮查询任务 → 回答与证据快照”只描述 RAG 查询工具链，不能代表完整办公能力。产品范围同时包含本节后续已记录的数值计算、已有 Excel 修改与报告整理。首期先交付设备资料查询的顺序保持不变，不能据此把完整产品设计缩减为问答。

整体衔接建议为：对话表达需求并补充已确认条件 → 办公任务按需调用检索、确定性计算、表格处理等工具 → 返回答案、数值或文件成果。一个办公任务可以跨多条补充消息并组合多个工具；澄清消息不必创建执行任务。工具选择、具体导航、文件提交与成果预览交互仍需讨论，当时尚未选择通用Agent框架；同日后续用户已确定Pi作为核心基底，授权具体接入设计。实现仍未获授权，角色业务范围不因技术选择扩大。

结果区优先呈现可用结论、数值及单位、表格/文件成果入口和完成情况；关键警告、缺项、未完成项目及待人工复核状态直接可见。来源原文、采用条件与版本详情、公式与计算过程、单元格修改明细通过关联链接查看，保留返回原任务的位置；链接访问仍需当前权限。附加详情链接不等于删除证据，也不替代交付物内必要的来源记录。

后端须真正执行并验证工具处理。返回自然语言计算说明、给出修改建议或显示文件按钮，均不能算作已完成数值计算或 Excel 修改。1.1 的原始文件保护、已有结果更新确认、多项目暂停/继续及人工复核要求继续有效；本次只修正设计范围，不表示相关服务已实现。普通使用者整体衔接见 [角色说明](../roles/普通使用者.md#办公任务与结果呈现)，首期网页契约只负责查询子流程。

2026-11-17 后续用户授权基于已设计的20项工具重整完整界面/后端并同步文档，明确暂不写代码。页面、四类流程、结果/详情/确认及恢复关系集中在 [完整界面与对接方案](../design/普通使用者界面与对接方案.md)，网页投影与连接在API15。候选三入口和只读预览方案属于设计建议，尚无用户导航/高保真视觉批准；不自动增加在线表格编辑、整任务分享或业务确认/发布能力。

#### 首期组织答案口径（2026-11-18用户确认）

首期Pi查询须增加**有证据约束的组织答案**，不能仅以拼接原文摘录宣称该能力完成。原摘录保留为有标记的证据查看能力；生成失败不得静默换摘录并显示组织答案已完成。本轮只完善规格和计划，未授权实施或真实模型调用。

- 模型基于当前获准的精确证据/完整支持组组织独立候选，候选不覆盖原PDF、原始解析、IR、Chunk或既有回答。每条实质声明须回溯具体版本/Run/Chunk/Block范围或region，并带所依赖的条件、单位、表头、定义及警告。
- 关键数值/范围、公式、操作动作/步骤顺序及适用条件不能由模型补写或随意改义；首版优先让模型选择、分组和编排已核验事实/程序证据组，关键内容按固定renderer或原句受控呈现，保留局部与全局警告的作用域。
- T14不能只检查“证据存在且当前有权”。还须核对声明的实际支持、关键内容及关系/完整支持组保全；引用ID存在、字面相似、另一个模型认可均不构成语义正确证明。对无法确定的改写保持待核验、拒答或交实际业务人员确认，不静默删除问题后把局部回答称完整。
- T16只交付经过上述门禁的答案快照，保留候选/校验/实际模型调用及原文证据身份。业务正确性核验与技术校验仍分开；正式答案保留设备用途业务复核提示，不作为设备执行指令。任意自然语言改写无法被程序普遍证明正确，须在真实人工参考上逐声明评估可答覆盖与错误放行，不承诺100%。

接口/候选保存与实施映射见[API18.5](../api/接口设计.md#185-pi核查整改的输入候选与正式出口契约)、[数据库18.1](../database/数据库设计.md#181-pi核查整改的来源与生命周期契约)和[Pi剩余Plan](../../specs/001-device-operation-maintenance-query/plan.md#pi-agent-剩余实施-plan2026-11-18六项核查整改待审核)。FR-007/008/014与SC-001/002/006继续适用，不新增或重编号首期FR。

### 1.1 候选场景：公式计算与 Excel

以下场景由用户提供，2026-11-14 进一步确认操作要求，并明确保留为首期查询流程之后逐步推进的需求。它不代表项目全部目标。透镜焦距测量是本轮讨论样例，尚未据此确认正式业务范围、具体公式或验收数值。

用户描述的当前做法：员工根据测量方法和已有数据翻手册选择公式，自行计算并填写 Excel，最后对照手册人工核对公式、原始数据和计算结果。三个环节均需人工处理；这些是用户陈述，尚未通过真实任务观察或计时验证。

任务描述样例（用户提供）：

> 根据这份 Excel 里的透镜焦距测量数据，查找手册中的适用公式，完成计算并填入对应的结果单元格，保留原始数据和表格格式；缺少信息或公式不确定时先问我。

| 环节 | 已确定要求 |
| --- | --- |
| 资料依据 | 使用计算公式手册，公式、变量、单位、适用条件及来源需可定位 |
| 任务发起与输入 | 员工以自然语言描述任务；测量数据通常已记录在 Excel 中，由系统读取，避免重复录入。原始值与单位分别保留，不用换算值覆盖原始输入 |
| 公式选择 | 系统结合任务描述与 Excel 数据查找手册中的适用公式；信息不足或有多种公式可选时，先向员工确认，未解决前停止依赖该选择的计算 |
| 表格识别 | 同一测量项目通常有固定模板，不同项目的表格可能不同。结合任务描述、表头和单位识别原始数据与结果填写位置；无法确定时先向员工确认 |
| 多项目与处理范围 | 一份 Excel 可包含多个测量项目，分布在不同工作表或同一工作表的不同区域。系统根据任务描述确定需要处理的项目，分别匹配公式、计算并填写结果，保持各项目的数据、公式与填写位置对应，避免混用数据；处理范围或对应关系不清楚时先向员工确认 |
| 项目级暂停与继续 | 某项目需要补充信息或确认时，仅暂停受影响项目，标明原因和待确认事项，不填入猜测结果；其他不受影响的项目先完成计算和填表。员工补充或确认后继续处理暂停项目，清楚区分已完成与未完成项目 |
| 计算前校验 | 检查必要参数、单位一致性或可换算性，以及公式适用条件；有依据的换算须保留过程 |
| 缺项处理 | 显示缺少哪些参数及已知定义；相关信息补齐前停止依赖它的计算，不默认填零、经验值或模型猜测值 |
| 条件不满足 | 单位不兼容或适用条件不成立时明确说明，不产生冒充正式有效结果的数值 |
| 计算执行 | 由确定性程序执行计算，保留输入值、采用公式、计算过程、计算结果和手册出处 |
| 精度与舍入 | 优先按手册和记录表中明确的规定执行；没有规定或两者不一致时，先向员工确认，不自行设定。中间计算不提前舍入，最终结果按确认后的规则处理，并保留采用规则的依据 |
| 已有记录表 | 原始数据与结果位置通常在同一 Excel 文件内；读取原始数据，将结果填写到对应位置，保留原始数据和表格格式 |
| 新建记录表 | 没有现成记录表时，根据具体需求从零生成表格，完成计算并填写结果；具体字段与版式仍需按任务明确 |
| 已有结果的更新 | 目标结果单元格已有数值或公式时，先展示原有内容和本次计算结果，经员工确认后才能在处理后的文件中更新，不直接覆盖 |
| 追加结果 | 支持在原有数据之后追加本次结果，保护已有数据不被破坏；追加的具体位置须满足已确认的表格映射要求 |
| 文件保护与交付 | 保留原始文件，处理后的表格另存为新文件 |
| 来源追溯与人工复核 | 保留公式出处、计算过程和结果填写位置，关联实际手册版本及章节、页序号或其他可靠位置；未知出处不得编造。便于员工对照复核，最终由人工确认结果是否可用，系统计算完成不代表业务复核通过 |

该场景实施时的验收应同时检查：正确输入的结果可独立核对；跨工作表及同表不同区域的多个项目按任务范围分别处理，数据、公式及填写位置不混用，范围或对应关系不清楚时先确认；缺少参数或公式、填写位置不确定时会提示确认且不自动猜测；单位或适用条件错误时能阻断相关计算；精度与舍入规定缺失或冲突时先确认，不自行设定，中间计算不提前舍入，最终采用规则可追溯；已有结果未经确认不被更新；追加不破坏已有数据；原始文件保持不变；输出 Excel 能打开，原始数据、要求保留的格式、必要字段及来源齐全，填写位置可核对。新建表格按任务约定检查字段与版式。具体预期数值、精度、容差及版式届时按样本确定。

多项目任务还须验证：需补充或确认的项目暂停且不填猜测值，不受影响的项目可先完成；暂停原因及待确认事项可见；补充或确认后可继续处理并更新项目状态；已完成与未完成项目可区分，不能将局部完成标为整份任务完成。

人工耗时：**待验证**。用户尚未准确统计，耗时随数据量、手册熟悉程度和表格复杂度变化；后续以真实任务记录人工基线，再与系统处理及人工复核的耗时对比，不预设节省比例。

正式业务范围、具体测量方法与公式参数、获准手册及有效版本、真实 Excel 样本、新建表格细则、真实样本的具体精度与舍入规定、复核的具体交互仍需按任务落实。2026-11-17 已在 [API14](../api/接口设计.md#14-agent工具统一契约设计基线01) 和 [数据库14](../database/数据库设计.md#14-agent工具持久化设计基线01) 对齐工具输入/输出、项目级暂停/补充/确认/继续及局部交付设计；尚未实现或运行验证。任务频率与错误影响待调查；真实业务参数不由通用契约代定，首期查询优先顺序保持不变。

## 3. 资料如何成为可信知识

1. 登记原始文件、内容哈希、版本、来源、适用设备及访问范围；识别重复内容。相同内容也须保留不同来源与权限关系。
2. 保存原件，解析章节、正文、表格、公式、图注、警告和脚注，保留原文定位。解析结果与索引可由原件重建。
3. 标记无法识别、缺失或存在歧义的内容。关键公式或表格未经核验，不得作为正式计算依据；不得静默丢弃关键内容。
4. 结构化关联公式、变量、数据类型、单位、约束、适用条件、精度和示例。未知字段显式留待确认。
5. 根据文档权威性与有效状态决定适用范围。上传较晚不自动代表现行版本，历史数据也不自动成为正式规范。
6. 更新时保留版本关系与变更记录；删除或权限变化同步影响索引、缓存和派生内容。历史计算保留可审计标识，同时遵守已确定的数据留存政策。

每次检索得到的是候选依据，仍需检查适用范围、版本和原文支持关系。语义相似或检索分数不能替代该检查。

## 4. 一次任务的完整流程

1. **明确任务**：识别设备或业务对象、目标产物、版本限制、用户输入和单位；列出影响结果的缺项。
2. **检索资料**：在授权范围内过滤并检索，补齐公式定义、表头、限制和警告，控制上下文预算。
3. **组织证据**：建立任务、原文位置、规则与输出字段的对应关系；未解决的版本冲突和适用条件歧义阻止相关结论继续生成。
4. **准备计算**：检查公式、输入类型、单位、取值范围和精度；记录原始数据与换算过程。
5. **执行与验证**：使用受控程序计算，并与独立核对的预期结果或适当的独立计算方式比较；模型自评不作为通过依据。
6. **生成产物**：按确定的模板组织数据、结果、单位、来源与验证状态。
7. **交付检查**：验证内容和引用，检查文件可打开、字段完整、公式无错误；相关检查全部通过后才能标为已验证。

不涉及计算的任务跳过计算步骤，仍须完成证据及产物检查。局部缺项允许交付清晰标识的部分结果，不能把整个任务标为完成。

用户明确要求估算时，记录假设、采用值和估算标识；估算与正式计算分开呈现，不能覆盖原始数据。

## 5. 概念数据对象

数据库已选择优先采用 PostgreSQL + pgvector。以下为业务对象概览；字段、关系、约束与索引生命周期单独维护在 [数据库设计](../database/数据库设计.md)，实际实现差距见项目状态，不以设计文档代替迁移或运行证据。

| 对象 | 需要保留的信息 |
| --- | --- |
| 文档版本 | 文档标识、版本标识、名称、哈希、来源、适用对象、有效状态、权限、原件位置 |
| 证据片段 | 片段标识、文档版本、原文定位、内容类型、正文或表格结构、关联上下文、核验状态 |
| 公式规则 | 规则标识、版本、原表达式、变量定义及类型、单位、适用条件、范围、精度、来源、验证样例 |

| 计算记录 | 规则与执行版本、输入及来源、单位换算、结果、舍入方式、验证结果 |
| 产物 | 文件标识、任务关联、生成时间、字段与证据或计算记录的映射、检查状态 |

证据定位使用文件实际提供的信息：PDF 文件页序号与印刷页码分别记录；其他格式使用章节、段落、表格或单元格等定位方式。

## 6. 异常与权限要求

首期账号（2026-11-15 用户明确）：先使用平台内账号，由系统管理员创建、维护和停用，关联员工身份，不开放自行注册。首个系统管理员通过一次性部署初始化流程建立；开发人员可以执行被授权的初始化操作，但不能以开发身份自动获得业务资料权限。账号开通不等于获得业务资料权限，仍须按审批结果单独授权。首期不接入企业统一登录，后续可通过认证适配器接入。账号管理职责见 [系统管理员](../roles/系统管理员.md#首期账号管理)。

首期会话（规划基线）：浏览器通过认证适配器建立不可猜测的服务端会话引用，以 `HttpOnly`、`Secure`（HTTPS 环境）和 `SameSite=Lax` Cookie 传递；状态变更请求需要 CSRF 防护。账号停用、显式登出或授权修订变化后，旧会话不得继续访问业务内容。业务 API 不接受客户端提交的 user_id、角色或权限作为调用者身份。具体实现契约见 [登录与会话](../planning/first-release-device-query/contracts/auth-session.md)。

权限判断维度（2026-11-15 需求讨论进展）：

| 维度 | 已明确要求及待细化边界 |
| --- | --- |
| 用户身份、角色与授权范围 | 普通员工只能查询和使用获授权资料；知识管理员只能上传、维护和发布其管理范围内的资料；系统管理员负责账号、权限和系统配置，不默认获得全部业务资料的读取权 |

| 文件类别 | 按业务用途和内容性质划分，首期支持企业自定义；业务负责人确定规则，系统管理员配置，知识管理员登记维护。与文件等级分开管理，访问与使用仍结合其他权限维度判断 |

具体访问和使用按完整授权组合判断：角色能力、资料范围、操作、文件等级、文件类别、需求分类和有效期限必须由同一条已批准授权组合或明确配置规则同时满足；不同授权记录不得跨记录拼接成未经批准的新权限。任一维度缺失、过期、冲突或不明确时不放行。等级配置职责见 [系统管理员](../roles/系统管理员.md#企业文件等级配置)。本节记录首期规划基线，不表示数据库或接口已实现这些规则。

文件类别示例（用户于 2026-11-15 提供）：操作手册、维护手册、计算公式手册、技术规范、记录表模板、内部说明。这些是业务类别示例，不将其固定为所有企业必须采用的类别清单；配置职责见 [系统管理员](../roles/系统管理员.md#企业文件类别配置)。

- 单份文件由业务负责人或文件所属部门负责人依据公司规则判定等级。

- 等级不明确时标记待确认，不默认开放。
- 等级变更须经业务负责人确认，保留确认人、确认时间和确认依据。

| 情况 | 预期行为 |
| --- | --- |
| 无检索结果或证据不充分 | 在授权范围内补充检索；仍不足则说明缺项，不生成无依据结论 |
| 型号不符或版本冲突 | 排除不适用证据；无法确定时请求确认，暂停相关结果 |
| 公式解析歧义或参数缺失 | 指明原文位置或缺失变量，阻止依赖它的计算 |
| 单位不兼容或输入越界 | 返回可定位的问题，不继续输出正式结果 |
| 无权访问资料 | 不向用户或模型暴露内容；检索和缓存遵循权限边界 |
| 文档包含执行指令 | 作为资料内容处理，不改变权限或执行任意代码 |
| 导出失败或无法重算 | 保留任务记录并报告失败或未验证状态，不宣称交付成功 |

企业资料、向量与日志均受数据使用范围约束。外部模型、解析服务、存储及遥测的数据流向须在接入真实企业资料前明确；凭据不得进入仓库。

### 10.1 目标、不变量与证据资格

目标是将一份已登记 PDF 的具体版本转换为可检索、可复核、可重新处理的知识单元，同时保留无法确定的内容和关系。普通员工按型号查开机步骤、维护要求和注意事项，必须能核对适用版本、关键警告及原文区域。

- “不丢失原始信息”的可执行保证是：原 PDF、实际收到的完整解析产物及修订来源不被覆盖；每页和已发现的信息区域有处置记录。**结构化内容与原件语义完全等价不能由自动程序保证**，须用独立人工参考检验；未解释区域不能因已有整页框而算作完整。
- DocumentVersion 表达业务版本，ParseRun 表达处理批次，ChunkSet 表达切分版本，IndexGeneration 表达检索代际。重新解析不创建虚假的业务版本，重新切分不重复调用解析器。
- 原始输出、归一化内容、结构关系、人工修订和模型复核建议分别保存。模型不得改写原始知识、补造单位/警告/表头、默认为当前版本或给自己签认通过。
- 缺页、缺资源、关键数值歧义、错误关系、未核验关键内容和权限不满足均保留可见状态；不能通过删除问题块、截断内容或改低阈值使批次通过。

技术依据统一标记：**【现有代码验证】**表示本轮静态检查实际实现或默认库结构；历史运行另标日期和范围，不代表本轮执行。**【官方文档确认】**表示固定版本官方契约。**【需真实样本验证】**表示拟采用规则/能力尚需原件对照。**【尚未确定】**表示缺少业务或运行事实。设计规则使用“应/须”，不冒充运行结论。


| 4 Document IR | 原始产物 + 预检 → schema受检IR、Page/Block/Asset映射及适配诊断 | Python类型/结构验证；0起始页转1起始原页；保存原bbox和变换；保留全部未知类型及原始JSON指针；安全资源落私有存储 | 协议/producer不支持则quarantine；缺坐标/页/资源进入issue，不用Markdown重建后冒充原始值；所有输出仍可回到3的具体原始节点 | 无生成模型；歧义交局部复核 |
| 5 Structure Recovery | 不可变IR叶块、版面/目录/编号 → 章节树、阅读顺序、procedure/table/paragraph连续组及有据关系 | 编号、书签、样式、列区域、表号/表头/边界/脚注等规则交叉核对；只加容器/关系，不改原文。关系标明规则版本、证据及候选/确认状态 | 不确定的续页/图注/变量关系保持候选，缺依赖的关键单元阻断；禁止仅凭相邻或语义相似合并。结构算法变更生成派生新批次，可复用原解析包 | 规则优先；同引擎视觉仅辅助候选；重要歧义由KM/专业人员核对 |
| 6 Semantic Chunking | 固定恢复IR + splitter配置 → immutable ChunkSet、child/parent及完整Block范围映射 | 按10.5的类型规则组成最小充分证据单元，先保持结构，再用经核验tokenizer及服务字节上限约束 | 不负责重新OCR/修复公式/推断表头；超长原子元素保留且标记，不截断。可独立重切分，失败不改当前选用集 | 无生成模型；仅无法安全切分项待复核 |
| 7 Quality Control | 原件/页图/独立参考、原包、IR、Chunk映射 → QC报告/issue、核验集及可否正式使用 | 10.6确定性对账、局部视觉建议、逐项关键事实原页确认；区分技术检查、内容核验、适用确认与发布 | pass不自授业务资格；关键未决阻止整批正式选用/发布；保留所有问题、处置依据及重开条件；不修改上下游产物来凑通过 | 普通正文自动筛查；关键内容必须有实际人工确认，模型自评不能放行 |
| 8 Knowledge Indexing | 已满足正式门禁的精确IR/ChunkSet、同一embedding profile → 新代际、向量/关键词索引及成员报告 | BGE-M3 1024维；按child构建，父只用于取上下文；检查实际成员/配置/向量后显式切换。查询、父扩展、外发、交付均再次鉴权 | 原始包可存储而不索引；缺门禁只入隔离候选库。失败保留旧代际及报告，旧来源失效时不得回退旧答案；不把写向量等同已接RAG | Embedding模型参与；KM选择合格批次/代际，不能靠系统管理员角色读正文 |

重新处理规则：原PDF变化创建DocumentVersion；引擎/权重/模式变化创建ParseRun；适配、结构恢复或有据人工校正变化创建同版本派生ParseRun并引用父批次及原包，无须重复MinerU调用；只改切分创建同IR的新ChunkSet。阶段输入/配置/输出清单形成指纹，Worker使用既有attempt/lease围栏，仅提交仍匹配原件、权限、服务许可及批次的结果。网络等待不持有长DB事务。本地解析也须搬离HTTP并进入持久Worker；不为此另引入编排框架。

每页有效尝试/裁区覆盖及父资产复用、冻结后的新批次规则、源级QC/叶块处置与集合级切分QC分别通过后建立候选ReviewSet的无环次序，唯一见[数据库22.7](../database/数据库设计.md#227-冻结核验及启用的确定时序)。候选单位为未选用的(Run,ChunkSet)，包含同IR新切分；新集合QC失败不使源Run或旧集合失格。effective同版用待审核的source_rebind动作重绑精确发布资格，失败保留旧指针，不能直接复用当前仅接受draft的核验/发布函数。

#### 10.4.1 处理、技术质量与人工审核状态

以下六项是**绑定具体产物的派生里程碑**，不是覆盖所有实体的单一status枚举，也不能直接从当前`ParseRun.succeeded`或HTTP202推断。平台负责技术门禁和审核依据有效性检查；业务人员对关键业务正确性作出核验，KM可登记其真实结论，模型不充当审核人。

| 里程碑 | 成立条件及必须保存的依据 | 不成立/失效时 |
| --- | --- | --- |
| Parsed | **Run级有效逐页来源清单**覆盖全部原页或有据空白，清单中每页实际产物均完整、契约可读且已归档/校验，可来自同固定profile不同attempt或有真实父来源的复用；并非要求单一attempt整本成功或仅远端done | 失败attempt仍记失败/partial，只有其中独立完整、可验证且已归档的页可被后续清单采用；缺页、畸形/缺失产物或归档失败不能整批Parsed |
| Normalized | Parsed后独立保存规范化IR；schema、原页/资源/原始节点映射受检，所有字段和未解释内容有明确处置；保留Normalized artifact身份/适配器版本 | 未知协议/断来源不通过；内容疑点可带issue保存，不因归一化完成认定内容正确 |
| Structured | 从固定Normalized IR形成独立、不可变的结构IR；树/阅读顺序/类型关系合法，关系依据与未决项完整记录 | 关系待核验可明确记录，但不能把Structured当作关系已正确；结构变更生成新派生Run |
| QC Passed | 源级报告绑定原件、两层IR、页/资源/关系及检查器修订，所有必需技术检查通过且无未处置技术阻断；集合级报告另绑定该源报告和精确ChunkSet/mapping。两级分别给出passed/needs_review/failed | 缺单位/表头、关系歧义、坏来源或截断等技术阻断不得passed；平台通过不代替业务真实性确认。新集合失败只影响自身，真实源缺陷按hold阻断 |
| Verified | 源级QC通过且所有关键业务事实/关系有职责有效的人工原页核验；候选级还须该ChunkSet.ready、集合QC通过、证据组保全，经新的精确ReviewSet记录为有效。源Verified不依赖候选ReviewSet，避免循环 | 任何必检事实/关系缺核验或依赖变化，当前资格为pending/stale/rejected；历史签认保留但不视为当前有效 |
| Published | 有效候选Verified＋适用/分类等业务依据＋无hold＋当前授权/ETag/预检检查，通过显式publish或同版source_rebind事务保存事件及精确资格 | 不能由QC Passed自动发布；撤回/依据失效即时阻断。Published后仍须完整活动索引就绪才可正式检索 |

技术主路径为Parsed→Normalized→Structured→源级QC Passed；源级人工核验与切分/集合QC可分别推进，再汇合为候选Verified→Published。源Run.succeeded只作22.7定义的源级兼容聚合，不能因新ChunkSet待核验而回写退级。失败恢复从最后**有持久产物且依赖仍有效**的阶段开始；不得通过重建旧状态标签恢复失效资格。

审核有效性每次重新解析/重切分、选用、发布、索引启用及正式使用时重算：原件/业务版本、内容/坐标、标题条件/警告、语义关系/资源、IR/切分/检查器修订、必检范围及真实核验依据任一受影响即失效。新Run不复制approved/Verified；仅改切分可重新判断未变源级依据，仍须新集合QC与新ReviewSet。允许复用的旧依据须逐项证明原件、内容、位置、关系和适用范围等价且职责/期限有效，记录比较与引用依据，不能仅看文本hash。审核证明独立追加、不改冻结IR；仅新增/撤销签认只重算对应Verified/发布资格，不重启无关解析/QC。独立失败候选不撤销仍有效旧集合；旧源真实失效先hold，修复候选按22.7的显式quality_repair重绑，不能因旧资格无效而被迫恢复坏来源或伪造业务版本。

### 10.5 结构优先的类型感知切分

**通用算法**：按已确认阅读顺序遍历叶块 → 建立不可拆的正文/步骤/公式定义/表格行组/图片图注证据组 → 仅在同一章节、适用条件与风险作用域内合并相邻组 → 以长度预算在合法边界再拆 → 生成原文区间映射与必需关联 → 检查缺失依赖/超限。短块不跨标题、型号、版本、表格或警告作用域强行合并；不使用固定滑窗重叠作为主策略。

| 类型 | 生成边界与必须保留内容 | 超长、跨页及关联规则 |
| --- | --- | --- |
| 普通正文 | 同一最低有效章节中的连续自然段组成child；保留限定词、否定、单位及引用编号 | 只在段落/句子边界拆；代词或条件依赖前文时追加有据原句范围或建立requires关系，无法消除歧义则待核验，不由模型补写 |
| 章节/标题 | 标题自身是源Block，章节为Structure容器；child继承标题路径的源引用 | 标题前缀标为context，不伪装正文；缺级保留未知层级，不能补造标题。目录页作为导航，不当作完整操作依据 |
| 编号步骤 | 一组操作的先决条件、顺序、动作和适用警告作为procedure parent；短程序一child | 长程序在完整步骤之间拆child，继承先决条件、编号及必须警告；不可将一个动作/按键同其限制分离。不同动作即使图标相同也分别绑定所在行语境 |
| 数学公式/变量定义 | 公式原表达、编号、变量定义、单位、适用条件及脚注形成证据组；正文引用指向同组 | 不按Token切断表达式/上下标/定义。缺定义不能猜；超长定义组保留parent并按完整定义拆child，以required依赖补全，不能在预算不足时输出可正式计算的公式 |
| 表格/表头 | 小表连同标题、多级表头、单位、行列/合并关系、脚注为一child；正文保留表号引用 | 大表按逻辑行组拆，重复有源表头/单位并映射原Block中的行列范围；跨合并单元格不切。单行或单元格超限不硬切，不把未知值补0；仅索引原标题等导航时明确不能作为数值证据 |
| 图片/图注 | 图、图号、原图注和明确的图例关系为一组，Asset指向原页区域及实际资源；原文说明可检索 | 无文字的图保留图像与“待解释”状态，不能把视觉摘要当事实；图形键须绑定具体步骤/单元格。可选模型描述放独立suggestion，不进入正式原文索引 |
| 跨页表格/连续段落 | 叶块保留各自原页，不物理抹掉分页；Structure容器及continues关系聚合 | 连续页、表号/续表标记、列数及表头含义、合并/单位一致等共同佐证；重复表头仅在检索展示层去重，原块保留。只凭同列数/相邻页/语义相似不足以合并；缺上一页表头时待核验 |
| 附录/参考资料 | 附录独立章节，保留附录编号和适用性；参考文献单条独立或同一书目组 | 附录中的规范表/操作仍按原风险审核，不能默认降权；参考链接仅为原文内容，不自动抓取/外发，也不把引用文献的结论当本文已确认规则 |

长度是保护上限，以下为**待样本校准的工程初值**：目标child约512–768 tokens，最大1536 tokens（含继承的标题/条件/警告），实际有效上限还须取所用embedding API经验证的token上限和字节限制中的更严者。当前合成出口的8192 UTF-8字节不是8192 tokens；使用固定tokenizer修订实数计数，不以字符数/4估算或允许服务静默截断。

无法在合法边界缩至上限的原子元素标记`oversized`，完整内容仍留IR/原页与待处理清单，不进入正式向量；可保留仅供定位的原文标题/图注导航单元，但须携带未覆盖内容状态，不能冒充完整知识。父对象不整体送Embedding；检索扩展的父级正文同样受任务剩余上下文预算约束。

**Parent-Child推荐**：适合“命中小片段、返回完整操作或表格语境”，但当前Block级检索不能直接支持。先落实既有设计中的chunks/chunk_blocks与同批次父关系；child存精确原文范围并向量化，parent引用章节/步骤/表组，按需装配，不生成摘要。首版只做一层parent-child，不递归塞入整个文档。

检索过程：①沿现有当前权限、型号、已发布版本、选用集合及活动代际筛child；②按`warns/defines/caption_of/continues/requires`补齐同批次必要关系及有源标题；③逐项重新查资格并按源范围去重；④按预算装配。全局安全警告仍作用于相应文档，局部警告只作用于其步骤/表格；未知作用域不自动附到最近段落，而是待复核。必须的限制无法放入预算时减少候选或返回证据不完整，不悄悄删警告；普通可选邻段可不扩展。索引分数不改变证据有效性。

### 10.6 质量控制、风险与异常处理

QC核对的是原件、解析、结构与切分之间的契约，不是重新编写内容的阶段。用户复审已明确：**公式、参数、单位、表格、操作条件、操作步骤及警告均为关键结构化内容**，与其含义关联的变量、表头、图注及关系也属必检范围，不能仅凭paragraph类型漏标。所有issue绑定版本/批次/页/块或关系、检查器修订、观察/依据、严重度、影响用途及处置；依赖改变时重开，不沿用模型“已修好”的结论。

| 维度 | 确定性检查能证明什么 | 视觉/人工必须补足什么 |
| --- | --- | --- |
| 内容完整性 | 原件页数与处理页一一对账；原生文字/数字/单位与解析差异；空页/异常短页；独立图像/矢量及前景区域与输出对照 | 原生文字可能错编码，扫描图含多个子元素；差异只能报警。人工原页标注确定真正内容及关键事实分母；数字小数点、正负号、指数、µ/单位和型号逐项检查 |
| 结构完整性 | 树无环、父子同批次、顺序键唯一、步骤编号跳变、双栏越列、页眉页脚重复候选 | 合法树不等于正确层级/顺序。疑难版面和跨页连接需原页对照；装饰判定有依据，不直接删页眉中的版本/警告 |
| 特殊元素完整性 | 表格网格不重叠且跨度有效、行列/表头引用齐全；公式语法和定义链接；图像资源可读取且位置合法 | 网格合法/LaTeX可解析不证明单元格、公式或按键含义正确；关键表格、变量、单位、图与动作关系由实际专业人员逐项确认，未知空格与真空值分别处理 |
| 语义完整性 | Chunk每段文字映射源Block范围、关键依赖闭合、跨条件/型号不混合、警告/表头/定义跟随、超长不截断 | 程序不能穷举自然语言依赖。局部复核歧义，人工检验真实问题所需证据组是否完整；模型可指出疑点，不能自行批准 |
| 证据完整性 | 原件身份、页序、坐标/变换、原始JSON指针、资源清单、Chunk→Block→Page链可解；渲染原区并对比 | 坐标在界内也可能指错区域。关键区域逐原页目视核对；无可靠区域的内容保持page-only/missing并待核验，不用整页框伪装精确定位 |

关键关系独立于文字准确率逐项验收；“两端文字正确”不能证明连接正确。下表由平台验证引用/结构并保存差异，业务人员依据原页确认实际含义；缺关系、错关系、跨作用域误连均作为失败项记录。

| 必检关系 | 技术检查与人工原页判据 |
| --- | --- |
| 公式—变量—条件 | 符号/上下标、变量定义/取值含义、单位和适用条件均有准确源引用；同名符号按章节/公式作用域分开，不能默认连最近定义；业务逐式核对表达及适用关系 |
| 参数—数值—单位 | 参数名、数值/范围、正负号/精度、单位和注释共属同一型号/行/条件；缺单位保持缺失，不从常识填充；跨行/跨型号共用单位须有原文依据并人工确认 |
| 表格—表头—单元格 | 每个值关联正确的多级行列头、单位/合并范围及脚注，续表有源表识别；程序查网格和引用，业务逐关键格核对，不能只比较导出的字符 |
| 操作步骤—前置条件—警告 | 步骤编号/先后、对象、动作、前置/分支条件及限制有明确作用域；拆分后仍带完整必需组；业务核对是否产生遗漏条件或错误操作顺序 |
| 图片—图注—动作 | 图号/图注/图例确属同图，表内图形键绑定所在单元格/动作；不得仅凭距离或同图形合并开关机含义；无文字图保留region证据并由业务确认含义 |

关系记录沿用数据库22.4，不另建评测框架；黄金参考保存期望的**端点＋子元素位置＋类型＋作用域＋原页依据**，运行结果逐条匹配并另报漏连/错连。关键关系未确认不得候选Verified/Published，OCR置信度或模型一致不替代该门禁。

风险与放行：

| 等级 | 典型对象 | 处置与放行 |
| --- | --- | --- |
| R0 普通正文 | 无异常信号、无关键规则/数据的常规段落 | 自动完整性/来源检查；沿用现有逐块核验和发布规则。本方案不授权自动将review_status改approved；未来减少人工另行批准 |
| R1 一般结构异常 | 层级/阅读顺序、非关键图注、可疑跨页连接 | 局部原页复核；允许一次有明确原因的同引擎受控补识，再不确定交人工。该次数是候选运行上限，不对未知外部POST自动重发 |
| R2 关键内容 | 全部公式、参数、单位、表格、操作条件/步骤/警告及其变量、表头、图形动作等必需关系 | 平台实施技术门禁，业务人员对照原页逐项确认业务正确性并记录职责依据；模型/OCR置信度只分配复核优先级，缺项/冲突不放行 |
| R3 不可判断/技术失败 | 缺页、解密失败、资源缺失、未知协议、矛盾数值、无法定位 | 保留原件/原包，显式blocked/needs_review或隔离；有权人补资料、校正或重新处理后重验。不可通过丢弃问题内容让整批通过 |

同引擎高档/裁区与额外视觉模型均只产生候选。**是否需要额外视觉模型的触发条件**是：现有原页有明确的关键缺口、同引擎修复无足够改善、许可和资源已获准，且固定失败集上预期收益能被人工参考验证；普通正文不全量再跑视觉模型。模型一致不是独立真值，OCR置信度不等于事实正确率。读取图线估数仅作为单独标记的估计候选，未确认用途/误差前不生成正式参数。

逐块核验的对象是源leaf；容器通过子叶、顺序和关系核验，observation通过原页完整覆盖/有据装饰处置等进入必检集合，不能要求它们伪造单独源框或approved。新核验指纹必须覆盖页处置、非文字依赖、关系、Chunk映射和QC报告；当前按所有ContentBlock物理行检查的代码须改造，不能直接套用。纯图/按键以region证据保留而非虚构quote，细则见数据库22.5/22.7。

沿用当前整批发布核验门禁：`ChunkSet.ready`只代表构建完成，不能代表内容可信。关键未决问题阻断相应处理及该版本整批正式选用/发布；原文参考阅读继续受显式开放和当前权限约束，不因QC引入新的草稿外发途径。现有published版本不被后台试验覆盖；旧来源一旦失效，即使新批次未准备好也不继续正式使用旧内容。

异常恢复：缺组件/权重返回明确待配置；格式或schema错误隔离原包且不重试相同输入；OOM先调整有据页窗口/并发，在新尝试记录配置，不丢页；局部候选重识不得混入已冻结批次。网络超时保留远端ID、调用账本与结果未知状态，轮询限额/退避在服务profile锁定；任务取消按attempt围栏阻止晚到结果落当前集，远端取消不可用时说明“本地停止使用、远端状态待核对”。服务TLS失败不关闭校验。所有页面图/解析资源的读取、缓存、外发和删除继承原文当前授权与留存政策。

仅围绕已见风险建立定向回归：正文旁图形、少量文字掩盖扫描正文、表内图形键与警告、跨页误合并、坐标变换、归一化资源丢失、超长原子元素及旧引用。升级时重放受影响契约与冻结样本；不每次重切分都全量OCR，不为凑证明新增Mock或重复全量测试。
