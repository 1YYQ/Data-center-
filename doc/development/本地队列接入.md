# Celery/RabbitMQ 本地接入状态

用户已授权本地接入验证。首选方式保持现有持久TaskOutbox：提交业务事务后再投递仅含`task_id`与`dispatch_id`的不透明消息；Celery worker必须按task/step重新读取数据库、重验当前授权并调用现有Pi执行宿主。Broker消息不包含提问正文、授权、模型配置、存储路径或凭据。重复投递由现有task/step租约与调用账本收敛；未知派发结果不得换ID盲目重发。

## 当前代码入口

`src/server/queue_runtime.py`提供Celery任务、受限JSON消息及有界outbox publisher。broker使用`confirm_publish=True`，关闭Celery publish自动retry，避免连接断开后新task身份重发。publisher只选择`QueryTask.kind=query`且`TaskStep.step_key=query`的待发送行，其他维护任务保持原outbox状态；publisher通过`FOR UPDATE SKIP LOCKED`和状态CAS领取待发送行；lease 2分钟，崩溃后可复用原dispatch id。publisher要求显式环境变量`DATACENTER_DATABASE_URL`、`DATACENTER_CELERY_BROKER_URL`和`DATACENTER_STORAGE_DIR`；可选`DATACENTER_CELERY_QUEUE`只用于受控隔离队列。worker另需`DATACENTER_PRIVATE_GATEWAY_URL`及固定profile ID/revision。一次投递使用`python -m src.server.queue_runtime --publish-once --limit 100`；有界前台常驻loop可用`python -m src.server.queue_runtime --publish-loop --interval 2 --limit 100`，Ctrl+C退出。短时发布错误输出脱敏类型并等待下一轮/claim lease复核，不立即换ID重发。不得把数据库/凭据写入消息或交互式命令历史。执行入口调用`run_one(..., task_id=...)`，只会选择该任务的可执行step；不指定task_id时保留原本地单次轮询行为。

outbox消息使用稳定TaskOutbox.id作Celery task_id与dispatch_id。publisher仅在confirm成功返回后，通过SQL状态与claim时间CAS推进published；确认未知时行保持publishing至租约过期，再以同一dispatch id复核/重发。发布确认与DB状态不是同一原子事务，极端崩溃仍可重复投递；消费者由原业务task/step租约及工具账本去重。

## 实测范围

- Python Celery 5.3.4、RabbitMQ官方镜像4-management-alpine；PostgreSQL 18、pgvector迁移0007。
- 本地容器`dc-local-rabbit-20261117`只绑定`127.0.0.1:56741`；队列验证使用`dc-local-*`独立队列，未读取/ack/purge共享业务队列。
- 真实Celery worker通过持久outbox领取合成查询任务，运行固定Node/Pi SDK及回环合成模型，完成原任务；另在PostgreSQL新建`dc_local_pgvector_queue_<uuid>`数据库完成相同路径。真实Rabbit重复投递同task/dispatch后不增加AgentRun、ModelCallAdmission、预算修订或新回答快照。
- RabbitMQ 4拒绝Celery 5.3默认remote-control pidbox临时队列并返回541；本地Worker关闭非必要remote control，持久业务队列继续运行。启动系统worker时使用`--without-gossip --without-mingle --without-heartbeat`。
- `final.xml`为11项最终回归（含SQLite outbox、真实RabbitMQ Celery worker及PG18/pgvector迁移联合烟囱）；`report.json`绑定容器、测试数、局限与源码hash。earlier attempt报告保留修复前失败。

本地命令提示：

```powershell
$env:DATACENTER_DATABASE_URL = '<隔离数据库URL>'
$env:DATACENTER_STORAGE_DIR = '<隔离存储目录>'
$env:DATACENTER_CELERY_BROKER_URL = '<已获准本地RabbitMQ URL>'
$env:DATACENTER_PRIVATE_GATEWAY_URL = 'http://127.0.0.1:<FastAPI端口>/'
python -m src.server.queue_runtime --publish-once --limit 100
python -m celery -A src.server.queue_runtime:app worker -P solo -Q data-center-query -c 1 --without-gossip --without-mingle --without-heartbeat
```

以上命令要求同一受控环境已注册匹配SDK profile；示例不包含凭据值。publisher不会读取maintenance任务。不得改真实授权或部署。

## 设计约束

1. PostgreSQL/业务DB中的TaskOutbox是待投递权威；RabbitMQ只携带引用，不成为业务状态权威。
2. outbox publish必须先有稳定dispatch身份；发送前以行锁/CAS认领pending→publishing，lease过期后可以相同dispatch ID重新发送。Celery publisher confirms开启，task_publish_retry显式关闭；确认未知时不做即时自动重试，等待稳定outbox身份过期核对。
3. Celery任务接收后只加载受控本地配置及task ID，再调用现有`run_one`的定向执行入口；不把数据库URL/storage路径塞入消息。
4. 无法确认消费结果时按原任务账本核对；模型调用unknown或已有run时不自动创建新逻辑动作。
5. 当前显式本地Worker可继续独立执行；不能据Celery配置/任务注册宣称RabbitMQ已接通。
