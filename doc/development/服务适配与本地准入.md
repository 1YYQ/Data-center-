# 服务适配与本地准入

2026-11-18。沿用 API19.4、数据库19.2、模型与解析方案；用户授权持续本地开发，真实签认/人工答案为真实验收待办，不阻塞独立工程。

采用现有 FastAPI/SQLAlchemy/Alembic 和标准库 HTTP，无新增框架。先实现 generation / embedding / parsing 三类协议及受控服务测试链：配置容器→不可变修订→固定合成自检→短期预检→启用/停用。配置、测试、许可和健康分别呈现。服务选择与业务发布、索引、Pi 运行许可不合并，不自动切换现有业务出口。

本地策略仅接受显式登记的127.0.0.1回环端点。自检使用固定fixture；业务还须私有夹具登记逐actor/用途/资源/精确输入hash。禁止外部目标、重定向、跨来源上传/下载及未证明的任意用户正文。凭据为受控进程环境引用，API/数据库不收存明文。HTTP和HTTPS均须显式登记；HTTPS使用可信CA、证书及IP主机名校验，不能关闭验证。企业数据准入保持未配置，合成启用不能转化为企业调用许可。后续真实服务网络策略需独立准入，本轮不向供应商发送资料。

协议适配器仅通过 ProviderTransport.request(method,target,body,purpose,content_type) 进行 I/O；安全异常仅返回 ProviderError.code。传输层逐请求检查当前配置/密钥修订/许可，调用意图先持久化，未知结果保留账本且不自动重发；只可凭既有 MinerU batch_id 查询。远端返回不作为指令、不执行 ZIP 内容，不把解析结果自动核验或发布。

验收覆盖本机真实 HTTP 的正常协议、畸形响应、超时/断线、禁用/旧预检、凭据变化、跨来源地址、一次消费与恢复；独立合成数据库验证迁移和持久账本。真实供应商兼容性、语义质量和真实 A–F 明确未验收。

协议依据：[MinerU 精确解析 API](https://mineru.net/doc/docs/index_en/)、[MinerU 输出格式](https://opendatalab.github.io/MinerU/reference/output_files/)、[SiliconFlow embeddings OpenAPI](https://github.com/siliconflow-inc/siliconflow-api/blob/main/openapi.yaml)。BGE-M3 1024 维，不发送其不支持的 dimensions 参数；供应商仍未选定。

MinerU兼容范围明确固定为精确解析v4批量上传API加旧版Content List V1 JSON，不把当前4.x Structured Content等未支持格式默认为空白成功。畸形/歧义格式拒绝；图注、表格正文/脚注、公式等支持内容保留原类型和定位，统一待核验。实际供应商当前返回格式仍待准入后验证。

## 本机操作入口

先按[安全迁移](安全迁移与事故核查.md)准备显式隔离库及当前schema；默认SQLite禁止启动或迁移。旧PG不自动升级。以下环境变量须在模拟器和应用两个独立终端分别设置，所有值仅为合成测试：

```powershell
$env:DATACENTER_SYNTHETIC_TEST_KEY = 'SYNTHETIC-local-development-only'
$env:DATACENTER_SYNTHETIC_SERVICE_ENDPOINTS = '{"synthetic":{"port":9041,"credential_env":"DATACENTER_SYNTHETIC_TEST_KEY"}}'
python -m src.server.synthetic_provider --port 9041
```

模拟器只监听回环且不向外请求。另一个终端在明确设置`DATACENTER_DATABASE_URL`与`DATACENTER_STORAGE_DIR`、核实当前隔离schema后运行`python run.py`，用本地合成系统管理员打开`http://127.0.0.1:8000/workspace/services`。配置类型选生成/向量/解析，模型分别为`synthetic-chat`、`BAAI/bge-m3`、`vlm`；先创建配置、保存修订、运行合成自检，再预检并单独确认启用；停用也有独立预检/回执。页面不提供凭据明文、外部URL或企业数据准入修改。

HTTPS登记额外字段`scheme:"https",tls_ca_file:"<受控本机CA文件>"`，端口仍只允许127.0.0.1；自测TLS服务器证书需包含该IP的SAN。CA/凭据/代码变化须重新自检。TLS测试用OpenSSL生成一次性合成证书；生产模块仅依赖Python标准库ssl，不新增PDF引擎或TLS依赖。

## 逐用途选用及可信Worker

配置启用后，在同页单独为document.parse/document.embed/query.answer/query.summary/query.compaction预检并确认选用。普通切换只影响新任务，停用会永久撤销旧epoch的pin；重新启用不会复活。精确修订、自检、秘密/CA/代码指纹和有效期固定，过期不自动续期。没有合成字节证明的请求安全拒绝，网页不能自行颁发证明；`testing_service_use.attest_synthetic_input`只供私有合成夹具使用，不能拿它签发企业资料许可。

业务接入可通过既有解析POST的`{mode:"selected_service"}`、查询POST的`service_mode:"selected_service"`及新embedding-jobs入口显式选用，契约见API19.4。解析HTTP受理后先提交任务，可信进程在显式环境与当前schema上推进：

```powershell
python -m src.server.parse_worker --run-id <已受理解析ID>
python -m src.server.embedding_worker --job-id <已受理嵌入ID>
```

解析CLI要求显式DATABASE_URL/STORAGE_DIR；嵌入要求显式本地PG，均检查schema、不自动迁移。Pi继续沿本地worker/private gateway与固定SDK入口，selected任务不回退旧端口；Runner不持供应商密钥。生成合成向量不自动切关键词索引或证明语义质量。原batch恢复仅GET；无ID未知保持待核对，新HTTP key不绕过。同原件解析和同version/chunk嵌入均保留逻辑动作围栏。

当前选用解析只接受不超过64KiB的已证明PDF，响应归档上限1MiB；嵌入单批最多32块、输入合计32KiB，超限明确拒绝。它们是本地合成接线的限制，不能当作真实复杂手册容量验收。解析原始ZIP保存在internal/parse-results，只有待核验规范化结果进入管理流程；畸形结果隔离。文件写入后、关联提交前崩溃可能遗留不可访问孤儿，清理/留存机制仍待办。
