# 决策演进

本文件只记录会持续影响实现的取舍。它不取代 ADR、SPEC 或 PLAN；每项均保留依据和失效条件。

## D-001：首期优先设备操作维护查询

- 状态：当前
- 决策：首期先打通按设备型号查询已确认适用的操作与维护资料，并提供版本、出处和缺失/冲突提示。
- 原因与取舍：这是当前用户已明确的优先任务，能先验证资料沉淀、检索、证据核对和说明交付的完整链路；计算填表和多资料对比暂不挤入首期范围。
- 拒绝的替代方案：一开始同时实现所有办公成果，或先做通用知识管理平台；它们会扩大未验证范围并掩盖首期证据链问题。
- 依据：[`SPEC.md`](../requirements/SPEC.md#13-首期场景设备操作与维护资料查询)、[`PLAN.md`](../planning/PLAN.md)
- 失效或复评条件：用户明确改变首期优先级，或真实样本验证显示该场景无法在既定权限、资料和验收约束下形成完整闭环。

- 原因与取舍：这些路线已在现有架构文档中形成基线，同时保留实现验证和后续修订空间；Memory 不替架构文档重复保存组件细节。
- 拒绝的替代方案：在 Memory 中另起一套模型、数据库或服务选型，或把尚未验证的接入写成已实现。
- 依据：[`模型与解析方案`](../architecture/模型与解析方案.md)、[`前后端技术方案`](../architecture/前后端技术方案.md)、[`README.md`](../../README.md)

## D-003：Memory 采用 Markdown + 轻量校验

- 状态：当前
- 决策：用 `doc/memory/` 的 Markdown 文件承载上下文、决策和状态，用 `python -m src.memory.validate` 做确定性结构检查，不引入数据库、向量检索或后台服务。
- 原因与取舍：2026-11-15 建立该机制时以“应用尚未实现”为阶段前提，选择 Git 和文档作为低成本持久化介质；这是历史依据，当前实现见 STATUS。轻量校验仍用于结构检查，不冒充语义或业务验收。
- 拒绝的替代方案：结构化索引和独立 Memory 服务；当前任务规模不足以抵消双写、同步、权限和运维成本。
- 依据：[`2026-11-15-harness-memory-design.md`](../design/2026-11-15-harness-memory-design.md)、[`AGENTS.md`](../../AGENTS.md)
- 失效或复评条件：多个项目共享记忆、任务规模使按需读取无法维持，或出现有证据证明 Markdown + Git 无法满足可靠性和权限需求。

## D-005：普通使用者采用持续对话、可选范围与独立资料查阅

- 状态：当前
- 决策：2026-11-17 用户确认同一对话追问/补充并记住已确认设备型号和条件，新工作可新建对话，历史及出处保留；默认检索当前有权查询资料并允许手动缩小；按型号或文件名直接查阅有权手册，引用可进原文；首期仅分享单条回答及设备条件/版本/出处，接收者仍需资料权限，整段对话分享后置。
- 原因与取舍：用户希望像本次交流一样连续处理工作问题，同时可直接查手册，减少前置选库操作；消息和资料权限仍需逐次核对。保留单条分享边界，避免隐式暴露其他工作过程。
- 拒绝的替代方案：强制每次先选部门/资料库、只允许独立单次查询、只能通过引用打开手册、分享整个对话或通过分享补授权。
- 依据：用户于2026-11-17在本会话逐项确认，并明确要求回写；权威需求见 [SPEC 1.3.2](../requirements/SPEC.md#132-普通使用者交互确认2026-11-17)、[角色说明](../roles/普通使用者.md)，设计建议/待确认边界见 [网页契约](../../specs/001-device-operation-maintenance-query/contracts/ui.md)，实际进度见 [STATUS](../planning/STATUS.md)。
- 失效或复评条件：用户明确调整交互/分享范围，或业务权限、真实任务及验证证据要求修订。布局/视觉、异常恢复和候选后端细节尚未全部确认，本条不授权直接编码或外部调用。

## D-006：员工资料问题反馈与确认发布相互独立

- 状态：当前
- 决策：2026-11-17 用户确认员工可从当前对话或手册页面提交资料问题反馈，由知识管理员后续处理；反馈不等于业务确认或自动发布。候选方案保持资料范围与对话权限边界，不因受理开放整段对话；员工随后进一步确认可在原对话/手册页查看进度和管理员答复，资料更新后提示重新查询并保留旧回答；具体状态标签、分派及通知方式仍待讨论。
- 原因与取舍：为缺失、版本或内容问题提供处理去向，延续原有业务确认、内容核验和发布分工；反馈事实本身不能证明资料有效或问题已解决。
- 拒绝的替代方案：用反馈直接确认/发布资料、默认转发完整对话、向所有知识管理员广播正文，或把界面草案写成已实现能力。
- 依据：本会话用户2026-11-17明确确认并要求同步；权威要求见 [SPEC FR-017](../requirements/SPEC.md#131-首期需求编号与覆盖边界)，接收职责见 [知识管理员](../roles/知识管理员.md#员工资料问题反馈已确认接收职责)，具体候选字段见 [API 13.4](../api/接口设计.md#134-资料问题反馈候选设计)；进度见 [STATUS](../planning/STATUS.md)。
- 失效或复评条件：用户变更反馈或处理职责，或实际权限/受理流程证据否定候选方案。完整管理界面和分派未确认，本条不授权应用实现或自动发布。

## D-009：发布前确认核验齐全，索引就绪后正式查询

- 状态：当前
- 决策：2026-11-17用户明确选择采用发布门槛：业务适用确认、内容核验和所需关键专业确认齐全后才允许发布；发布后仍须索引就绪，才允许正式查询。系统外实际确认、知识管理员登记和系统授权继续分离。

- 拒绝的替代方案：未核验先发布、仅解析成功即认定可信、用上传时间或模型判断替代业务确认、发布即宣称可查询。该项取代旧API5/数据库5中发布独立于解析完成的宽泛表述。
- 依据：用户本会话2026-11-17对发布门槛问题明确回答“采用这个门槛”；权威要求见[SPEC职责](../requirements/SPEC.md#2-职责划分)，动作与门禁见[API17.3](../api/接口设计.md#173-发布预检执行和索引衔接)、[数据库17.3](../database/数据库设计.md#173-发布撤回及失效事务)和[管理员流程](../design/知识管理员界面与对接方案.md#44-发布索引与撤回)，实现状态见[STATUS](../planning/STATUS.md)。
- 失效或复评条件：用户明确调整门槛，或真实业务/版本与核验样本要求修订。界面导航、实际受理名单及具体实现仍按权威文档待确认/开发，本条不授权编码、发布企业资料或外部调用。

## D-013：未分类资料先限制为上传者及明确单文档管理者

- 状态：当前
- 决策：2026-11-18用户授权非环境阻塞自主继续后，Agent选用保守可逆默认：分类维度任一未知时，KB继承管理权仅首版上传者可用，且必须仍有当前有效完整授权；其他管理员需要明确单文档管理授权。首版缺失不推断所有者，后续版本不转移身份；分类齐备后恢复原元组规则。
- 原因与取舍：避免未知分类使同KB其他范围管理者提前读取原件。代价是协作需已有批准后的单文档授权；上传身份不授予权限，普通DR/正式问答门禁不变。
- 拒绝的替代方案：所有KB管理员共享未分类原文、用上传者身份绕过当前授权、由Agent伪造分类或企业审批。也不把用户的自主推进授权写成逐项选择该策略。
- 依据：[SPEC9](../requirements/SPEC.md#9-未分类资料的保守隔离默认2026-11-18)、[开发说明](../development/资料创建与生命周期验证.md)、[STATUS](../planning/STATUS.md)及本轮用户的自主推进指令；运行证据与现行候选在STATUS/tasks引用。
- 失效或复评条件：用户/企业提供明确隔离制度，或真实协作样本证明默认不适用；调整前保持最小可见范围，不从本条推导真实授权/外发或业务签认。
