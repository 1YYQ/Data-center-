# 长期项目理解

更新时间：2026-11-16  
记忆类型：长期背景（不是规范）

## 项目为什么存在

数据中心用于持续沉淀企业文档，并在授权范围内帮助用户获取、理解和整合资料，必要时执行可复核的计算或办公处理。它要减少重复上传和整本手册占用上下文，同时保留版本、适用范围、公式条件和结果来源。

**为什么保留**：这是跨会话仍需理解的产品方向，单靠局部代码不足以恢复完整用户目标。  
**来源**：[`README.md`](../../README.md)、[`SPEC.md`](../requirements/SPEC.md)

## 核心用户体验

用户应能围绕具体任务，在自己有权访问的资料中获得可核对的说明：知道采用了哪份资料、版本和适用范围，能回到原文位置，并清楚看到缺失、冲突、待确认或待人工复核的部分。

**为什么保留**：它说明“回答有内容”不是完整成功条件，证据和状态同样属于用户结果。  
**来源**：[`SPEC.md`](../requirements/SPEC.md#13-首期场景设备操作与维护资料查询)、[`AGENTS.md`](../../AGENTS.md)

## 长期原则

- RAG 只提供检索增强，不构成正确性保证；重要结论必须回溯原文和有效版本。
- 模型负责理解和组织，正式数值由受控、可重复的程序或表格公式计算。
- 缺少关键依据、版本冲突、型号不符、公式歧义或权限不明确时，保留缺项或阻断相关结果，不用猜测补齐。
- 原始文件是依据，解析文本和索引是可重建派生数据；来源、权限和版本变化必须影响派生内容的可用性。

**为什么保留**：这些原则跨越多个未来模块，能帮助新会话识别代码或文档中的局部实现是否越过了证据边界。  
**来源**：[`AGENTS.md`](../../AGENTS.md)、[`SPEC.md`](../requirements/SPEC.md#3-资料如何成为可信知识)、[`PLAN.md`](../planning/PLAN.md)

## 适用范围与不确定性

截至本记录日期，首期优先任务是设备操作维护查询；计算填表、多资料对比和报告生成随后推进。角色流程、获准样本、业务版本确认和真实验收仍有待调查，不能把尚未确认的内容当作长期事实。

本文件保留长期背景；当前实现、已核实证据、依赖和下一步统一见 [`STATUS.md`](../planning/STATUS.md)，不从本段旧调查线索推断整个应用尚未实现。
