# Harness Memory 入口

本目录保存跨会话恢复所需的最小项目记忆。它是上下文线索，不是新的规范、授权来源或聊天记录。权威顺序仍为：用户当前指令与授权、适用的 `AGENTS.md`、当前有效的 SPEC/PLAN/ADR、实际代码与验证证据，最后才是本目录的记忆。

本目录仅用于开发助手。普通员工的四层产品记忆由 [架构7](../architecture/前后端技术方案.md#7-四层产品记忆设计)、API16和数据库16设计；不能从这些Markdown恢复员工设备参数、企业资料授权或任务执行状态，也不能把本目录校验通过写成产品记忆已实现。

## 会话启动

按以下顺序读取，按任务范围停止扩展：

1. 先读取适用的 `AGENTS.md`，确定工作边界和必须回溯的权威文档。
2. 读取本文件、[`context.md`](context.md) 和 [`state.md`](state.md)。它们恢复长期背景与来源；项目进度、实施或恢复任务还须沿指针读取 [`STATUS.md`](../planning/STATUS.md) 和相关任务检查点。
3. 只有任务涉及某项历史取舍时，才读取 [`decisions.md`](decisions.md) 的对应条目，再回溯它引用的 SPEC、PLAN、ADR、代码或验证记录。
4. 检查记忆中的关键事实是否仍与当前 Git 工作区、权威文档和任务状态一致。发现冲突、过期或来源不足时标为不确定，采用当前有效来源并记录差异。

普通任务不扫描整个仓库、不读取全部决策、不从历史聊天推断授权。Memory 不能扩大任务范围、资料权限或执行权限。

## 文件约定

- `context.md` 只保留跨任务仍有价值的项目定位、用户体验和长期原则，重点写为什么；每项必须有来源。
- `decisions.md` 只保留持续影响实现的决策。每项必须写 `状态`、`决策`、`原因与取舍`、`拒绝的替代方案`、`依据` 和 `失效或复评条件`。被取代的条目保留历史原因，不静默覆盖。
- `state.md` 保留统一状态入口、仍有价值的模块历史证据和边界，按 `已实现`、`已验证`、`未验证`、`阻塞` 区分，并为每项写依据、范围和日期；不再复制整项目进度。项目状态与任务检查点在 STATUS/tasks 维护，历史快照不自动适用于当前候选。
- 来源优先链接到当前仓库中的 SPEC、PLAN、ADR、代码路径、Git 提交或验证记录。没有来源的内容只能写成假设或待验证，不得变成执行指令。

结构检查命令：

```powershell
python -m src.memory.validate
```

该命令只检查文件结构、状态枚举、必要来源字段和本地 Markdown 链接；通过结构检查不等于业务结果正确或跨会话体验已证明。

纳入项目既有 Verify 入口的完整检查：

```powershell
python verify.py --task harness-memory --output outputs/verify/harness-memory/report.json
```

该契约复用 SPEC、PLAN、AGENTS 和本设计文档作为来源，并检查结构校验和 Python 编译；报告中的 `PASS` 仍只覆盖确定性工程检查。

## 任务结束时沉淀

只有信息发生了会影响后续会话的实际变化才更新：

- 新的长期约束或用户体验原因 → 更新 `context.md`，保留依据。
- 已批准且持续影响实现的设计 → 更新 `decisions.md`，或直接引用已有 ADR。
- 已核实的项目实现、验证或阻塞变化 → 更新对应任务/验收记录与 `STATUS.md`；仅在恢复指针或模块历史证据本身变化时更新 `state.md`，标明日期、范围和依据。

临时推理、一般聊天、重复代码信息和未验证结论默认不写入。更新前先检查当前文件和 Git 差异，避免覆盖其他会话已经记录的新变化。

## 完整恢复、使用与更新示例

**恢复**：新会话接到首期查询任务时，读取本文件、`context.md` 和 `state.md`，再从 `STATUS.md` 与相关任务检查点取得当前候选、失败证据和下一步；随后按任务范围读取 SPEC/PLAN。核对 Git 和文件哈希后只刷新变化部分，不从 Memory 的历史状态推断当前实现或新增授权。

**使用**：若 `decisions.md` 记录“首期先打通设备操作维护查询”，Agent 会把它当作需要回溯的历史取舍，并以当前 SPEC 和用户当前指令为准。若 `README.md` 或 SPEC 已显示范围变化，Agent 标记旧条目为被取代或待复评，报告差异后继续当前授权范围内的工作。

**更新**：若一次验证仅证明脚本运行，记录该检查的真实结果与日期，并将超出覆盖范围的业务任务保留为未验证。任务记录与 STATUS 不因脚本通过而宣称完整链路通过。若 SPEC 或代码改变决策前提，保留历史条目及取代关系。

## 当前验证边界

本项目可以在仓库内验证冷启动材料、来源链接、状态枚举、冲突标记和最小读取规则。当前未启动一个真正独立于本会话的 Agent 来证明跨会话恢复；该限制必须在交付报告中保留，不能用同一会话的模拟替代。
