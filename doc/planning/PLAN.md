# 数据中心 · 实施计划

状态：草案。依赖 [SPEC.md](../requirements/SPEC.md)，当前仅完成仓库、目录及规划文档建立，尚无应用实现。

## 阶段一：角色工作与资料障碍调查

- 分别从普通使用者、知识管理员和系统管理员的工作目标出发，调查现有资料渠道、所需信息、无法获取或完成的事项，以及当前人工替代办法。
- 以近期实际工作记录验证问题，区分资料未找到、未收录、没有记录、版本不明、无权访问和后续处理困难；不预设现有系统不具备某种能力。
- 按发生频率、耗时或错误影响、资料可获得性和实现成本选择首期场景；公式计算与 Excel 保留为候选，不提前锁定其优先级。
- 为选定场景准备获准使用的资料、输入与人工参考成果；企业原件放在本地 `data/`，不提交 Git。
- 逐项解决 SPEC 中影响该任务的待确认事项，记录决定与依据。
- 完成条件：关键角色障碍有实际依据，首期任务与预期收益明确，并具备可核验资料和成果。缺失时保持假设状态，不以模型生成的角色故事替代真实需求证据。

## 阶段二：细化规格与验收样本

- 根据样本修订 SPEC，明确必须保留的文档结构、公式字段、输出模板与异常行为。
- 按选定场景检查数据库与接口缺口。若涉及正式计算与 Excel，必须先补齐公式版本、变量单位、计算记录、缺项反馈及导出契约；若涉及其他办公任务，则定义对应成果与验证方式。
- 建立正常任务及缺项、冲突、型号不符、单位错误等对照案例。
- 记录基线，确定验收阈值及需要业务人员复核的结果。
- 完成条件：每项首期需求都能对应可检查的预期结果；影响技术验证的未决项已解决。

## 阶段三：验证完整流程

- 在 `src/` 实现选定场景的完整链路：资料沉淀 → 解析与权限管理 → 按任务获取证据 → 理解和组织内容 → 必要的工具处理 → 交付与核验。是否需要计算、对照、清单或文件生成由真实任务决定。
- 优先验证已选择的 [BGE-M3 + MinerU VLM](../architecture/模型与解析方案.md) 路线，再按样本选择尚未确定的组件；记录效果、成本与局限，出现不满足验收的证据时再评估替代路线。
- 对失败案例定位原因，区分资料缺陷、解析错误、检索遗漏、计算错误和输出问题。
- 完成条件：选定任务的正常与失败路径达到约定标准，产物可打开、可定位来源、可复算；未达标项有明确记录。

## 阶段四：扩展为可持续使用的产品

- 依据验证结果确定架构，再逐步补齐资料更新、失效处理、任务记录、权限和交互能力。
- 为新增格式与任务单独增加验收样例；未经验证的能力不列入已支持范围。
- 完成条件：已约定范围内的完整流程及数据生命周期、权限隔离通过验证，实现与文档一致。

## 阶段五：真实工作评估

- 在获准环境中对照人工基线，检查正确性、上下文用量、任务耗时和复核成本。
- 将失败任务加入回归样本；按证据修订检索、解析或交付方式。
- 完成条件：达到已确定的业务验收标准，并说明适用范围与仍需人工处理的情况。

## 当前推进边界

未决事项集中跟进于 [开工前待确定项](开工前待确定项.md)，当前先调查角色视角的资料与办公障碍，再确定首期场景；后续按依赖解决认证、数据使用和交付规则。

下一步先了解普通使用者现有资料获取渠道与实际卡点。此计划不预设工期、尚未选择的技术栈或已通过的指标；在具体资料和服务的数据使用范围明确前，不接入真实企业数据到外部服务。
