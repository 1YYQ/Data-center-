## 阶段一：任务与资料调查

- 首个任务已确定为“计算公式手册 + 一组参数 → 单位与条件核对 → 计算 → 可溯源 Excel”，详见 [SPEC 1.1](../requirements/SPEC.md#11-首个业务闭环已确定)。继续记录该任务当前的人工处理与复核过程。
- 准备获准使用的计算公式手册、一组输入与人工预期结果，以及可用的 Excel 样例；企业原件放在本地 `data/`，不提交 Git。
- 逐项解决 SPEC 中影响该任务的待确认事项，记录决定与依据。
- 完成条件：任务范围、样本使用权限、目标字段、原文证据、人工预期结果和数据流向明确。缺失时继续文档整理，不以假设代替正式验收依据。

## 阶段二：细化规格与验收样本

- 根据样本修订 SPEC，明确必须保留的文档结构、公式字段、输出模板与异常行为。
- 补齐首期必需的公式版本、变量与单位、输入快照和计算记录设计，以及参数校验、缺项反馈和 Excel 导出接口；目前这些尚未完整覆盖，不能推迟到首期验收之后。
- 建立正常任务及缺项、冲突、型号不符、单位错误等对照案例。
- 记录基线，确定验收阈值及需要业务人员复核的结果。
- 完成条件：每项首期需求都能对应可检查的预期结果；影响技术验证的未决项已解决。

## 阶段三：验证完整流程

- 在 `src/` 实现最小链路：公式手册登记 → 解析定位 → 检索证据 → 参数完整性、单位与条件校验 → 缺项时提示补充 → 确定性计算 → Excel 导出 → 独立核验；参数未补齐前不执行依赖计算。
- 优先验证已选择的 [BGE-M3 + MinerU VLM](../architecture/模型与解析方案.md) 路线，再按样本选择尚未确定的组件；记录效果、成本与局限，出现不满足验收的证据时再评估替代路线。
- 对失败案例定位原因，区分资料缺陷、解析错误、检索遗漏、计算错误和输出问题。
- 完成条件：选定任务的正常与失败路径达到约定标准，产物可打开、可定位来源、可复算；未达标项有明确记录。

## 阶段四：扩展为可持续使用的产品

- 依据验证结果确定架构，再逐步补齐资料更新、失效处理、任务记录、权限和交互能力。
- 为新增格式与任务单独增加验收样例；未经验证的能力不列入已支持范围。
- 完成条件：已约定范围内的完整流程及数据生命周期、权限隔离通过验证，实现与文档一致。

## 阶段五：真实工作评估

- 在获准环境中对照人工基线，检查正确性、上下文用量、任务耗时和复核成本。
- 将失败任务加入回归样本；按证据修订检索、解析或交付方式。
- 完成条件：达到已确定的业务验收标准，并说明适用范围与仍需人工处理的情况。
