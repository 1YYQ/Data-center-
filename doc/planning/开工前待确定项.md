# 业务前置条件与首期开发基线

用途：保留D00–D09既定边界，并维护业务未知项、拟定岗位责任和待签认材料；工程准入与文档维护规则唯一见[baseline](../../specs/001-device-operation-maintenance-query/baseline.md)。2026-11-17用户授权推进基线收敛，确认DM显式开放待确认原件仅供参考，并要求先自拟岗位安排。规则和实现分别以SPEC/API/数据库及代码为准；本文件是可评审的准备基线，不产生真实业务确认、任命、开发、外发或部署授权。当前状态只在[STATUS](STATUS.md)，执行状态只在[tasks](../../specs/001-device-operation-maintenance-query/tasks.md)维护，不按D00从头重开已定路线。

## 1. 已确定的部分

React + FastAPI、PostgreSQL + pgvector、BGE-M3、MinerU（本地Standard优先验证、云VLM独立备选），以及 TypeScript、Vite、Ant Design、SQLAlchemy、Psycopg 3、Alembic、Celery + RabbitMQ 已有选型基线，不重复询问。

首版本地 Docker 开发、后续考虑企业内网部署、先外部 API 并保留本地模型切换能力也已确定。已存在的本地依赖/SDK/数据库/队列和合成协议证据以STATUS/tasks为准；真实供应商兼容性、业务适用性和逐服务外发资格仍未验收，不把本表的规划状态作为当前实现清单。

## 4. 生产或后续阶段前确认

- 内网主机、推理硬件及本地模型规模：本地推理部署前确定，不要求外部 API 原型阶段先采购硬件。
- 企业浏览器、统一登录及部门目录：若首版必须接入现有企业环境则提前，否则在对应接入前确定。
- 留存期、永久删除、备份窗口和恢复目标：写永久清理逻辑及接入正式业务数据前确定；现有设计不自动永久删除资料。
- 并发量、高可用与性能目标：依据真实使用规模确定，不默认首版必须建设集群。
- 重排模型、历史版本检索与更多格式：由样本效果及实际任务驱动，不为凑齐选型提前引入。
