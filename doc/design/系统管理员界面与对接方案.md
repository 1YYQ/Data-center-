日期：2026-11-17。范围：账号与角色、资料授权、模型与解析服务配置、任务监控、审计、备份恢复，及其与20项工具、四层记忆和Pi基底的衔接。本轮为完整功能结构及接口设计，未编写产品代码、安装依赖、修改真实授权、调用外部服务或执行备份恢复。已有确认沿用；新增导航、控制粒度和恢复步骤标为候选，不作为已批准企业政策或已实现功能。

职责依据见[系统管理员](../roles/系统管理员.md)，产品要求见[SPEC](../requirements/SPEC.md)。HTTP契约唯一维护在[API19](../api/接口设计.md#19-系统管理员完整工作区对接设计)，结构和一致性唯一维护在[数据库19](../database/数据库设计.md#19-系统治理配置与恢复记录设计)；实施验收见[PLAN](../planning/PLAN.md#系统管理员完整界面与后端设计交付)，实际进度只维护在[STATUS](../planning/STATUS.md)。

## 1. 目标、职责与设计取舍

管理员应能回答“谁有权做什么、服务把数据发到哪里、任务卡在哪里、变更影响什么、能否恢复”，并完成有回执、可解释、可撤销或可安全停止的操作。后台不以显示业务正文作为排障前提，不把账号开通、服务连通或备份文件存在当作业务可用。

| 事项 | 业务负责人/资料所属部门负责人 | 知识管理员 | 系统管理员 |
| --- | --- | --- | --- |
| 资料适用性、关键专业内容、单份文件等级 | 作真实判断并提供确认依据 | 核对、登记、维护及发布；关键项仍需专业确认 | 配置规则与权限，不作上述业务判断 |
| 新增业务权限或扩权 | 在系统外审批对象、资料范围、操作、文件维度和期限 | 按已获管理范围维护资料，不授予访问权 | 核实并登记实际审批，按完整授权组合配置；登记不等于审批 |
| 类别、等级、需求分类规则 | 确定业务含义和使用边界 | 按规则登记具体文件 | 配置已批准规则，不自行给具体文件定级 |
| 解析、索引和发布 | 确认业务有效性及必要专业内容 | 原文核验、修正、选用批次、发布撤回；整库索引须KM | 配置获准服务和运行条件，不借修复服务改变业务/核验/发布状态 |
| 服务、平台运维、恢复目标 | 企业有权责任人批准外发、费用、留存及恢复影响范围；实际负责人待落实 | 提供有权资料状态核对与必要业务验证 | 在平台运维授权内配置、监控、备份、演练；生产切换须获准且验证通过 |

同一人可明确兼任角色，仍保留每项职责、依据、资料范围及期限，不增加未经确认的强制双人审批。系统管理员若需查阅业务正文，应另有对应业务权限或有期限的排障访问授权；不能自批。排障授权也不自动给出计算、导出、分享或发布能力。

取舍：单纯参数页无法覆盖撤权和恢复影响；另建独立运维平台会重复授权与任务状态。建议复用现有FastAPI授权/任务/审计和Pi受控运行机制，增加受限管理投影与领域命令；这是本轮设计建议，不预设新微服务、通用脚本控制台或任意HTTP代理。

## 2. 导航与完整页面结构

建议六个主入口：“概览、账号与授权、服务配置、任务监控、审计记录、备份恢复”。账号处只切换已授权角色。概览默认展示需要处理的异常及其影响，所有数量都限于平台运维范围，不显示无权资料标题、员工问题或答案摘要。

| 页面/子视图 | 核心内容与动作 | 后端与恢复位置 |
| --- | --- | --- |
| S00 登录与身份恢复 | 平台账号登录、当前管理能力/范围、会话失效说明 | auth/me；首个管理员通过一次性部署初始化，网页不提供公开初始化开关 |
| S01 概览 | 服务可用性、失败/待核对任务、容量、最近备份及最近验证恢复；每项链接到具体处理页 | OperationsOverview；未知/过期数据显式显示，健康不等于资料获准外发 |
| S02 账号 | 创建、激活、重置、停用及会话撤销；账号归属、当前状态和影响 | API4用户接口及会话操作；创建默认disabled，不回显密码/token；离职不删除任务归属 |
| S03 角色任命 | 固定角色/能力目录、人员角色及批准范围/期限；变更前后对比 | 角色任命依据+API4；首期不开放自定义权限码或任意脚本规则 |
| S04 业务审批登记 | 实际审批人/时间/职责依据、申请对象、范围、操作、期限、附件/来源；系统登记信息独立显示 | 授权审批记录与依据核查；不是系统内业务审批页，不出现“以管理员身份批准” |
| S05 资料授权 | 按安全对象ID选择知识库/文档，配置完整组合、继承/限制模式，预检具体允许/拒绝及变更影响，撤销/到期 | API4授权+access-preview；没有DR时不读取文档标题或原文，业务审批Ref必须可用 |
| S06 规则与受理配置 | 已批准等级/类别/需求分类及操作规则；反馈受理/协调范围；规则版本、适用对象和变更影响 | GovernanceRuleSet及受理关系；不修改单份文件等级或反馈正文，未配置默认拒绝 |
| S07 服务配置列表/详情 | 生成、向量、解析、可选重排；供应商/本地端点、模型/解析版本、数据范围、凭据状态、预算及配置修订 | ServiceProfileView；区分未配置/草稿/启用/禁用、测试和准入；不把未选供应商预填成正式平台 |
| S08 服务测试与切换检查 | 合成样本测试、费用与数据范围、实际能力/错误；精确配置启用/停用、旧版回退资格 | TestRun/ConfigChangePreview；成功返回原配置详情，修改后旧测试不自动有效 |
| S09 任务监控列表/详情 | 业务任务、维护任务、Pi运行与工具调用的安全状态、阶段、耗时、错误、用量、回执；受控取消/核对/恢复 | OperationsTaskView；只读不推进任务；不打开原输入/日志正文，不改所有者或代员工确认 |
| S10 审计列表/详情 | 按操作者、时间、动作、资源安全ID和request_id追查；明确实际批准与登记、成功/失败/未决 | AuditView；白名单字段、分页；没有删除/改写审计入口，导出仅脱敏且另授权 |
| S11 备份策略/记录 | 已批准范围、位置策略、加密/密钥可用性、计划、最近结果及一致性清单；手动触发、核对失败 | BackupPolicy/BackupRun/Manifest；不提供企业备份包通用下载，未实测不标“可恢复” |
| S12 恢复计划/演练/切换 | 选快照、目标与截止点，隔离验证，重放撤权/删除，业务校验，影响确认后切换及恢复回执 | RestorePlan/Run；全过程持久化，失败保持隔离；生产切换和演练是不同动作 |

管理操作优先显示对象、当前状态、影响和下一动作，详细日志用受控链接进入。表格筛选/游标、任务位置及安全导航状态可恢复；未保存表单不得显示假保存。敏感表单不长期存浏览器，凭据不存入页面历史。首期电脑网页；视觉、高保真和真实浏览器操作未验证。

## 3. 六条端到端工作流程

### 3.1 账号与角色

首期平台账号由管理员建立，业务用户与登录身份分离；安全激活渠道需要部署时落实，未配置就显示未开通，不在响应中返回初始口令。激活/重置凭据、停用和撤销会话都有持久回执；重置不改历史任务所有者，停用不级联删除业务成果。

角色任命须有真实平台职责/业务授权依据及有效期，角色码不直接代表全部资源范围。角色级授权只有在批准的受益人/成员规则覆盖目标成员时生效，不能通过给自己加角色获得未批准资料。变更前显示新增和失去的能力及范围；最终按同一批准组合校验，不从多条不相干授权拼出新权利。停用/角色变更递增authz_revision，旧会话、在途调用及派生内容读取即时重查。

建议防止停用最后一个可用管理责任人而又没有已批准接管方案；恢复入口仍是受控部署流程，不增设公开万能账号。是否由同人兼任或安排多名管理员由企业决定。系统管理员账户自身也走相同批准与留痕规则。

### 3.2 资料授权与规则配置

1. S04登记系统外审批：实际审批人及职责、时间、依据、受益人、完整资料范围/操作/文件等级/类别/需求分类/期限；登记人与登记时间单列。附件可核验且真实覆盖范围后才可启用，字段填全不能替代依据核实。
2. S05使用最小对象ID/获准业务别名，检查审批、完整组合和现有继承规则。无DR不以授权管理为理由浏览文件名/原件。按文档授权不使整库标题可见；限制模式不再隐式继承整库范围。
3. 预检显示新增/撤销、过期、冲突、受影响会话/索引资格/缓存/分享及在途任务的安全影响。最终锁定目标及相关修订，校验审批和当前身份再原子写授权/模式/回执/审计/outbox。预检不授予权限，禁止force或通用permission=true字段。
4. 撤销、缩小和到期立即使当前门禁失效，不等待索引或异步缓存清理。授权扩大须新依据；已过期/撤销审批不可再次用于增权。历史成果保留但读取按当前权限，已合法离线下载的文件不能承诺追回。
5. S06配置业务已批准的规则版本；未知等级/映射、冲突、未启用场景默认拒绝。首期计算/报告/通用导出仍预留，显示“未启用”，不能因配置一个权限码就宣称具备工具能力。新规则不能无依据放宽旧文件；具体文件等级按知识管理员版本绑定确认，现行/历史均满足自身等级和现有文档约束。

反馈受理配置使用API17的FH/FR范围及全部资料依赖条件；配置者不因此读反馈或成为受理人。无来源/无合格接收人保持受保护待分派，系统管理员不能将其正文广播给全部管理员。受理、专业确认与权限审批的记录分别保存。

### 3.3 模型、解析与Pi运行服务配置

沿用BGE-M3向量和MinerU VLM解析方向，生成/重排与具体供应商尚未确定的部分保持未定。服务区分用途、供应商/本地地址、模型及可知修订、能力、版本化参数、凭据引用、网络目标、外发/留存/费用依据。配置可保存草稿，未满足准入不能启用；保存密钥只返回已配置/修订时间等元数据，不以明文读回。

连接测试默认使用获准的非敏感合成样本；测试调用也要检查网络目的地、凭据、费用和测试数据许可，不能为排障自动发送企业PDF或旧对话。真实样本另需逐服务许可。连接成功、能力检查和业务数据外发准入分开显示，测试结果绑定配置及策略修订/有效期，未知供应商版本不补造。

配置端点使用允许的协议、主机/网络范围和受控适配器；内网服务可在明确获准地址范围内使用，不能简单封禁全部内网，也不能接受任意URL抓取。DNS、重定向及解析结果下载地址按实际目的地再次校验；TLS异常保留原因，不通过关闭证书校验绕过。凭据仅由后端出口/适配器注入，Pi Runner不持供应商密钥。

启用/停用前比较精确配置与影响。正常变更新调用使用新修订，已接收调用保留原执行绑定并继续受当前准入/预算检查；禁用或许可撤销应阻断尚未发送的请求。已经外发的请求按远端回执核对，返回仍重验当前资格，不声称数据已经追回。不自动换供应商重发；备用服务也须独立获准，切换不得重置任务预算。

向量模型/预处理变更必须新建不混用的索引配置，由具备KM的知识管理员构建并启用；系统管理员配置服务不直接切业务索引。重新解析生成新批次，不能使旧核验自动通过。生成模型切换不改已交付答案。Pi SDK、工具/skills清单、隔离和运行镜像按受审部署版本管理，后台不开放任意插件上传、shell或修改20工具白名单的开关。

费用显示实际报告用量、供应商币种/价格依据、估算与结算差异；未知金额显示未知，不用cost_units冒充人民币或计零。日志不含密钥、完整提示词、文档片段、向量或带凭据链接。配额、自动重试次数/时限来自明确策略，不无限循环或遇错自动换服务。

### 3.4 任务监控与受控操作

S09默认看状态/阶段/错误分类、运行环境/配置修订、队列等待和安全回执；“查询不到资料”“权限不足”“解析待核验”“服务异常”分别显示，不能为消除红色告警把任务改成成功。没有业务读取权限时不含员工输入、文件名、条件、答案、公式值、原始Pi消息或模型payload。

operations.read仅监控。取消、核对和恢复建议另设operations.control及平台运维范围、理由、原任务修订；服务端只允许真实可恢复动作，不提供任意重跑函数或状态PATCH。恢复按原owner/冻结操作范围、当前授权、确认、预算和副作用回执执行，不能以管理员身份代跑、代员工答复T17、代确认表格写入或代T14/T16验收。

结果不明先核对原幂等回执、tool_call_id/model_call_id和远端任务，已完成步骤不重复。取消是请求与最终回执分离；已提交外部调用/已生效文件操作不因取消自动回滚，显示部分结果及未决影响。原任务无合法执行授权时只允许安全停止，不以“修复”恢复过期许可。长任务GET只读，刷新网页不推进执行。

### 3.5 审计与排障

审计记录实际身份、动作、对象安全ID、请求/任务/配置修订、依据Ref、结果与时间；实际业务审批人和登记人分开。详情按动作白名单显示安全前后差异，避免将自由reason/metadata原样序列化。无权文档名、反馈说明、输入及答案、凭据、Pi日志都不是系统审计默认字段。

普通操作用户不能改写或删除审计。必要留存、脱敏与永久清理使用受控生命周期，不能以不可变为由保留本该清除的业务正文副本。导出审计需独立audit.export及脱敏范围，不是企业数据通用导出。诊断包也须固定安全字段，禁止打包数据库/SDK完整历史给排障人员。

若确需正文排障，另走有权业务人员在系统外批准的限资料/任务/用途/期限授权；接口继续执行资料、任务所有权/有效分享等原门禁，不能仅添加document.read就通读他人任务。不增设绕过TR的“管理员查看全部”。只需复现的情况优先由获准人员提供非敏感样本；实际企业需要的委托查看机制若超出已有TR，须另行明确，不能在本轮默开。

### 3.6 备份、隔离恢复与生产切换

备份策略待企业确定RPO/RTO、频率、保留期、存放位置、加密/密钥托管、责任人和恢复窗口；本文不给出虚构数值。未配置必需策略时显示缺项，不假装已自动备份。用户要求设计不构成执行生产恢复或永久清理授权。

备份必须覆盖同一可证明一致性边界的数据库和所引用原件、解析包、成果、证据及必要内部Pi记录/依赖；索引可选择备份或重建但须记录配置。清单保存快照截止点、schema/运行版本、对象身份/哈希、加密及恢复依赖；凭据正文不随普通数据库导出，密钥恢复使用单独受控保管。已保存、完整性通过、隔离恢复通过和业务可用是不同状态。

备份任务使用服务端受控存储profile及服务身份传输加密对象；系统管理员只查看安全清单和结果，不通过备份下载/原始对象路径获得企业正文。目标选择不能任意指定本机路径、URL或把数据迁出获准范围。只有明确backup.manage/restore.execute等运维授权才可触发相应动作，operations.read不包含这些写能力。

用户2026-11-17已确认生产恢复遵循以下流程；确认范围是设计，具体切换授权和恢复目标仍待企业落实：

```mermaid
flowchart LR
  A[选择快照与恢复目标] --> B[隔离恢复并关闭外发与执行]
  B --> C[完整性与依赖验证]
  C --> D[追平当前撤权 删除 停用记录]
  D --> E[安全门禁与业务验证]
  E --> F[获准人员确认切换影响]
  F --> G[切换与健康核对]
```

恢复环境默认关闭出站、Worker/outbox派发、共享下载和Pi执行，不加载旧会话令牌、供应商密钥或开放下载地址；恢复不重放旧工具命令和付费外发。引用/对象缺失或哈希不一致则隔离失败，不能以“数据库已还原”报告完成。

恢复还要核对快照之后的已受理提交/逻辑动作、HTTP/工具/供应商回执、费用预留/实际用量、失败次数及已写入产物。它们须有独立于旧快照的持久账本或可信外部对账来源，不以普通审计文字代替；先保存执行许可/身份再产生副作用，缺账本就停止相关执行。无法证明结果的动作保持待核对并封锁其任务/项目/目标版本，不允许换幂等键、换owner或从旧pending重新做；无法界定影响范围时不开放执行。预算/失败记录按真实调用身份合并，不能回到旧余额或重复累计。该核对是恢复验证门禁，不是切换后再补的排障。

必须从独立于被恢复快照的现行治理记录取得删除、撤权、账户停用及服务许可撤销的完整截止点，先追平并验证，再开放读取。没有这份可用记录或无法证明追平时不得切生产，也不能回退到旧授权。重建会话/权限修订和缓存命名空间，旧分享和下载凭证重新验证；恢复索引仍按当前资料资格过滤。内部Pi分支、摘要和私有快照同样应用来源失效/清理，不把备份历史当成永久授权。

生产切换采用停写/停派发及明确截止点，处理隔离验证期间的新资料、权限与删除变更；最终验证绑定目标、快照、治理截止点、环境修订和切换审批。任一变化使预检失效时重新验证。失败继续隔离，保护现有生产；切换后若已有新写入，不允许简单指回旧库而丢数据或复活旧权限，须重新规划恢复/回退。实际耗时与恢复点经演练记录，不在文档中声称满足未定RPO/RTO。

## 4. 状态、并发与恢复共性

| 对象 | 必须分开的状态 | 页面与服务端规则 |
| --- | --- | --- |
| 账号/角色 | 用户active与身份可登录、角色任命、实际业务范围 | 任一不满足不放行，角色叠加不拼接授权；变更失效旧会话 |
| 审批/授权 | 外部决定、依据核查、系统配置、当前有效性 | 记录不等于approved；到期/撤销/冲突即时生效，预检不能永久授予权限 |
| 服务 | 草稿/启用、测试结果、逐服务准入、实时健康/预算 | 连通不等于可发企业数据；配置/许可改变重验，不沿用过期测试 |
| 任务 | 已受理、真实执行、待输入/外部等待、部分完成、结果不明、终态 | 原回执恢复，不盲目重发；取消请求不伪报已取消或自动回滚 |
| 备份/恢复 | 已保存、清单验证、隔离恢复、安全追平、业务校验、切换完成 | 无证据不升级，生产切换需独立资格及当前截止点，失败保留安全状态 |

所有写入沿用会话/CSRF、Idempotency-Key、必要If-Match与事务内权限重验；身份来自服务端。预检显示影响但不发权限，最终提交用最新资源/策略修订。并发冲突保留用户输入后重读；请求结果未知先核对回执。操作白名单由allowed_actions返回，隐藏按钮不代替后端拒绝。

## 6. 四层记忆、Pi与四类工作链路

| 层 | 运维侧读取/更新 | 失效与恢复边界 |
| --- | --- | --- |
| L1 本轮上下文 | OperationsMemoryView仅含当前平台范围、资源安全ID、配置/任务状态及诊断引用，按用途组装 | 不包含员工条件/正文；权限、配置、治理epoch变化重新组装 |
| L2 对话条件 | 纯系统页面不创建或修改员工条件；表单/过滤器属于管理资源或导航状态 | 恢复不把旧摘要或旧确认写成当前条件；来源派生项按原机制待复核，用户明确值不擅改 |
| L3 执行记忆 | 管理动作回执、测试/备份/恢复任务、员工任务的安全状态投影；Pi运行只作执行映射 | 原owner/计划/预算/幂等继续权威；旧Worker租约/会话/SDK命令不直接回放 |
| L4 成果与证据 | 配置与批准历史、安全审计、备份清单/演练和恢复证据；员工成果仍归原业务记录 | 备份加密保管不授予读取权；撤权/删除同步作用于SDK日志、摘要、条件、证据和成果，历史不成为旁路副本 |

Pi主/辅助模型都经API18私有出口，以API19的当前已启用服务修订、逐服务准入、预算和来源许可判定；Runner不获得密钥或全局管理工具。更改服务/权限使旧许可失效或要求重新签发，不在旧payload中隐藏失效片段后继续发送。服务恢复和备份恢复不重置任务attempt、总预算或失败记录。

| 工作链路 | 管理侧保障 | 配置/权限变化时的动作 |
| --- | --- | --- |
| 资料查询 | 正式检索/生成服务准入，当前授权和选用索引兼容 | 新请求重验；历史回答保留原版本但按当前read/use展示，无合格来源说明原因 |
| 数值计算 | 独立操作授权、执行器版本、公式/常量来源依赖 | 在准备/执行/交付门禁暂停受影响项，不以换模型猜数或替代专业确认 |
| 表格修改 | 文件范围、已确认计划、确定性写入/重算回执 | 不盲目重做已生效步骤；恢复检查原文件/副本/计划及调用结果，独立项可部分交付 |
| 报告生成 | 资料/模板/数值依赖、生成模型许可和成果权限 | 不自动换供应商或重写历史报告；服务返回和交付均重查当前许可 |

以上沿用四层产品记忆，没有第五层系统管理员全局业务记忆；个人偏好仍后置。开发doc/memory仅为开发助手线索，不是产品配置或恢复控制平面。

## 7. 已有基础、待开发与确认边界

当前有本地账号、角色、授权和运维记录端点，以及只展示provider状态的React组件边界；不是完整后台。服务配置修订/密钥和逐服务准入、角色任命与外部审批登记、受控运维命令、审计白名单、真实备份恢复和本方案投影均需开发或集成。源码中的管理员approve动作、任意审计metadata返回和人工填写演练result不能当作上述能力已验收，具体差距登记STATUS，不在本轮修代码。

本轮设计的结构/契约一致性可检查；实际三角色网页、逐服务调用、越权/在途撤权及备份恢复按PLAN SA-01–14验证，目前未运行。首期FR/T编号、工具实现状态及历史失败不因设计完成改变。
