# Harness Memory 模块设计

日期：2026-11-15  
状态：已实现（方案经确认，结构校验已通过）

## 意图

让一个没有历史对话的新 Agent，能够从仓库中的持久化材料低成本恢复项目目标、长期约束、重要决策和当前工作状态，并在旧信息与当前权威来源冲突时安全地停下来核对。

Memory 是上下文恢复层，不是聊天记录、规范替代品或知识库。它服务于当前项目的真实工程任务，优先复用 Git 和现有 `doc/` 文档。

## 目标与非目标

目标：

- 在 `AGENTS.md` 中提供简短、可执行的启动、使用和沉淀入口。
- 以 `context.md`、`decisions.md`、`state.md` 保存最小且可追溯的长期认知、决策演进和恢复状态。
- 明确事实、决策、假设、待验证和阻塞状态，保留来源和适用范围。
- 用一个无外部依赖的确定性校验脚本检查结构、来源和失效标记。
- 用受控场景记录冷启动、冲突处理、更新准确性和最小读取成本的证据。

非目标：

- 不建立数据库、向量索引、后台服务或会话全文归档。
- 不复制 SPEC、PLAN、ADR、测试日志或完整代码说明。
- 不自动授予执行权限，不把 Memory 当作高权威规范。
- 不声称通过真实独立 Agent 会话，除非确实启动并观察到独立会话。

## 方案比较与选择

### 方案 1：Markdown + 轻量校验脚本（选定）

在 `doc/memory/` 保存三个逻辑文件，根 `AGENTS.md` 只保留入口规则；脚本按需检查必需标题、来源链接、状态枚举、决策状态和失效/取代标记。它与现有 Git 和文档治理兼容，双写面少，失败时可人工阅读和修订。

### 方案 2：Markdown + 结构化索引

在三个文件之外维护 YAML/JSON 索引和标签筛选。它能进一步减少读取量，但引入索引同步、冲突和额外维护成本；当前仓库规模和任务数量尚不足以证明收益。

### 方案 3：独立 Memory 服务/数据库

提供查询、版本和冲突 API。它适用于多项目共享和大规模自动化，但会引入第二套状态、权限和运维边界，与当前尚未实现的应用和本任务的轻量目标不匹配。

## 设计

目录结构：

```text
doc/memory/
├── README.md       # 入口、读取顺序、字段约定和更新规则
├── context.md      # 稳定的项目为什么与长期原则
├── decisions.md    # 重要决策的当前状态、原因、取舍、来源和失效条件
└── state.md        # 当前可恢复工作状态及验证范围
```

`AGENTS.md` 增加以下行为：新会话先读适用的 `AGENTS.md`，再读 `doc/memory/README.md`、`context.md` 和 `state.md`；只有任务相关时才读 `decisions.md`、SPEC、PLAN、ADR 和代码；所有影响当前任务的 Memory 必须回溯权威来源和当前仓库状态；冲突或过期信息标为不确定并以有效来源为准；结束时仅在长期约束、重要决策或经过核实的状态确实变化时更新，并保留来源。

字段约定：

- `context.md`：项目定位、核心用户体验、长期原则；每项说明为什么值得跨会话保留，并链接当前依据。
- `decisions.md`：每项包含 `状态`（当前/被取代/待复评）、`决策`、`原因与取舍`、`拒绝的替代方案`、`依据`、`失效或复评条件`。被取代项保留历史因果，不静默改写。
- `state.md`：按 `已实现`、`已验证`、`未验证`、`阻塞` 分组；每项记录观察依据、有效范围和日期。状态快照不表示永久事实。
- 来源优先链接到 `SPEC.md`、`PLAN.md`、ADR、代码路径、Git 提交或验证记录；没有来源的结论只能写为假设或待验证。

校验脚本：`python -m src.memory.validate`。它只做确定性检查：文件存在、必需标题存在、决策状态合法、状态条目含依据和日期、Markdown 链接目标存在（外部 URL 不做网络验证），并以非零退出码报告错误。该命令通过既有 `verify.py --task harness-memory` 契约复用 SPEC、PLAN、AGENTS 和设计来源。脚本不判断语义正确性，也不把通过结构检查等同于业务验收。

## 运行闭环

1. **恢复**：读取最小入口，定位当前任务；按范围扩展读取；核对来源、Git 状态和当前文档；冲突时保留不确定性。
2. **使用**：把 Memory 当作线索；SPEC、PLAN、ADR 和实际代码优先；不扩大范围或权限。
3. **沉淀**：仅记录实际变化且会影响后续会话的信息；更新前保留来源、适用范围和状态，不覆盖其他会话的新变化。

## 验收

- 冷启动：只读持久化材料，能够恢复本项目定位、首期范围、权威边界和当前未实现状态。
- 冲突处理：将故意过期的 Memory 与当前 `README.md`/SPEC 对照，校验脚本允许标记取代，示例流程要求采用当前来源。
- 更新准确性：未验证结果只能进入 `未验证` 或 `阻塞`，不能进入 `已验证`。
- 最小开销：普通任务只读取入口、context、state 及任务相关决策；不扫描整个仓库或生成会话总结。

交付材料包含一次完整示例和验证记录，并明确独立跨会话未实际启动时的限制。
