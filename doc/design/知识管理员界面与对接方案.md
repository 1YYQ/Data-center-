# 知识管理员完整界面与后端对接方案

日期：2026-11-17。交付范围：资料上传、解析核验、版本管理、发布撤回、员工反馈，以及20项工具和四层产品记忆的衔接。本文为供逐项讨论的完整功能结构稿；已有用户确认的职责沿用，新增导航、状态标签和操作细节为 proposed，未获视觉批准，不代表页面、接口或业务流程已经实现。本轮不写代码、不处理真实企业资料、不调用外部服务。

职责依据见 [知识管理员](../roles/知识管理员.md)，产品范围见 [SPEC](../requirements/SPEC.md)。字段与端点分别集中在 [数据库17](../database/数据库设计.md#17-知识管理员维护记录与一致性设计)、[API17](../api/接口设计.md#17-知识管理员完整工作区对接设计)；进度只维护在 [STATUS](../planning/STATUS.md)。

## 1. 工作目标与责任边界

管理员应能判断一份资料“来自哪里、适用于谁、识别是否可信、由谁确认、员工现在能否使用”，并知道下一步由谁处理。系统以具体资料、版本和待办为工作单位，不要求每次维护先开启对话。

| 事项 | 业务负责人或具备职责的专业人员 | 知识管理员 | 系统管理员及授权服务 |
| --- | --- | --- | --- |
| 适用设备、条件、生效版本及新旧共用 | 作出真实业务判断，提供可核验依据 | 登记实际结果、核对依据与版本，不按上传先后推断有效性 | 配置身份及权限，不代作业务判断 |
| OCR、表格、公式、警告及步骤 | 对影响业务的关键内容作专业确认 | 对照原文核验、提出修正、留存核验依据；关键项确认缺失时保持待核验 | 配置解析服务及数据外发边界，不替代专业核验 |
| 文件等级、类别规则 | 确定等级及类别规则；等级调整提供真实确认 | 登记等级依据、选择已配置类别，不授予访问权 | 按已批准规则配置类别、授权、允许操作及期限 |
| 发布、撤回、索引 | 提供适用性及停用判断依据 | 在管理范围内执行发布/撤回；满足整库管理条件者才可启用整库索引 | 执行强制门禁；服务配置权限不自动包含业务正文或发布权 |
| 员工反馈 | 必要时判断专业问题、补充确认 | 在配置的受理范围内处理、答复并关联真实资料变更 | 配置受理关系；没有业务权限时只处理安全元数据 |

首期业务确认在系统外完成，系统内分别保存实际确认人/时间与登记人/时间；“登记”按钮不叫“替业务审批”。同一自然人可经明确授权兼任职责，不额外规定必须两人审批；兼任也不能省略真实依据和各项记录。模型辅助摘要、差异定位及检查，不能产生业务确认、专业核验结论、授权或自动发布。

## 2. 导航与完整页面结构

建议主入口为“资料、处理任务、员工反馈”。默认进入本人管理范围的资料列表，可按待处理原因筛选；不显示全企业资料总数。账号处切换已获授权角色，不能通过切换角色扩大资料范围。

| 页面/子视图 | 主要内容和操作 | 后端连接与返回位置 |
| --- | --- | --- |
| K00 身份与工作区恢复 | 登录、恢复当前角色及管理范围；无范围给出申请入口说明 | 沿用 auth/me；所有管理页重新鉴权，不缓存永久角色结论 |
| K01 资料列表 | 文件名/型号/版本搜索，知识库与类别筛选；显示待确认、待核验、待索引等实际原因；进入详情、上传 | ManagementDocumentPage；列表不暴露未分配资料、重复文件或其统计 |
| K02 上传与登记 | 选目标知识库或已有文档、上传PDF、登记来源/型号/原始版本；明确新资料或已有资料的新修订 | 沿用API5上传；每个文件独立回执，成功进入该版本详情；不把201当解析完成 |
| K03 资料及版本详情 | 原件、来源、型号/适用范围、版本关系、五类状态、确认依据、处理记录、当前访问范围摘要 | ManagementVersionView；进入K05/K06/K07/K08；访问范围只读，无“增加可见人员”操作 |
| K04 处理任务列表/详情 | 本人有权维护的上传回执、解析、校正、索引任务；当前阶段、失败原因、下一动作、持久回执 | MaintenanceTaskPage/View；可离开后恢复；索引详情仅KM可见，不显示员工办公任务 |
| K05 解析核验工作区 | 左侧原PDF，右侧对应内容块；按真实页序/章节定位，筛选待核验、表格、公式和警告；修正、退回、提交核验记录、选择已核验批次 | API6及review-set；保留PDF阅读位置与筛选；管理核验需要原文对照，不套用员工仅证据链接的阅读布局 |
| K06 业务确认登记 | 分别登记适用性、关键内容专业确认、文件等级依据；显示实际确认与系统登记两组身份时间 | 版本绑定的确认附件/来源与business-confirmations；缺依据保持待确认，不提供系统内业务审批流 |
| K07 版本/解析批次对比 | 新旧版本原件、来源、适用范围、状态及内容差异；同一版本不同解析批次的校正变化 | 管理视图+compare；差异提示不能裁定哪个版本有效；回到原版本/核验位置 |
| K08 发布/撤回检查与回执 | 显示阻断项、旧版变化、当前查询影响、索引状态；确认本次操作后查看真实结果及下一动作 | publication-preview、API5发布/撤回、API7索引；不设置强制发布/自动回退按钮 |
| K09 员工反馈队列 | 待分派、待处理、处理中、已答复；仅列已配置可受理对象；领取或移交给合格受理人 | API13.4/17；状态及分派修订防止重复受理，不开放全员工问题库 |
| K10 反馈详情 | 员工明确提交的说明、必要定位、处理进度、对员工答复、关联维护版本和实际更新状态 | FeedbackHandlingView；只进入有权原文，不进入员工完整对话；返回队列保留筛选位置 |

K03集中呈现状态摘要和可执行的下一步，其余细节按链接进入；资料原文、确认附件、审计记录分别鉴权。列表无需把所有状态铺成多个统计卡；K05的双栏用于核验任务，其他页面以当前待办和实际结果为主。电脑网页端为首期范围；高保真、布局尺寸和浏览器验证后续处理。

## 3. 统一状态与界面动作

以下为独立状态轴。页面可派生“暂不能正式使用”等摘要，但不保存另一个可独立修改的“已就绪”布尔值。

| 状态轴 | 页面必须说明 | 允许的下一步和限制 |
| --- | --- | --- |
| 文件接收 | 上传中、已保存或失败；来源/文件身份是否完整 | 重查回执后恢复，未知结果不得换键重复上传；保存成功不触发自动发布 |
| 业务适用性 | 待确认、已确认、有冲突或业务已停用；依据及适用范围 | 登记/替代真实确认；冲突未消解不能形成正式依据 |
| 内容核验 | 未核验、待核验、已核验或退回；涉及的精确解析批次 | 修正或补专业确认；解析成功不等于内容核验通过 |
| 发布 | 草稿、已发布、历史版或已撤回；当前版本指针 | 发布通过事务改变现行关系；撤回不修改原业务确认事实 |
| 草稿原件参考 | 默认关闭或已开放仅供参考；精确版本及操作原因 | K03可由DM显式开放/关闭；有当前DR的员工才能人工看原件，开放不满足正式发布/检索/计算门槛 |
| 检索就绪 | 无解析、无选用切分、待建索引、索引过期或可查询 | 指明阻断原因；业务已发布但索引未就绪不能冒充正式可查询 |
| 当前权限/任务 | 本人可做什么、是否失权、外部服务是否获准、任务是否仍在运行 | 后端返回allowed_actions及原因，点击时重验；不返回无权内容后再靠前端隐藏 |

正式查询/计算还要按当前用途逐次检查型号、条件、版本、块核验、索引和权限。历史原文能否查阅与能否作为新的正式依据分开；已撤回/历史结果遵循既有历史读取规则及当前权限，不因保留记录而恢复正式资格。

## 4. 五条端到端工作流程

### 4.1 上传与资料身份登记

1. 管理员进入获分配知识库，或从已有文档选择“新增修订”；服务端校验DM及文件限额，PDF、原件哈希和文件状态按既有上传契约处理。
2. 登记实际来源、设备型号、版本标记；未知信息显式留待确认。同名、相同哈希只在当前有权范围提示，既不自动合并资料，也不继承另一文件的权限或业务确认。
3. 每个文件显示独立保存回执和下一步。页面离开或请求超时，先查询原幂等回执；部分成功保留成功项，不显示整个批次完成。
4. 类别使用业务确定、系统配置的选项。文件等级须有真实确认；未知不默认开放。新文档沿用已批准授权规则，不允许上传请求写ACL；需要调整访问范围时由授权流程处理，不能把每次上传都变成额外人工授权审批。
5. 只有隔离区文件核验并可用后才能解析；外部解析还须逐服务检查资料外发、账号、费用、留存和服务可用性，未获准时说明缺项并保留已保存原件。

K03另提供“开放原文参考/关闭原文参考”，沿API17.6的DM、精确版本、原件可用、等级/访问条件和并发检查执行并留审计。用户2026-11-17已确认该规则：未开放草稿仍管理隔离，开放仅供当前有DR的员工人工参考。它不登记业务确认、不设置approved、不启用索引、不授予新ACL；关闭后旧链接/派生页立即重查状态。K03显示参考状态，K08正式发布门槛不变。

### 4.2 解析、人工核验与校正

1. 显式发起解析并返回持久任务；显示提交、外部等待、归一化、完成/待核验/失败等真实阶段，不编造百分比。提交结果未知时先核对已保存远端任务ID，不重复外发。
2. K05按原PDF真实位置核对文本、图注、表头与单元格关系、公式/变量/单位、脚注和警告；坐标或印刷页码缺失时说明，不能伪造定位。图示无法表达、结构缺块等问题保留待核验。
3. 修正只作用于选中块的允许字段，生成有parent_run_id的新manual批次，保留原批次与原件。表格/公式以结构数据为准重新生成文字；不允许上传执行代码或修改原件定位。增删布局块、跨页重排未设计，不承诺在线支持。
4. 改动块及受影响的变量、表头、脚注关系重新核验；只有内容、定位和关联完全相同的项目才可保留原核验引用。公式、单位、关键步骤或警告还须绑定对应专业确认，运行一次计算不能替代此确认。
5. 核验集绑定确定的解析批次、块与ready切分集合；检查所需覆盖和关键限制后形成核验记录，再选择该集合。不能只改content_review_status，也不能默认选择“最新解析”代替已核验批次。
6. 若已用于正式服务的块被退回或选用集合改变，立即阻断受影响的正式使用并使相关索引/缓存过期；历史证据保留，不能等索引重建才停止使用。重新解析不自动替换在用内容。

### 4.3 版本与业务确认管理

原件、版本适用条件变更创建新版本；标题/类别维护不改历史任务采用的快照。K07显示系统修订序号与真实版本标记，上传时间不充当业务生效日。

K06保存实际确认人、职责/权威依据、确认时间、适用范围、结论和附件或可追溯来源，同时保存登记人、登记时间及依据核查结果。字段填写完整不等于依据可核实；无法核实、无权确认或范围不匹配的记录保持pending，不满足门禁。确认来源中的指令及外链不执行、不自动抓取。

适用性确认绑定原件和适用范围；关键内容确认还绑定解析内容/定义及定位；等级依据不写授权表。修正错误登记时新增替代记录，旧记录保留，不回改实际确认人或时间。新证据与旧证据冲突先进入保护性暂停，交具备职责人员消解；管理员不得自行选一份“看起来更新”的依据。

当前单文档current_version_id只支持一个现行修订。确有按设备/条件并行适用的版本时，必须先明确无冲突的资料组织和适用范围；不能用第二次发布覆盖其中一组，也不能声称已有多现行版本能力。该边界需要业务样本验证。

### 4.4 发布、索引与撤回

用户2026-11-17已确认发布门禁为：原件可用、适用性依据已核实、精确选用批次与内容核验通过、关键专业确认齐全、等级/类别及访问规则满足、无冲突或保护性暂停。此项取代旧文档“发布与解析完成独立”的宽泛描述，已获用户明确确认；发布与索引启用仍分开，不能提前开放正式查询。

发布前K08显示本次版本、将被转历史的现行版、是否产生索引等待期和可执行下一步。预检不是授权凭证；最终请求在锁定事务内重查确认/核验/权限/修订，改变了就返回冲突和新的阻断项。发布不自动启用未完成索引，不允许force_publish。

建议常规顺序为保存→解析核验/业务确认→发布→构建并启用索引；业务确认可先登记。具备KM者维护整库索引；仅有单份DM者看到本份资料“待索引”并交给已配置的整库维护人，不能获得全库来源或索引启用权。没有可用配置/维护人时保留真实未就绪状态。索引失败不自动回滚业务现行版本，也不偷用已转历史的旧版做新查询；可能存在查询空档，预检必须说明。

撤回需明确原因，作用于精确版本；立即移除其正式资格、更新当前指针/修订和失效事件。撤回发布不等于业务人员已经确认该手册失效；真正业务停用另登记其依据。未确认的重大风险可在DM范围内设置保护性暂停，不能伪造业务停用事实。历史版不自动复活；需要重新采用旧内容时建立可追踪的新修订，重新核验确认和发布，不提供一键隐藏回退。

撤回/暂停后旧回答不被新内容覆盖，按当前权限与历史规则显示原快照和失效提示；正在进行的查询、计算、表格、报告在正式提交或交付前重查所用来源，受影响项目暂停，其他独立项目按部分交付规则处理。撤回、撤权不能保证追回已合法下载的离线文件。

### 4.5 员工反馈受理、答复与更新

1. 员工从原对话/手册提交；管理员只获得明确提交的问题与必要定位，不获得对话/任务通读权。受理名单依据配置的处理范围、能力和所有附带资料依赖交集确定，不能群发全部知识管理员。
2. 没有归属或合格接收者时保持受保护的待分派。具备明确feedback.route范围的协调人员只能按其权限分派，系统管理员可配置关系但不因配置权读取正文。安全路由元数据不能含无权文件名/问题摘要；无法判断归属时回执说明待补归属或待配置，不要求员工查询前先选部门。
3. K09领取/移交使用修订条件，防止两人覆盖。新受理人必须满足范围及全部资料读取条件；移交不是权限授予。失权立即停止读取正文，已提交的处理记录保留受控历史。
4. K10可登记处理进度、形成对员工的答复，并关联有权维护的版本/解析任务。对外答复不得粘贴员工无权内容；发布给提交者前检查其当前依赖权限，无权部分阻断或只返回安全状态，不能仅隐藏来源链接而保留正文。处理记录与员工可见答复分开，不把内部确认附件默认发送给员工。
5. “已答复”仅表示已提供答复，不等于资料已改好、业务已确认或员工已认可解决。需要修改资料时走上述独立流程；接收反馈、填写回复或选择关联版本不直接调用确认/核验/发布。
6. 员工原入口展示真实进度、答复及关联版本状态。资料实际满足正式使用门禁后才出现可重新查询的更新提示；未发布/未核验/待索引只显示相应状态，不能宣称可正式使用。由员工主动重查，旧回答的条件/版本/出处保持不变。员工补充、关闭、时限及站外通知后续确认，不擅自发送邮件/群消息。

## 5. 页面与后端服务的连接

读接口返回当前授权过滤后的页面投影，写接口执行独立领域动作；前端不能提交computed_status、权限或“已确认=true”绕过领域规则。端点/字段唯一维护在API17，表和约束唯一维护在数据库17。

| 页面动作 | 服务/已有契约 | 关键依赖和结果 |
| --- | --- | --- |
| 查资料、看详情、访问范围摘要 | 管理投影+API5 | DM范围；版本与资料归属验证，分类可编辑而ACL只读 |
| 保存原件/新增版本 | API5、文件隔离与幂等回执 | 原件可用才提交版本；失败可核对原请求，不覆盖旧版 |
| 解析、校正、块复核、选用集合 | API6、维护任务、核验集 | 精确run/chunk/block/proof；记录与选择分开，门禁可复算 |
| 登记确认附件/实际结果/核查结论 | confirmation-evidence及business-confirmations | DM；精确版本/原件/关键块依赖；不写授权审批或员工条件确认 |
| 对比、暂停、发布/撤回预检和执行 | compare、holds、publication-preview及API5 | Document/Version ETag、依赖修订、锁、回执、失效outbox |
| 索引处理 | API7 | KM、可用服务配置、完整来源清单；DM只能看自身就绪原因 |
| 反馈领取、路由、处理和答复 | API13.4/17 | feedback.handle/route范围、全部依赖权限、修订、员工可见答复校验 |
| 任务恢复 | 管理task投影+既有任务运行机制 | 长任务真实状态、远端ID、检查点；取消是否成功以服务回执为准 |

跨页面保留resource_id、version_id、run_id、筛选和阅读位置等导航上下文；敏感未提交表单不长期存浏览器，离开提示先保存服务端草稿或放弃，后端未提供草稿能力时不得展示假保存。写冲突保留用户输入并要求重读差异；失权先清受限内容，不以旧ETag/浏览器缓存继续操作。

## 6. 与20项工具的完整映射

20项是员工办公工具目录，数量不变。资料维护、确认登记、授权和发布是受控治理服务，不新增为默认Agent工具。复用内部适配器不等于扩大现有工具的输入作用域。

| 工具 | 知识管理员的连接方式与限制 |
| --- | --- |
| T01 context.read | 员工工具仍要求其对话/任务作用域；管理页读独立MaintenanceMemoryView，不能读取员工对话或将conversation_id改可选来混用 |
| T02 files.inspect | 可复用文件类型/内容检查；原件与确认附件走DM维护上传，不伪装成员工conversation输入文件 |
| T03 sources.search | 可复用目录检索适配器；草稿由管理投影按DM返回，不放宽普通工具的资料资格 |
| T04 evidence.search | 普通正式检索门禁不变；核验草稿读管理块接口，不把草稿预览包装成正式问答证据 |
| T05 sources.read | 可复用定位/文件流机制；管理原件按DM，普通读取仍按DR/版本规则；确认附件独立保护 |
| T06 workbooks.read | 仅管理员明确兼有员工能力且在本人办公任务内使用；核验表格内容不等于获得员工工作簿访问权 |
| T07 documents.read | 同样受本人办公任务权限限制；管理PDF核验走维护服务，不读取他人任务附件 |
| T08 calculations.prepare | 可在获准办公任务准备计算；不能代替公式、单位等专业确认 |
| T09 calculations.run | 正式计算仍确定性且来源合格；不得执行解析文字/模型代码或以试算作为核验通过 |
| T10 workbooks.plan_changes | 仅本人获准的表格任务；资料管理员角色不自动有单元格修改能力 |
| T11 workbooks.apply_changes | 只修改已确认计划的任务副本，不写知识库原件或员工原文件 |
| T12 workbooks.recalculate | 与获准表格任务及执行版本绑定；不产生手册有效性结论 |
| T13 documents.compose | 获准办公任务可生成报告草稿；生成物不自动进入知识库或发布 |
| T14 artifacts.validate | 可复用技术校验组件；产物校验结果不等于业务适用/专业内容确认 |
| T15 artifacts.preview | 本人获准产物预览；管理解析产物采用DM文件端点，不开放通用file_id下载 |
| T16 artifacts.deliver | 办公交付按员工能力执行；维护回执不是员工成果交付，原件或确认附件不自动对外发放 |
| T17 tasks.request_input | 只补员工任务输入/覆盖确认；不能登记实际业务确认或提升版本资格 |
| T18 tasks.control | 复用持久任务/取消恢复底座；管理投影限制维护任务和资料范围，不获得员工任务或全库索引权限 |
| T19 answers.share | 仍只分享有权单条回答；不能用它转发草稿、确认附件、反馈或整个对话 |
| T20 feedback.track | 员工提交/回访沿用；管理领取、分派、回复用独立受理契约，不给员工工具新增管理员写权限 |

管理资料状态的变化影响四类员工链路：查询重验说明证据；计算重验公式/常量/单位；表格修改重验来源、计划和计算绑定；报告重验每一节/表的数据依据。对不再合格的来源停止新的正式使用，已冻结结果留存并标注当前状态；不会通过重新检索自动改写旧成果。

## 7. 与四层产品记忆的衔接

四层责任沿用 [架构7](../architecture/前后端技术方案.md#7-四层产品记忆设计)，个人偏好仍后置；不是再建四套管理员数据库。管理页面与员工对话具有不同作用域，API16原MemoryBundle契约不被暗中改为通用企业记忆。

| 层 | 管理侧读写与边界 | 更新和失效 |
| --- | --- | --- |
| L1 本轮上下文 | 维护请求按身份、DM/KM、purpose=maintenance及明确resource_refs组装最小MaintenanceMemoryView；含当前版本、选中批次、待办和必要证据引用，非整库/员工对话摘要 | 请求结束可丢弃；资源/授权/索引修订变化立即重组，不能把旧页面状态当当前资格 |
| L2 对话条件 | 纯管理页面不创建员工条件记忆；选择版本、编辑登记表单属于资源/表单状态。管理员另以员工身份使用自己的对话时才沿用其L2，且受原作用域限制 | 页面选择不等于业务确认；登记外部确认不写员工“已确认设备/参数”，不回填他人对话；无新增管理聊天需求 |
| L3 执行记忆 | 解析、校正和索引复用持久任务、步骤、远端ID、检查点、幂等回执；维护读取需当前资料范围，索引需KM | 恢复重查身份/依赖/服务许可；不明外部效果先核对，禁止重复外发；反馈、发布等短事务保留独立回执而非强造长任务 |
| L4 成果与证据 | 原件、解析批次、核验记录、确认依据、发布撤回回执及反馈答复按各自业务记录和权限保存；员工结果继续保留采用的旧条件/版本/出处 | 追加历史而非原位改写；当前资格由权限及资源状态派生。确认附件仅有DM等指定权限者可读，员工引用不自动包含它 |

发布/撤回、暂停、退回核验、变更选用批次、撤权事件经持久outbox使目录、索引资格和缓存过期，并更新依赖投影：员工L1重新组装，L2中来自该来源的条件标为待复核而非擅改用户明确输入，L3在恢复/执行/交付门禁停止受影响正式步骤，L4保留旧成果但按当前read/use门禁呈现。权限撤销作用于所有读取；资料撤回主要改变正式用途，历史读取按既有规则。永久清理按留存/授权流程处理，不由“撤回”按钮顺带物理删除。

## 8. 已有基础、开发范围与验收

已有代码提供部分上传、版本、解析/块操作及发布撤回端点，React知识管理员目前仅列表组件边界；现状以STATUS为准。管理完整投影、确认与专业依据记录、核验集、发布预检、反馈受理及四层维护投影需要开发或集成。已有接口不能当作完整流程通过，文档端点也不能当作可调用服务。

本方案的验收场景统一见 [PLAN知识管理员验收](../planning/PLAN.md#知识管理员完整界面与后端设计交付)。必须覆盖五条正常流程及并发、撤权、关键内容缺失、索引未就绪、无受理人、多来源反馈等失败路径。只做文档一致性核对不能声称三角色浏览器、真实PDF或业务闭环通过。

本轮待用户继续确认的设计点集中为：三个主入口及K00–K10分组、反馈协调/移交的实际责任人及处理范围、是否存在同文档按条件并行有效的真实样本。已确认的系统外业务确认、权限分离、员工原入口回访和保留旧答案无需重新讨论；本轮发布前业务/内容/所需专业确认齐全、索引就绪后正式查询的门槛亦已确认。视觉与实际业务名单仍未确认，不以此阻止本轮完整设计入档。
