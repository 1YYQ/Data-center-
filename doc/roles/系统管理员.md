# 系统管理员 · 角色需求

状态：角色与核心职责已确定；可见范围、权限细节及入口为设计草案，尚未实现。

## 核心职责

用户、权限、模型、存储及系统配置。

## 工作目标与待验证障碍

目标：让用户在明确权限和数据使用范围内稳定使用平台，并能定位服务问题与控制运行成本。以下问题需要结合实际企业环境验证。

| 工作环节 | 应调查的障碍 | 数据中心可提供的结果方向 | 需要的实际证据 |
| --- | --- | --- | --- |
| 管理访问 | 是否难以解释谁可以访问哪些资料，或人员变化后权限未同步 | 可检查的授权关系与变更记录；业务正文访问仍独立授权 | 账号来源、部门或角色授权及人员变更流程 |
| 管理模型与数据流 | 是否难以判断哪些资料发送到哪里、调用了什么服务 | 服务配置、数据流范围、调用状态与用量 | 企业外发要求、现有服务与实际调用约束 |
| 排查失败 | 用户拿不到结果时，是否难以区分资料、权限、解析或服务问题 | 脱敏的失败分类、任务状态和必要诊断依据 | 一次实际故障、现有排查步骤 |
| 持续运行 | 是否存在容量、备份恢复、服务替换或内网迁移方面的缺口 | 可验证的恢复与迁移方案、容量和服务状态 | 运行环境、恢复要求和维护职责 |

不能因为方便排障就默认读取全部资料。运维能力为普通使用者和知识管理员的真实工作提供支撑，不以管理菜单数量作为成果。

## 可见范围

“需要看到”指完成本职工作的核心内容；“应该看到”指判断可信度、状态和影响所需的信息，同样属于设计要求，不是可省略的装饰；“不需要看到”指默认界面隐藏的无关细节。无权访问的数据另列为权限边界，不能仅靠隐藏界面保护。

| 类别 | 内容 |
| --- | --- |
| 需要看到：工作核心 | 用户、角色和权限配置；模型服务与连接测试；存储、系统参数及运行状态；配置与权限变更记录 |
| 应该看到：判断依据与状态 | 模型可用性、调用失败率与用量；存储容量、任务队列和服务异常；配置变更影响、脱敏诊断信息、数据流向及已配置策略的执行状态 |
| 不需要看到：默认隐藏 | 日常知识问答正文、专业公式校对界面、每份手册的阅读界面，以及用户业务输入和生成文件正文；排障默认使用必要的状态与标识 |

## 权限边界

- **系统管理员**：平台配置权限与业务内容阅读权限分开。系统管理角色本身不自动授予全量手册、任务输入和结果正文的读取权；需要排障访问时采用明确授权并留痕。具体授权责任人和流程待确认。
- **界面与数据**：隐藏菜单只解决信息负担，读取、检索、预览、下载和修改均需在服务端校验权限；无权访问的资料标题、摘要、引用、缓存和产物也不能泄露。
- **凭据**：系统管理员可按权限录入、替换和测试密钥，已保存密钥不以明文回显；其他角色不可读取。脱敏日志不能成为获取业务正文的旁路。
- **多角色**：建议支持一人兼任多个角色，以获授角色及数据范围组合权限；不设“系统管理员自动继承全部业务权限”的隐式规则。是否启用兼任待确认。
- 发起普通业务任务时，应显式具备普通使用者角色或对应能力。

| --- | --- |
| 系统概览：服务状态与异常 | 用户与权限、模型配置、存储与系统配置、运行与审计记录 |

## 验收要求

各角色能完成本职工作；无关入口默认隐藏；直接访问接口或文件链接也不能越权；错误信息和日志不会泄露无权读取的内容。
