# 普通使用者 · 角色需求

用途：普通使用者的职责、任务体验和权限要求。实现与验收进度统一见 [项目状态](../planning/STATUS.md)，本文件不维护功能完成快照。

## 核心职责

查询知识、发起任务、获取结果。

## 工作目标与待验证障碍

目标：在自己的权限范围内取得完成工作所需的资料和依据，并将其转化为可以检查、使用的办公成果。以下为待验证问题，不代表已发现企业现有系统存在这些缺陷。

| 工作环节 | 应调查的障碍 | 数据中心可提供的结果方向 | 需要的实际证据 |
| --- | --- | --- | --- |
| 找资料 | 是否不知道文件在哪、名称是什么，或需要反复向同事询问 | 按工作问题定位授权文件、相关章节和来源 | 最近一次查找过程、所用渠道与最终找到的位置 |
| 判断依据 | 多个版本或不同文档说法不同时，是否无法判断适用性 | 展示版本、适用条件和冲突，指出需要谁确认 | 实际冲突文档、原来的裁定方式 |
| 理解与整合 | 是否已找到文件，却仍需逐份阅读才能回答一个问题 | 带引用的解释、跨文档对照、事项清单；资料缺失时明确缺口 | 原始问题、所读文件、人工整合结果 |
| 完成工作 | 是否有依据但仍需重复摘录、核算、检查或制作文件 | 可追溯的办公成果；按任务需要补充计算或导出工具 | 任务输入、现有操作步骤、目标成果与复核方式 |

不能获取资料可能是“未找到”“未收录”“没有记录”或“无权访问”，应区分处理。计算公式到 Excel 只是完成工作这一类中的一个候选场景，不限定本角色的全部需求。

## 可见范围

“需要看到”指完成本职工作的核心内容；“应该看到”指判断可信度、状态和影响所需的信息，同样属于设计要求，不是可省略的装饰；“不需要看到”指默认界面隐藏的无关细节。无权访问的数据另列为权限边界，不能仅靠隐藏界面保护。

| 类别 | 内容 |
| --- | --- |
| 需要看到：工作核心 | 有权使用的知识查询入口和结果；工作提交与补充入口；本人任务列表、进度、结果预览和下载；获准接收的单条回答 |
| 应该看到：判断依据与状态 | 答案和结果的来源、手册版本、原文定位；公式、输入、单位和计算说明；有效性与验证状态；缺失参数、冲突、适用条件及关键警告；失败原因和下一步操作 |
| 不需要看到：默认隐藏 | 文档解析流水线、切片与向量、检索调试分数；模型连接参数、数据库结构、服务器指标、系统调试日志及管理菜单 |

## 权限边界

- **普通使用者**：仅可读取获授权资料、本人任务/成果及获准接收的单条回答；不可修改知识库、用户权限或系统配置。分享不开放发送者的整个办公任务、输入文件或其他成果。
- **需求分类**：选择任务分类仍须遵守已有角色、授权范围及文件规则，不能因此获得额外资料访问或使用权限。
- **操作权限**：查看、用于计算、生成报告和下载导出分别授权；查看权限不自动包含其他使用权限，授权不明确时不默认放行。
- **系统内分享**：首期以单条回答为分享单位，保留该回答采用的设备条件、版本、出处及必要状态；整个对话分享后置。接收人仍须具备相应资料范围和操作权限，分享不自动授权，不绕过文件等级、文件类别和需求分类规则；权限不足、过期或撤销时不放行，扩权仍需重新审批。
- **新增或扩大授权**：首期在系统外由业务负责人或资料所属部门负责人审批，系统管理员登记配置；资料范围、允许操作和有效期限须明确，未批准或信息不完整时不放行，扩大权限须重新审批。记录要求见 [SPEC](../requirements/SPEC.md#6-异常与权限要求)。
- **待确认手册**：新上传草稿默认管理隔离。知识管理员显式开放精确版本“仅供参考”后，具有当前原文读取权限的员工可查看原PDF，醒目标明待确认/待核验、原因、版本与出处。参考开放不增加资料权限、下载/分享或正式使用资格；关闭或撤权后重新限制。正式说明及计算边界见 [SPEC 首期场景](../requirements/SPEC.md#13-首期场景设备操作与维护资料查询)。
- **界面与数据**：隐藏菜单只解决信息负担，读取、检索、预览、下载和修改均需在服务端校验权限；无权访问的资料标题、摘要、引用、缓存和产物也不能泄露。
- 不可读取模型密钥及其他服务凭据；脱敏日志不能成为获取业务正文的旁路。
- 首期允许同一账号兼任多个角色，按明确批准的角色、资料范围、操作和期限组合，不能突破文件规则；完整原则见 [系统管理员](系统管理员.md#权限边界)。

## 页面入口

2026-11-15 已明确按角色/权限显示入口、支持自然语言和版本出处核对，以 Apple 备忘录的信息层次为参考，首期只做电脑端。2026-11-17 用户进一步确认以持续对话组织工作，并增加资料查阅入口；旧“工作台/查询/我的任务/结果”的页面分组不再视为已定导航，任务与结果能力仍须保留，具体呈现继续讨论。

本轮已确认：

- 同一对话可连续追问、补充信息，记住已确认的设备型号和条件；新工作可新建对话，历史及回答出处保留。
- 默认在员工有权查询的资料中检索，无需先选部门或资料库；可以手动缩小范围。
- 员工可从资料查阅入口按型号或文件名查找、打开自己有权查看的手册，也能从回答引用进入原文。
- 分享粒度按上节的单条回答规则执行；不分享其他消息或整个对话。
- 2026-11-17 后续确认：可从当前对话或手册页面提交资料问题反馈，由知识管理员后续处理；提交反馈不等于业务确认或自动发布，也不授予管理人员读取整段对话的权限。后续进一步确认可在原对话/手册页查看进度和管理员答复，资料更新后提示重新查询、保留旧回答。表单细节及状态标签仍待确认。
- 同日范围更正：结果区以答案和实际成果为主，附加证据通过链接跳转；此前并排原文的建议被取代。RAG 查询是工具链之一，角色设计必须同时覆盖数值计算和表格修改，不能把查询稿称为完整办公界面。

查询需求编号与确认范围以 [SPEC 1.3.2](../requirements/SPEC.md#132-普通使用者交互确认2026-11-17) 为准。[网页契约](../../specs/001-device-operation-maintenance-query/contracts/ui.md) 只维护首期查询子流程；整体办公工作模型见下节。后端字段与端点在 API/数据库文档维护，不在角色文档复制。以上是需求确认，非实现或视觉验收。

2026-11-17 按用户要求，基于20项工具重整的 [完整界面与对接方案](../design/普通使用者界面与对接方案.md) 统一覆盖四类工作。候选导航为“对话、资料查阅、任务与成果”，同一对话提交工作，结果就近呈现，长任务/文件也能独立找回；原两入口提议不再代表完整方案。页面/状态/链接关系只在该设计文档维护，具体API读写在接口15、关联数据在数据库15。此为本轮设计，不把候选导航记为用户已批准或实际功能。

## 办公任务与结果呈现

依据：[SPEC 整体工作模型](../requirements/SPEC.md#普通使用者整体工作模型2026-11-17-范围更正)、[计算与 Excel](../requirements/SPEC.md#11-候选场景公式计算与-excel) 和 [资料汇总报告](../requirements/SPEC.md#14-候选场景多资料汇总对比与报告整理)。整体能力范围和结果优先/证据链接已明确，以下页面与后台组织是待讨论的衔接建议。

对话承载工作需求、文件输入和补充条件；同一办公任务可经过多次补充、多个工具步骤后形成成果，而非每条消息都只能生成一条查询答案。按任务需要使用工具，纯计算或表格整理不强制先检索，涉及手册规则时才取得相应依据。员工无需理解检索、计算或表格服务的内部划分。

| 工作任务 | 主区交付什么 | 后台必须实际完成什么 | 通过链接查看什么 |
| --- | --- | --- | --- |
| 查询资料 | 直接答案、适用条件及关键警告 | 在当前授权和版本范围内检索、核对并组织说明 | 来源原文、版本与定位、当时条件详情 |
| 计算数值 | 数值、单位、必要适用条件及验证/复核状态 | 核定公式与输入，由受控确定性程序计算，校验单位、适用范围和舍入 | 公式出处、输入来源、换算与计算记录 |
| 修改或生成表格 | 修改摘要、表格预览与可编辑新文件；明确未完成项目 | 识别工作表/区域与单元格映射，按授权修改或追加，保留原始数据和格式；涉及公式时重算并核验 | 修改位置与前后内容、公式/输入依据、重算和文件检查记录 |
| 汇总与报告 | 预览及约定格式的可编辑成果，突出冲突和待确认事项 | 按任务及模板组织内容、生成文件并验证 | 引用原文、各部分的来源和版本 |

以上任务可组合。例如“依据手册计算并填表”应实际贯通：读取员工 Excel → 确定处理项目/区域和输入 → 按需查找适用公式 → 校验参数/单位 → 程序计算 → 更新允许修改的单元格 → 重算/核验 → 另存新文件并交付。缺项只暂停受影响项目；目标单元格已有结果时先展示差异、经员工确认再更新。不能只回答计算方法或修改建议后就标记完成。

主区不堆叠证据全文或工具日志；影响员工使用结果的警告、缺项、局部完成、计算/文件未验证等状态保留在结果旁。打开详情链接时保留原工作位置，详情及文件仍实时校验权限。人工确认结果可用与系统完成处理分别标识。

2026-11-17 用户进一步要求先完成完整工具体系设计，再细化界面；候选目录、工具组合及强制执行边界统一维护在 [Agent工具体系总览](../architecture/前后端技术方案.md#6-agent-工具体系总览候选设计)。工具名不是网页导航，也不代表已实现。

文件随对话提交、成果预览/打开、长任务找回与恢复已经在上述完整方案形成设计；尚未实施或取得布局/视觉批准。方案以只读预览、下载可编辑Excel、对话继续提出修改为基线；网页手动编辑单元格仍待另行确认。单条回答分享不扩大为表格或整任务分享，首期查询优先顺序不变。

用户进一步确认的记忆能力按 [四层产品记忆](../architecture/前后端技术方案.md#7-四层产品记忆设计) 维护：本轮上下文按需组装、对话条件按设备/项目/文件区分、执行依真实检查点恢复、历史成果保留来源版本。条件值、用户确认和企业资料批准分开；新对话不自动沿用旧条件，个人偏好后置。权限或来源变化后记忆也不能继续放行，具体数据/读写见数据库16/API16，不将开发助手的doc/memory当作员工功能。

## 验收要求

各角色能完成本职工作；无关入口默认隐藏；直接访问接口或文件链接也不能越权；错误信息和日志不会泄露无权读取的内容。
