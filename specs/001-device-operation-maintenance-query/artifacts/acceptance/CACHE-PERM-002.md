## 2. 实际机制及完整路径

| 层 | 实际键/边界 | 当前鉴权与一致性 |
| --- | --- | --- |
| 网页入口 | `run.py` → `src.server.app`；`/api/v1` 与无前缀路径进入同一应用 | 请求 cookie → AuthSession → active 用户/会话到期/授权修订；写入有 CSRF |

| 索引 | 知识库 `active_generation_id` → 代际及 IndexSource（版本/解析批次）；source_revision 对比 content_revision | 本地关键词检索；发布递增内容修订，过期代际被拒绝；不含可绕过当前 ACL 的授权快照 |
| 新查询 | 输入库/型号/授权维度 → 块/解析/版本/文档 → 当前 document.read 与 knowledge.query → 生效/核验/型号 → 排序 → 答案 | 原来只在检索时判断；现在保存前对所选候选重新验证当前状态和索引来源 |
| 已保存答案 | QueryTask UUID/owner，TaskEvidence 记录实际块/版本/原文快照 | 任务所有者或有效分享 + task.read + 全部证据当前资料权限；历史 superseded 与新检索 effective 分开，不复用另一用户的问题文本作答案键 |
| 回执 | `(actor_user_id, idempotency_key)` 唯一，方法/路径/正文指纹 | 不存答案正文；当前实现的首次回执未完成，重放得到 409（见独立缺陷），不是跨用户答案命中 |
| HTTP | 敏感路径响应 `private, no-store`，ETag 用于并发条件 | 没有发现当前网页服务的 Redis、查询结果字典、查询文本缓存或持久浏览器答案缓存；已发送字节不能追回 |
| 旧原型（未接当前入口） | `knowledge_base/utils/llm_utils.py` 按 `(model, json_mode)` 缓存客户端；Mongo 历史按 session_id；图实例复用编译图，MCP 缓存工具清单 | 客户端/工具清单缓存不是答案缓存。旧原型召回按 item_names，历史按 session_id，源码中未见网页授权边界接入；本次只读检查，不导入运行、不外发资料 |

最终输出链：新查询在任务轮询时由本地执行器处理，保存 QueryTask/TaskEvidence；结果、任务列表、证据列表/详情、产物列表通过共享任务门禁，证据再检查文档权限；原件入口独立检查文档及版本。分享不会授予资料权限。网页的错误分支可能保留之前渲染的内容，须与后端新响应分开判断。

不变量：当前资料权限必须来自当前用户、有效授权和文档继承模式；restricted 仅允许直接授权；新答案只引用当前生效且核验通过、型号匹配及索引来源仍一致的证据；保存历史不授予新权限；分享与会话失效不能凭已有答案放行；公共证据可以产生相同答案。

## 3. 已证实根因与区分实验

1. **授权继承规则遗漏**：`can_access_document` 无条件接受知识库授权，未读取 `access_mode`。restricted、仅知识库授权时返回 true，撤掉同一知识库授权则 false；HTTP 中私有正文和证据真实出现。它能解释撤直接授权后仍可访问及不同范围答案相同，无需答案缓存。
2. **当前身份复核使用过期对象且缺少会话终检**：认证保留 User，提交后不自动过期；在长请求执行窗口停用账号，最终读取仍用旧状态。对同一数据库、同一对象只做 refresh，任务读取从 true 变为 false。会话撤销另经三入口 HTTP 实验复现，原路径在执行后没有再次检查当前 cookie 会话。
3. **检索资格被当成保存资格**：候选带着旧版本/授权状态进入 `build_query_result`，保存前不再检验。另一事务替换版本后，候选仍被当作 effective；仅刷新版本就由可正式使用变为不可使用。检索后撤销资料授权时，原 HTTP 结果门禁虽会阻断，但旧正文仍写入新任务，证明响应拒绝与写入安全是不同条件。

竞争解释的结果：普通顺序发布的“索引始终使用旧版本”未获支持；跨用户共享答案缓存未发现，两个账户同键提交得到不同任务；当前原型缓存不能在无调用链证据时作为网页症状原因。对真实事故的因果归属仍未知。

修复前对照产物：`outputs/cache-permission-002/2026-11-16/discriminating-controls.json`。实验不伪造接口响应、不用延迟；在真实服务调用边界插入另一 SQLite 事务提交，是确定性交错，不是生产并发压测。

## 4. 独立发现，未混入本次修复

- **已复现的幂等误拒绝**：首次 POST 返回 202，重复同键返回 409 REQUEST_IN_PROGRESS，回执仍 processing。`idempotency_record` 创建后返回 None，`complete_idempotency` 因而不完成该回执。证据 `separate-idempotency.json`。这是恢复/可用性缺陷，不证明旧答案复用，未修复。
- **旧原型权限缺口（源码观察）**：Mongo 会话历史仅按 session_id 读取，召回按商品名过滤；未接当前网页授权。若未来接入，必须先补身份/资料/版本边界，不能直接作为企业授权查询服务。本次未证明其运行时跨用户泄露，也未改它。
- **旧页面错误后的保留内容（源码观察）**：query.js 的失败分支更新状态却未清空上一次结果；可能造成“仍显示旧答案”的感受，不等于撤权后再次取得正文。未作浏览器复现/修复，不将它冒充本次已证实后端根因。
- **原三项服务回归失败**：夹具缺少必填授权维度，正式证据、待核验提示和撤回证据断言仍失败；与 CACHE-PERM-001 相同，保留，未通过放宽生产规则消除。
