# Feature Specification: 设备操作维护资料查询

**Feature ID**: 001  
**Progress**: [Project status](../../doc/planning/STATUS.md); requirements below do not imply implementation or acceptance.
**Date**: 2026-11-18

## Overview

普通员工需要按设备型号查找适用的操作和维护手册，并快速确认步骤、注意事项、版本和原文出处。首期将 89 份 PDF 纳入资料范围清单，由知识管理员维护来源、版本、业务适用性和内容核验状态；系统只在用户当前有权、版本适用、内容已核验且已发布时生成正式查询说明。

首期只支持电脑网页和设备操作维护资料查询。计算填表、Excel/Word 修改、多资料对比报告、企业 SSO、手机适配、自动扫描共享文件夹和直接控制设备属于后续范围。

## User Scenarios & Testing

### US1（P1）：普通员工查询设备资料

作为普通员工，我希望用自然语言描述设备型号、操作步骤、维护要求或注意事项，并查看带版本和出处的说明，以便在授权范围内完成工作。

**验收场景**

1. 给出已确认型号和已发布手册，answer模式交付有证据约束的组织答案，包含步骤、限制、版本、适用范围和可定位原文证据；只有摘录、部分回答或待核验候选不能标作该模式已完成。
2. 型号不明、资料缺失、证据不足或版本冲突时，系统明确说明缺项并要求确认，不猜测补充。
3. 新上传草稿默认仅管理者可见；知识管理员显式开放精确版本“仅供参考”后，具有当前原文读取权限的员工可查看带状态的原PDF。开放参考不改变适用/核验/发布状态，不增加ACL，不进入正式问答上下文或正式依据；关闭参考或撤权后立即重新限制。
4. 用户刷新页面后仍可恢复自己的对话、任务、状态和结果。
5. 同一对话追问沿用已确认设备和条件，新工作可新建对话；历史保留每条回答当时的条件与出处。
6. 默认在当前有权查询资料中检索，可主动缩小；无需先选部门或资料库，空命中不暗中扩大。
7. 从资料查阅按型号/文件名查找有权手册，打开原件；从回答引用进入实际引用版本与位置。
8. 只分享选定的一条回答及设备条件、版本、出处，接收者仍需相应权限，不能借此打开其他对话消息。
9. 员工在当前对话或手册页面提交并回访资料问题反馈，查看进度与知识管理员答复；资料更新后提示重新查询且保留旧回答；处理不自动完成业务确认、内容核验或发布。

### US2（P1）：知识管理员维护可信资料

作为知识管理员，我希望上传原件、登记元数据、核对解析内容、记录业务确认并发布版本，以便普通员工查询到可追溯资料。

**验收场景**

1. 89 份范围清单中的每份文件都有哈希、来源、型号、版本、类别、等级、访问范围和状态字段；重复内容不自动合并权限或来源。
2. 文字版、扫描版、表格、图片、警告和脚注保留可靠原文定位；识别不清的块进入待核验状态。
3. 业务适用性、内容核验和发布状态分开记录；只有适用性 confirmed、内容 approved、发布 effective 才可进入正式查询。
4. 上传重试、版本发布、撤回、解析修正和索引启用有幂等、并发保护和审计记录。
5. 受理员工反馈不自动获得整段对话、其他任务或受限资料权限；反馈处理和适用性确认/内容核验/发布分别留痕。

### US3（P1）：系统管理员控制账号和权限

作为系统管理员，我希望管理平台账号、角色、完整授权组合和运行配置，但不能因为管理员身份自动读取业务正文，以便平台可控且不越权。

**验收场景**

1. 首个管理员通过一次性部署初始化建立；账号激活、凭据重置、停用和会话失效可追溯。
2. 授权同时匹配角色能力、资料范围、操作、文件维度、有效期和业务审批；不同授权记录不能拼接新权限。
3. 无权资源不泄露名称、摘要、引用、缓存或任务正文；分享不补资料权限，过期/撤销后读取被阻断。
4. 授权、版本、解析、发布、索引、分享、撤权和管理员操作都保留脱敏审计。

## Functional Requirements

本节是FR编号、需求正文和逐项验收要点的唯一维护位置；业务细则引用[项目SPEC](../../doc/requirements/SPEC.md)。不在项目SPEC或角色文档另存同一需求表。

| ID | Requirement | 验收要点 |
| --- | --- | --- |
| FR-001 | 维护 89 份正式资料范围清单，保存文件哈希、来源、型号、版本、类别、等级、权限和状态；重复哈希不能自动合并来源或权限。 | 清单可追溯；原件哈希稳定；重复内容关系可解释 |
| FR-002 | 提供平台账号、一次性初始化、登录、会话、登出、停用、凭据重置和会话失效流程；客户端不能提交身份或角色冒充调用者。 | 账号停用/重置后旧会话失效；登录失败不泄露账号存在性；操作有审计 |
| FR-003 | 按角色能力、资料范围、操作、文件维度、有效期和业务审批的完整授权组合鉴权；不跨授权记录拼接；分享不补资料权限。 | 401/403/404 边界正确；撤权、过期、冲突和系统管理员越权均被阻断 |
| FR-004 | 分开保存业务适用性、内容核验和发布状态；只有适用性 confirmed、内容 approved、发布 effective 的版本可作为正式查询依据。 | 待确认/待核验版本只能带状态参考，不能生成正式说明 |
| FR-005 | 上传和版本创建具备文件类型/大小/哈希检查、幂等、中断核对/恢复和临时文件清理；失败不能留下可见的半个版本。 | 同键重放不重复创建；中断可核对并恢复或明确失败；无效文件不进入查询 |
| FR-006 | 解析文字版、扫描版及复杂表格/图片/警告/脚注，保留文件页序号、印刷页码或章节等原文定位；识别歧义进入待核验。文档内指令按不可信内容处理。 | 对照原件检查关键结构；修正产生新批次并保留历史；文档内指令不改变系统权限或执行代码 |
| FR-007 | 默认在员工当前有权查询的资料中检索，无需先指定部门或资料库；允许手动缩小范围，仍按适用型号、有效版本和活动索引过滤，每个结果关联证据、定位、版本和状态；answer模式交付有证据约束的组织答案 | 默认范围、缩小范围、无命中和权限变化均可核对；实际检索范围可追溯，不因前端选择而扩权 |
| FR-008 | 查询任务持久化状态、步骤、重试、取消、等待输入、部分完成和恢复信息；刷新页面后可继续查看任务。 | 重试幂等；本地取消不再提交产物；服务异常能区分等待、失败和未验证 |
| FR-009 | 首期仅分享单条回答，保留该回答采用的设备条件、版本和出处；接收者须具备相应资料及操作权限，保存有效期和撤销状态，整个对话分享后置 | 分享不包含其他对话消息或自动授予资料权限；过期、撤销或依赖撤权后阻断读取，不产生匿名公开链接 |
| FR-010 | 记录授权、版本、解析、核验、发布、索引、查询、分享、撤权和管理员操作审计；日志脱敏。 | 审计能回答谁在何时依据什么改变了什么；日志不含正文、密钥或签名链接 |
| FR-011 | 规定资料、解析结果、向量、缓存、任务快照和产物的留存、逻辑删除、最终清理、撤权失效和备份恢复边界。 | 删除/撤权同步影响检索、缓存、索引、预览和外发；恢复后不重新暴露已撤权资料 |
| FR-012 | 外部解析、向量和生成服务按服务记录授权、数据范围、账户、费用、配额、留存和失败状态；适配器隔离供应商响应。 | 未获准资料不外发；超时/限流/额度不足可追踪；费用和调用量可归属 |
| FR-013 | 电脑网页按角色组织对话、资料查阅、任务/结果与管理能力；网络异常、权限变化、证据不足和版本冲突有可理解反馈，明确支持的浏览器和桌面视口 | 普通员工实际完成连续追问、查阅手册、核对引用与单条回答分享；主要布局及视觉仍须预览确认 |
| FR-014 | 建立人工黄金样本、参考答案、负面案例和回归记录，记录检索质量、引用准确性、任务耗时、上下文用量和费用。 | 每个指标有样本、计算口径、当前基线和验收阈值；未验证不标记通过 |
| FR-015 | 支持同一对话内追问和补充信息，记住已确认的设备型号与条件；可为新工作新建对话，保留历史消息、各回答采用的条件和出处 | 连续追问沿用已确认条件；更正条件不篡改旧回答；恢复和后续生成均复核当前权限，不把旧回答或推测当成新事实 |
| FR-016 | 提供资料查阅入口，员工可按设备型号或文件名查找并打开自己有权查看的手册，也能从回答引用进入对应版本原文；未发布草稿默认隔离，仅DM显式开放的精确版本可按当前DR供人工参考，正式用途仍独立检查 | 列表、检索及原件读取均鉴权；直接查阅不等于正式问答资格，引用定位不跳换版本；无权资料的名称和存在性也不泄露 |
| FR-017 | 员工可在当前对话或手册页面提交资料问题反馈、查看进度和知识管理员答复；资料更新后提示重新查询并保留旧回答；反馈与业务确认、内容核验和发布相互独立 | 两个原入口可回访进度与答复；新查询不覆盖旧回答条件/版本/出处；提交、处理或答复不自动确认业务适用性、通过核验或发布，不扩大资料权限 |

| ID | Success Criterion | 口径与限制 |
| --- | --- | --- |
| SC-001 | 查询说明中的每个关键事实都能回到当前有权、适用且已发布的版本和原文定位 | 使用人工参考答案逐项核对；没有证据的事实必须显示为缺失或未验证 |
| SC-002 | 缺失资料、型号不明、版本冲突、内容待核验、权限不足和服务异常不会生成冒充正式结果的内容 | 记录阻断原因、下一步和是否允许局部结果 |
| SC-003 | 任务在刷新、Worker 重试、外部超时、撤权和本地取消后仍保持可追踪且不重复提交产物 | 以任务状态、执行尝试、消息派发和审计记录为证据 |
| SC-004 | 撤权、版本撤回、逻辑删除和最终清理同步失效查询、缓存、索引、预览、下载和后续外发 | 已下载到用户设备的内容无法追回，交付说明必须明确这一边界 |

| SC-006 | 解析质量、检索召回、引用准确性、耗时、上下文用量和费用均有人工样本基线 | 阈值在黄金样本建立后写入验收记录，未设阈值前不宣称达标 |
| SC-007 | 首期运行具备最小审计、脱敏诊断、备份恢复和数据删除演练记录 | 实施前记录备份窗口、恢复目标和删除演练证据；恢复后的权限状态和索引可用性必须重新核对 |

## Edge Cases

- 同一幂等键重复上传相同或不同文件。
- 上传中断、临时文件残留、文件类型/大小不支持、哈希不匹配。
- 版本业务适用性待确认、内容待核验、版本冲突、撤回或旧版失效。
- 解析服务超时、远端任务状态未知、索引未完成、向量配置不兼容。
- 普通用户被撤权、分享过期或撤销、账号停用、会话过期、系统管理员尝试读取正文。
- 查询无证据、部分索引、型号不明、文档含有提示词或执行指令。
- Worker 重试、任务取消、刷新恢复、局部结果和失败后重新提交。
- 逻辑删除、最终清理、备份恢复后不能重新暴露已撤权资料。

## Assumptions and Non-Goals

- 89 份 PDF 是首期正式资料范围清单，不等于每份已经业务确认或获准外发。
- 首期采用平台账号；企业 SSO、计算填表、报告生成、通用导出及整个对话分享另行规划。
- 外部服务、费用、配额、留存、浏览器支持范围和备份恢复目标必须在真实运行前取得证据。
- 系统辅助整理和查询，设备相关结论仍需业务人员复核，不直接作为设备执行指令。
