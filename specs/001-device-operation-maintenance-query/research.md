# Phase 0 Research：首期设备操作维护查询

状态：规划产物。依据 `doc/requirements/SPEC.md`、现有角色文档、数据库/API 草案、模型方案和用户本轮明确事项整理；本文件不表示任何代码、数据库或外部服务已经实现。

本轮用户输入有三项直接影响规划的决定：

1. `doc/example/doc/` 中的 89 份 PDF 足以列入首期正式资料清单。
2. 登录、会话、权限组合规则和越权验证属于首期规划范围。
3. 先校准文档，再按开工前待确定项逐项收敛；本轮不写代码、不执行应用检验。

## 决策记录

### D00：首期角色工作流

首期只建立支撑完整查询闭环所需的三类职责：

- 普通使用者：提交自然语言查询、查看任务状态、阅读结果和证据、核对版本与出处。
- 知识管理员：手动上传资料、登记元数据、处理解析结果、记录核验状态、登记业务确认和发布版本。
- 系统管理员：创建/停用平台账号、配置角色与授权规则、维护运行配置；其管理身份不自动获得业务正文读取权。

实际企业部门、审批人名单和通讯录接入不是首期技术前提，作为部署前配置和业务核对项处理。

### D01：首期范围

首期交付物是带版本、适用范围、原文定位和状态提示的设备操作维护查询结果。计算填表、Excel/Word 产物和多资料对比报告保留在后续阶段，不进入本轮首期实现任务。

### D02：正式资料清单

89 份 PDF 作为首期正式资料范围清单的输入范围。清单保留文件哈希、来源、设备型号、版本标识、内容类型、访问范围和业务确认状态；相同内容的文件不因哈希相同而自动合并来源、权限或适用范围。

正式清单不等于每份资料已经通过业务适用性确认，也不等于每份资料可以发送到外部服务。

### D03：登录与会话

首期使用平台内账号，由系统管理员创建、维护和停用，不开放自助注册，也不在首期接入企业统一登录。业务 API 不接受客户端提交的 `user_id`、角色或权限作为身份依据。

会话采用认证适配层产生的不可猜测服务端会话标识，通过 `HttpOnly`、`Secure`（HTTPS 环境）和 `SameSite=Lax` Cookie 传递；状态变更请求使用 CSRF 防护。账号停用、会话撤销或权限修订变化后，旧会话不能继续访问业务内容。具体口令策略和生产密钥轮换属于部署配置，不改变本轮业务边界。

### D04：权限组合

有效访问必须同时满足：账号 active、角色能力允许目标操作、存在覆盖目标资料范围的已批准授权、授权仍在有效期内、资料版本/等级/类别/需求分类规则允许该操作。

不同授权记录不能跨记录拼接成未经批准的新权限。一次请求必须由同一条完整授权组合或明确的企业规则匹配；任一维度缺失、过期、冲突或不明确时拒绝。查看、查询、用于计算、生成报告和下载导出继续分开授权。

拒绝行为统一为：未认证 401、已认证但无操作能力 403、资源不可见 404；错误不得泄露无权资料的名称、摘要、引用、缓存或任务正文。分享链接只分享任务/说明访问关系，不补充资料 ACL，接收时重新检查全部依赖权限。

### D05：版本和核验

资料版本保存两条独立状态：业务适用性 `pending/confirmed/conflicted/withdrawn`，内容核验 `unreviewed/approved/blocked`；发布状态为 `draft/effective/superseded/withdrawn`。业务确认记录和系统登记记录分开保存；业务负责人确认适用范围和依据，知识管理员登记、维护和发布。

只有 `publish_status=effective`、`applicability_status=confirmed` 且内容核验通过的版本可以作为正式查询依据。业务适用性待确认/冲突和内容待核验/阻断分别标记；有资料读取权限的用户可以查看带状态的原文参考，但不能据此生成正式说明或参与正式计算。新版本不会因上传时间自动替换旧版本；旧版被确认仍有效时继续可用，影响旧版有效性的冲突会暂停相关正式使用。

2026-11-17补充确认：DM可显式开放精确draft原件“仅供参考”；员工仍须当前DR，未开放草稿继续隔离。参考不进入正式问答上下文或正式查询/计算，不替代确认、核验、发布及索引门槛。具体动作与数据唯一维护在API17.6/数据库17.6，本记录不再另定义一套参考状态。

### D06：资料外部处理边界

89 份文件进入正式清单，但“列入清单”和“允许外部处理”分开记录。向 MinerU、向量平台或生成服务发送资料前，必须针对服务、账户、数据留存和费用边界分别有明确记录。任何一个服务获准，不自动推导其他服务或其他资料获准。

### D07：模型和外部服务

业务层只依赖解析、向量化和生成适配器契约；不把供应商响应结构暴露给业务接口。外部 TLS、账户和费用未闭合前，计划允许使用固定的结构化解析夹具推进业务链路设计，但不把夹具结果当成真实服务能力证据。

### D08：任务和结果

首期任务类型为知识查询。任务结果至少包含回答/整理文本、证据片段、文档版本、原文定位、当前状态和警告。证据不足是可追踪的业务结果，不得用模型记忆补写专业事实。计算、导出和附件输入接口留待后续场景补齐数据模型后再定义。

### D09：界面方向

首期只支持电脑网页。菜单、面板和数据入口按角色与权限显示；普通使用者默认进入知识查询、我的任务和结果详情。视觉层次参考 Apple 备忘录的简洁和信息组织方式，但验收以任务可完成、版本与出处可核对、错误可理解为准，不以复刻某个产品外观为目标。

## 方案比较

| 选择 | 采用原因 | 未采用的替代 |
| --- | --- | --- |
| 首期做查询纵向闭环 | 能同时验证资料版本、权限、解析、检索、证据和 UI 的衔接 | 先做独立解析或独立聊天，无法证明用户任务完成 |
| 平台账号 + 会话适配器 | 满足首期账号边界，同时为后续 SSO 保留接缝 | 首期直接绑定企业 SSO，依赖尚未确认的发行方和目录 |
| 授权组合按完整元组匹配 | 防止多角色、多范围和多维分类被错误拼接扩大权限 | 分别计算各维度后取并集，容易产生未批准的组合权限 |
| 供应商适配器 + 固定夹具 | 外部服务受网络/费用影响时仍可推进领域设计 | 在外部服务未验证前把供应商 SDK 直接写入业务层 |
| 89 份全部进入正式清单 | 满足用户明确的资料范围决定，便于统一追溯 | 只把 3 份抽查样本当作正式范围 |

## 仍需在实施前取得的外部事实

这些不是本轮规划缺口，而是运行前的证据门槛：实际业务负责人和确认依据、每份资料的有效版本、服务账户和费用、生产密钥初始化、企业保存/删除政策、部署硬件及并发目标。它们不改变首期范围，但未取得前不能把对应能力标为已验证。
