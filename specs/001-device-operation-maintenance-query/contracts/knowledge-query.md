# Contract：资料治理与知识查询

用途：资料治理与查询行为契约。实现和验证状态统一见 [项目状态](../../../doc/planning/STATUS.md)，不能由契约存在推断验收通过。

## 管理流程

1. 知识管理员上传原件并登记来源、型号、版本、类别、等级和访问范围。
2. 系统保存原件哈希，创建默认隔离的draft版本；上传成功不表示可查询。DM可按API17.6显式开放精确原件仅供有当前DR的员工人工参考，不改变业务/核验/发布状态或正式查询资格。
3. 解析任务产生结构化块、原文定位和待核验状态；关键表格、警告、图片、公式和脚注不能静默丢弃。
4. 知识管理员对照原件修正；业务负责人确认适用版本和依据；两类记录分开保存。
5. 发布 effective 版本后才可进入正式查询；旧版本保留历史引用。
6. 选择 ready 切分集合构建索引并显式启用；未完成索引时返回清晰覆盖提示。

## 查询输入

- 自然语言问题。
- 默认由后端在当前有权查询的资料内确定范围；用户可选择知识库或手册缩小，无需先指定部门或资料库。字段和边界统一见 [API 8.1](../../../doc/api/接口设计.md#81-提交与结果接口)。
- 可选设备型号筛选。
- 查询模式为 retrieve 或 answer；未配置生成模型时仍可使用 retrieve。

## 查询输出

结果包括整理文本或空结果、证据片段、文档版本、原文定位、核验/适用状态和警告。证据不足、型号不明确、版本冲突、资料待核验和权限变化均是可见状态，不能用模型记忆填补。

## 对话与资料查阅衔接

2026-11-17 确认的持续对话、条件记忆、资料查阅与单条回答分享需求见 [SPEC 1.3.2](../../../doc/requirements/SPEC.md#132-普通使用者交互确认2026-11-17)。需要检索的消息关联查询任务；该轮保存条件、范围和证据，后续追问不覆盖旧答案。资料查阅按查看权限执行，正式回答按查询资格及版本/核验门禁执行；二者不能互相替代。

候选端点和数据映射在 [API 13](../../../doc/api/接口设计.md#13-普通使用者对话与资料查阅候选设计) 与 [数据库 13](../../../doc/database/数据库设计.md#13-对话消息与条件快照候选设计) 维护；本契约不另列一套字段，不表示多轮链路已实现。
