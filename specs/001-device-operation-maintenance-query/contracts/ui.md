# Contract：首期网页界面

用途：首期设备资料查询的电脑网页子流程契约，不代表普通使用者全部办公界面。整体计算、表格和报告任务见 [角色说明](../../../doc/roles/普通使用者.md#办公任务与结果呈现)。实现和验证状态统一见 [项目状态](../../../doc/planning/STATUS.md)，真实呈现与完整用户任务须通过浏览器验证。

2026-11-22 当前获准页面组织与视觉的唯一来源为[任务工作台全新设计](../../../doc/design/任务工作台全新设计.md)，用户已批准按其本地实施。下文旧页面结构及2026-11-17[普通使用者方案](../../../doc/design/普通使用者界面与对接方案.md)只保留历史讨论和锚点，不再作为布局、导航或视觉基线。既有业务权限、版本、证据、分享与反馈约束继续有效；当前实现及实际验收从[STATUS](../../../doc/planning/STATUS.md)进入。新版不将20工具或未实现成果入口自动纳入本期。

## 普通使用者

### 已确认的交互能力

2026-11-17 用户确认，业务依据为 [SPEC 1.3.2](../../../doc/requirements/SPEC.md#132-普通使用者交互确认2026-11-17)，对应 FR-007/FR-009/FR-013/FR-015/FR-016/FR-017：

1. 同一对话连续追问和补充信息，记住已确认的设备型号与条件；新工作可新建对话，历史记录和回答出处保留。
2. 默认检索全部当前有权查询的资料，手动缩小范围为可选操作，不设必经的部门/资料库选择页。
3. 资料查阅入口支持按设备型号或文件名查找、打开当前有权查看的手册；回答引用也可进入对应版本原文。
4. 首期仅分享单条回答及其设备条件、版本和出处，接收者仍需相应权限；整个对话分享后置。
5. 员工可在当前对话或手册页面提交资料问题反馈，由知识管理员后续处理；反馈不等于业务确认或自动发布。
6. 员工可在原对话或手册页面查看反馈进度和知识管理员答复；资料更新后提示重新查询，保留旧回答及其条件、版本和出处。
7. 后续用户更正：主区以答案结果为主，附加证据采用链接跳转；RAG 查询只是整体办公任务的一种工具链。本契约不承担计算填表的完整界面设计。

### 页面结构与交互草案（待预览确认）

| 区域 | 建议内容 | 后端衔接 |
| --- | --- | --- |
| 导航与历史 | 按“对话 / 资料查阅”组织主操作；对话下保留新建和历史入口 | 当前用户的对话目录；不以拥有对话为由读取所有消息依赖 |
| 对话主区 | 查询子流程的连续消息、当前任务状态、答案及证据链接；其他办公成果见角色说明 | 查询消息关联查询任务，回答关联条件和证据快照；不能将此模型代替整个办公任务 |
| 条件与范围 | 简要显示已确认型号/条件；范围默认“全部可查询资料”，允许缩小及恢复 | 后端保存确认来源和范围设置，每轮冻结实际条件与检索范围 |
| 资料列表 | 搜索型号或文件名，突出手册名称、适用型号、版本和状态 | 跨库可查看资料目录，列表、计数与详情均先鉴权 |
| 原文核对 | 从附加证据链接跳转原始 PDF/详情，保留返回原对话的位置；资料查阅入口复用同一查看能力 | 稳定版本 ID 与实际定位；链接仍鉴权；不可用时说明原因，不偷换版本或伪造高亮 |
| 单条回答分享 | 该回答上的分享入口，显示接收者、有效期和撤销操作 | 复用该轮任务的受控分享，不给接收者开放整段对话 |
| 资料问题反馈 | 对话和手册页面提供反馈入口，关联原问题或版本/位置；原入口回访已确认，表单和状态标签仍为草案 | 独立反馈记录与受控受理，不复用回答分享去开放对话，不修改业务/核验/发布状态 |

建议的交互约束：明确更正条件只影响后续回合，旧回答仍能查看当时条件；新对话默认不继承上一对话的条件/手动范围；单纯打开手册不修改已有对话。可考虑在合格手册页提供“基于此手册新建对话”，该快捷动作尚未最终确认。

### 信息与异常边界

- 关键步骤、警告和限制保留在回答中，引用提供版本与实际页序号/章节等定位；型号未知不从文件名推断为已确认。
- 有权查阅不等于允许用于正式说明。draft默认隔离；2026-11-17用户确认由知识管理员显式开放精确版本“仅供参考”后，有当前DR的员工可在目录和原文看到参考提示，未开放草稿仍不可见。API17.6独立控制参考开放，业务确认/核验/发布/索引继续控制正式用途；关闭参考或撤权后重新限制原件、预览和旧链接。
- 缩小范围无命中时明确当前范围，不自动悄悄扩大；索引未就绪不伪装成“没有资料”。部分覆盖是否允许及具体恢复交互仍待讨论，不改变现有完整覆盖默认门槛。
- 历史及分享内容保留追溯关系，当前失权时阻断相应正文、引用及后续模型上下文，不以“保留历史”为由继续暴露内容。
- 不显示解析流水线、向量、密钥、数据库和调试分数；失败反馈需可理解，具体文案和恢复动作待下一轮讨论。

候选端点见 [API 13](../../../doc/api/接口设计.md#13-普通使用者对话与资料查阅候选设计)，持久化关系见 [数据库 13](../../../doc/database/数据库设计.md#13-对话消息与条件快照候选设计)。早先结构稿和隔离示例仅覆盖查询；用户已指出其遗漏计算和表格能力，不能再作为完整角色方案。尚无对应应用实现或真实业务浏览器验收，整体布局或视觉方向未批准。

### 反馈表单与回访草案（待讨论）

- 建议员工只填写问题说明；问题类型可辅助分类，源问题/选定消息或手册版本/当前页由页面关联。没有查询答案也可针对当前问题反馈，不能要求先取得成功回答。
- 提交前显示将附带的必要信息，不默认附带整段对话、其他消息或全部任务正文。知识管理员只能查看明确反馈内容与当前权限允许的资料；来源标识不授予原对话访问权。
- 原对话/手册页查看进度和管理员答复已确认；“已提交 / 处理中 / 已答复”是候选状态标签，“已答复”不等于资料已核验或问题已解决。员工补充反馈及通知方式仍待确认。
- 资料更新后提示重新查询、保留旧回答已确认。更新提示反映实际版本状态；未通过适用/核验/发布门禁时不冒充正式可用。员工主动重新查询时使用当前对话已确认条件/范围和当前权限，创建新的回答，不覆盖旧快照。
- 缺少归属或接收者无权查看资料时，不扩大权限或群发正文；受理分派及脱敏边界待知识管理员/系统管理员讨论后落实。

接口与存储草案见 [API 13.4](../../../doc/api/接口设计.md#134-资料问题反馈候选设计) 和 [数据库 13.3](../../../doc/database/数据库设计.md#133-资料问题反馈候选设计)。

## 完整页面结构稿 v1（proposed）

整理日期：2026-11-17。范围更正：保留本标题仅供旧链接定位；原稿“完整”的称谓被取代，以下仅作为首期查询子流程草案。用户已指出其缺少计算与表格处理；普通使用者完整工作模型在 [角色说明](../../../doc/roles/普通使用者.md#办公任务与结果呈现) 维护。附加证据改为链接跳转；原隔离预览不再作为完整方案或后续视觉默认依据。已确认能力与候选布局分开，整体结构/视觉尚未批准。

### 导航与视图关系

```text
登录 → 普通使用者工作区中的查询子流程
  ├─ 对话（建议默认入口）
  │   ├─ 新建对话 / 历史对话
  │   └─ 当前对话：条件与范围 → 消息/任务状态 → 回答/引用
  │       ├─ 证据链接 → 原文/详情（可返回原对话）
  │       ├─ 单条回答分享（受控独立视图，不开放整段对话）
  │       └─ 资料反馈 → 原位置看进度/答复 → 更新提示 → 主动重新查询
  └─ 资料查阅
      ├─ 按型号/文件名搜索 → 手册列表
      └─ 版本与原始 PDF → 资料反馈 → 原位置看进度/答复
```

上述两个入口仅为查询子流程建议。查询任务状态随对应消息展示，反馈进度随来源展示；完整办公任务还会交付数值和文件，不能把“回答就是结果”推广至所有任务。是否需要独立任务/成果入口，须结合计算与文件任务的长时间处理和恢复继续讨论，原稿不据此删除这些能力。账号及登出放在账户入口，多角色入口显隐仍由权限决定。

### 对话页

1. 左侧为两个主入口和历史对话，新建进入独立对话；标题仅用于辨认工作，不能泄露失权资料。
2. 主区顶部显示当前工作标题、已确认设备/条件摘要和范围摘要；可展开查看/更正，条件不明时就近询问，不默认确认模型推测。
3. 中部按回合显示员工消息、任务状态、答案和必要警告；附加证据以链接提供，详情保留当时条件/版本及准确定位。单条分享和反馈动作就近出现。
4. 底部输入区用于连续追问；范围默认全部可查询资料，可主动缩小/恢复。选择范围只影响相关后续回合，不改旧答案。
5. 附加证据通过链接跳转原文或详情，保留返回原对话的位置；此前右侧或下方展开的提议被取代。具体跳转容器与返回交互仍待完整视觉设计，不将新标签页固定为业务要求。
6. 反馈在关联消息附近显示回执、进度和管理员答复。资料更新提示不覆盖旧回答；“按当前条件重新查询”建立新消息/任务，旧回答继续标明其原版本。

### 资料查阅页

1. 搜索区允许型号或文件名；无需先选择部门或资料库。列表仅显示当前可查看资料，不让无权文件影响可见计数或提示。
2. 列表突出手册名称、已登记适用型号、版本及必要状态。点击进入当前有权查看的版本及原始 PDF；其他版本通过版本入口区分。
3. 阅读区保留手册名称、版本、适用/核验状态、文件页序号与可知印刷页码；不可用定位说明原因，不猜页码或把重排文本冒充原件。
4. 手册页的反馈区域显示本人相关反馈、进度及管理员答复，不默认列出其他员工的问题。若后来关联新资料，提示真实更新状态；从手册发起新对话的快捷动作仍是可选建议，未批准。
5. 查看、查询和下载资格分别判断；不因为能阅读原件就显示通用导出能力，也不承诺浏览器中已读取内容可被追回。

### 单条回答分享视图

接收者登录并通过当前权限检查后，只看到选定回答、必要设备条件、版本/出处和状态。没有发送者的对话目录、其他消息或管理入口。过期、撤销、失权或来源不可用时返回可理解的受限状态；不以分享补资料权限。

| 更新提示、重新查询 | 反馈关联实际版本 → 派生 update_notice → 员工发送新回合 | 当前条件、范围和版本资格重验；旧答案不变 | 提示不能靠回复文案推定发布，链路未实现 |

字段和逻辑表的唯一维护位置仍是 [API 13](../../../doc/api/接口设计.md#13-普通使用者对话与资料查阅候选设计) 与 [数据库 13](../../../doc/database/数据库设计.md#13-对话消息与条件快照候选设计)，本表只解释页面如何衔接，不另建一套响应格式。

### 必要状态与恢复建议

| 状态 | 员工看到的内容/动作 | 后端约束 |
| --- | --- | --- |
| 新对话/无记录 | 可直接输入工作问题；没有伪造最近任务或推荐数据 | 新上下文独立，登录身份不等于资料授权 |
| 处理中 | 区分查找依据/整理结果等实际阶段，可保留输入与查看状态；停止动作沿用任务取消语义 | 无总量不显示假百分比；关闭/刷新不创建重复任务 |
| 缺型号/条件冲突 | 在同一对话询问必要缺项 | 补充关联原问题，不把推测持久化为已确认 |
| 选定范围无命中 | 说明当前范围，允许主动扩大或提交反馈 | 未命中不等于资料不存在，不暗中扩大范围 |
| 版本/核验/索引未就绪 | 说明原因及允许的原文参考/反馈入口 | 不用旧版或局部索引冒充完整说明；部分覆盖默认门槛未改变 |
| 服务失败/提交状态不明 | 保留输入，显示可理解状态，先核对原任务再恢复 | 不无条件换幂等键重提，不谎报成功 |
| 权限变化/会话过期 | 停止相关正文读取，必要时重新登录；保留允许的安全状态 | 重新校验列表、消息、原文、反馈和模型上下文，不能读旧缓存绕过 |
| 反馈有答复/资料有更新 | 原入口看进度与答复；按实际更新状态提示员工重新查询 | “已答复”不等于“已解决/已发布”；重新查询不自动改写历史 |

具体文案、状态标签、停止后的输入策略、处理分派及通知仍需在相应角色/实现评审中细化；本结构稿不改既有安全门禁。

## 管理角色的业务边界
