# 数据中心项目宪章

**版本**: 1.0.0  
**批准日期**: 2026-11-15  
**最后修订**: 2026-11-15

## 原则一：用户结果优先

每项功能 MUST 对应真实用户任务、触发条件、输入、预期结果和可观察的完成证据。技术组件数量、接口数量、文档数量和模型输出长度不能单独作为成功标准。首期工作优先保证普通使用者能够找到获授权且适用的资料，并核对版本和出处。

## 原则二：证据驱动与诚实状态

项目 MUST 区分已确认事实、工程决策、待确认事项、已验证结果和未验证结果。不得用模拟结果、局部模块成功、测试数量或模型自评代替完整用户任务验收。资料缺失、版本冲突、解析歧义和外部服务阻塞 MUST 以可见状态保留。

## 原则三：根因修复与最小充分实现

非平凡缺陷 MUST 调查触发条件、调用链、共享机制和影响范围，再选择能消除已证实根因的最小修复。实现 MUST 优先复用现有能力、保持边界清晰、避免无依据的重构和新增依赖。首期不得因后续计算、报告或格式需求扩大查询闭环范围。

## 原则四：权限、数据和外发边界

身份、角色能力、资料范围、操作权限、资料状态和有效期限 MUST 在服务端共同决定访问结果。管理员身份不得自动获得业务正文权限；授权不得跨记录拼接成未批准的新权限。企业原件、解析结果、向量、缓存、日志和凭据 MUST 遵循明确的数据使用范围；向外部服务发送资料前 MUST 逐服务记录授权、留存、费用和失败状态。

## 原则五：可追溯与可复算

原始资料 MUST 保留稳定标识、内容哈希、来源、版本和可靠原文定位。查询结果、证据、任务、产物、授权变更和状态转换 MUST 能回溯到具体输入、规则、执行版本和操作者。正式计算或文件生成 MUST 使用受控、可重复的执行路径，不能执行文档或模型生成的任意代码。

## 原则六：完整任务与失败恢复

交付 MUST 覆盖用户入口、数据流、状态反馈、错误恢复和最终结果。长任务 MUST 持久化任务、步骤、执行尝试、幂等回执、取消和恢复状态。重试、刷新、撤权、外部超时、删除和恢复不能产生重复产物或重新暴露已失效资料。

## 原则七：真实验收与可控演进

每个首期需求 MUST 有人工样本、正常路径、关键失败路径、验收口径和责任边界。质量、耗时、上下文用量、费用、审计、备份恢复和删除演练 MUST 以实际记录为依据。未经验证的格式、服务、模型、浏览器或任务不得列入已支持范围；发生反证时，相关规格、计划和任务必须同步修订。

## 治理

- 本宪章是 Spec、Plan、Tasks 和实现审查的强制约束；功能文档不得降低其中的 MUST 要求。
- 修订必须记录版本、日期、影响原则和迁移影响。原则新增或实质扩展提升 MINOR 版本，原则删除或重新定义提升 MAJOR 版本，澄清性修改提升 PATCH 版本。
- 每次 feature 规划 MUST 通过 constitution check，并在 tasks.md 中保留与原则相关的任务或验收门槛。
- 合规审查至少覆盖用户任务完成、权限隔离、数据外发、证据追溯、失败恢复和真实验收；审查结果必须区分通过、失败和未验证。
